# /sprint-selftest — 研发自测方案 + 自测用例生成

你正在执行 `/sprint-selftest` 命令，为当前版本生成**研发自测方案 + 人工自测用例 + 「测试环境与账号」配置**。

**★ 本命令是 skill 编排器**：调用 `dev-manual-testcase` skill 从研发需求 / 详细设计 / 研发执行计划生成研发自测方案 + 自测用例；并生成 `/sprint-aiauto-test` 用的「测试环境与账号」配置文件。研发自测是版本规划四类产物之一，与其余三类**对称**（研发需求 → `/sprint-requirements`、详细设计 → `/sprint-design`、研发执行计划 → `/sprint-plan`、**研发自测 → 本命令**），由独立命令承载——**是 `dev-manual-testcase` 生成研发自测方案 + 自测用例 + 测试环境与账号的唯一信源入口**（`/version` 与 `/sprint-plan` 不再内嵌研发自测生成，一律委派本命令）。

参数：$ARGUMENTS（可选）
- 第 1 位：版本号（如省略，从 AGENTS.md 当前状态读取）
- `--supplement={NN}`：★ 补充模式— 产品中途更新 PRD/原型、或约定 22 级联触发 L4 研发自测用例增量时，由 `/version` 或 `/sprint-dev` 传入；产出研发自测用例增量 `NN_<业务主题>.md`（约定 15，文件名不带"补充"字眼、补充身份记入 `00_索引.md`）而非覆盖主文档；详见文末「补充模式」段

## 补充模式（`--supplement={NN}`）

当版本开发中途产品更新了 PRD **或原型**、或约定 22 级联触发 **L4 研发自测用例增量**时，由 `/version`（Step 2.4.3.5）或 `/sprint-dev` Step X.0.0 调用本命令并传入 `--supplement={NN}`。**fresh 模式（无此参数）保持 Step 1~3 全流程不变**。


### ★ 约定 22 级联落盘（`--ledger-cascade`，与 `--supplement={NN}` 互斥，同时传则报错）

由**约定 22 级联**调用时（攒批收口子 Agent / `--cascade-now` 即时级联）**必须**加 `--ledger-cascade`：**就地改内容主文档正文** `docs/testing/{version}/研发自测/` 的既有用例册，改完刷该目录 `00_索引.md` 生成时间（约定 15）。
⛔ 不新建 `NN_` 分册、不产中转增量册、不全量扫 `code/` 等落盘细则与内容产出方式，**单一信源 = `{{AIDP_HOME}}/reference/开发期族增量.md`「收口执行要点」第 2/3 条（L4 用例）**，本命令不复述。

### 输入差异
- **必读** `docs/requirements/{version}/研发需求/输入变更-{NN}.md`（含 PRD 与原型两类变更）
- **必读** 本轮研发需求增量 + 各类设计增量（`docs/requirements/{version}/研发需求/NN_<业务主题>.md`、`docs/design/detail/{version}/NN_<业务主题>.md`，如有）
- **必读** 原研发自测用例（基线，只读）
- 具体落盘 / 子目录化 / 归一 / 索引登记规则见 **Step 1「补充模式」段**（单一信源，本命令单独被调用时也跑同段前置脚本兜底）

### 输出差异
- 只针对本次变更涉及的功能点输出新增 / 修订用例，未变功能不重复；原型变更会改变用例的"操作对象"和"预期现象"，必须重点对齐
- 增量用例落 `docs/testing/{version}/研发自测/NN_<业务主题>.md` 续编（补充身份记入 `00_索引.md`；命令端只做序号续编校正、不回补"补充"字眼）
- 新增用例 ID 全局唯一（继承原主文档编号空间，往后递增）
- **业务主题**：① 用户 `/sprint-selftest {version} --supplement={NN} "<主题>"` 显式传；② 从研发需求增量文件名/头部解析；③ 兜底 `增量NN{NN}`

## `--capture` 归档短路（约定 38 显式补录入口）

> 用户主动要求归档环境信息（"把这个环境记一下"、"补录一下测试账号"、"这个库连接存下来"）时走本模式。
> **只做归档、不重生成用例**：跳过 Step 1（不调 `dev-manual-testcase`）与 Step 2 硬门，直接执行 Step 3 的落库动作。
> ⚠️ 约定 38 的**自动触发路径**（用户在任意对话中随口给出地址/账号，Claude 当轮归档）**不必经本 flag**——
> 直接按细则落库即可；本 flag 只是把同一套动作暴露成显式入口，供主动补录与批量补齐。

**判定与规则单一信源 = 约定 38 细则（`{{AIDP_HOME}}/reference/约定细则-5.md`）**，本段不复述（约定 21），只列编排：

1. **定版本**：第 1 位参数 > `AGENTS.md`「当前状态 → 当前版本」。
2. **解析待归档项**：从用户本轮消息（或显式传入的文本）中识别环境 URL / 账号密码 / DB 连接，按细则 38.2 的
   触发与排除清单过滤（第三方公共地址、代码里已有的配置、用户说"别记"的一律不收）。
3. **敏感分流**（细则 38.5）：dev/test/研究/演示 → 明文写入配置文件；**prod / UAT → 不写入**，改存
   `memory/.sprint-autopilot-credentials.json`（chmod 600 + `.gitignore`）且**须用户显式确认**，配置文件里只留指针。
   判不准环境 → 按 prod 从严 + 问用户。
4. **落库**：写 `docs/testing/{version}/研发自测/01_测试环境与账号.md` 对应段（三/四/五），
   文件不存在则按 Step 3 模板建骨架再填；同步 `01_研发自测方案.md` §3 已有表格的数据行（该文件不存在则**不造**，
   只提示"跑 `/sprint-selftest` 后补齐方案 §3"）。
5. **冲突不静默覆盖**（细则 38.4）：同系统同角色已有不同值 → `AskUserQuestion` 三选一（更新 / 新增一行 / 保持）；
   无人值守追加新行 + 备注来源时间，不动旧行。值一致则 no-op。
6. **告知**：当轮回复明确说明写到了哪个文件的哪一段；改动随本轮其余产出一并提交，不单独 commit。
