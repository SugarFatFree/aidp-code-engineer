## 为什么把「执行步骤」外置

`/sprint-requirements` 命令主体原 341 行，一次性整份入上下文会触发 README 所述三症（lost-in-the-middle 漏步 / 指令互相稀释 / 满足即止跳步）。其中**「执行步骤」段（Step 0 输入扫描 → Step 1 调 ux-logic-extractor → Step 1.5 命令级后处理 → Step 2 补充元数据 → Step 3 更新状态，共 226 行）** 是唯一 ≥120 行的自包含大段，且只在"真正进入执行"时才需要，故外置为按需加载的 flow 文件 `execution-steps.md`。命令主体该段替换为「关键规则一句 + Step 骨架表 + Read 指针」，主体压到 128 行。

- 最易被漏的是 **Step 1.5 的 (a)~(e) 后处理**——尤其 (e) SKILL 脚本复核（技术内容污染 / 白名单 / 不臆造兜底 / PRD 条目反向覆盖 / 表 E 语义变更）。整份入上下文时这些尾部子步骤正落在"中段注意力衰减 + 满足即止"的盲区。

## 兜底回检脚本的退出码口径

`ux-logic-extractor` 全部校验脚本统一为 **`0`=通过 / N-A · `1`=检出违规 · `2`=入参或环境错**。故命令端判据只需一句：**`== 1` 才是产物违规，`2` 修参数重跑、不得据此回退重写需求**。若退出码语义不统一（如「路径不存在」有的返回 0 假绿、有的返回 1 假红），单看退出码无法区分「入参错」与「产物违规」——这类缺陷在模板仓库直接修 SKILL 脚本（约定 16），不在命令端加补丁。

## Step 1 「严格模式」信号传递的设计意图

`ux-logic-extractor` SKILL 独立使用时输入来源**不一定齐全**（可能仅 HTML 原型无 PRD），SKILL 内规则对引用强制度有"模糊度"；但 `/version` 串联场景下**PRD + 原型 + 高保真三类齐全**，命令端传"严格模式"信号，让 SKILL 按最高引用密度跑。

## Step 1 输出路径映射为何不再写"override 旧锚"

SKILL 已把专职索引与内容主文档改为索引态原生产出：索引恒为 `00_索引.md`、单文件内容主文档为 `01_PRD-{项目名}.md`。此前 SKILL 产的是 `00_PRD-{项目名}-总览.md`（索引）与 `00_PRD-{项目名}.md`（内容主文档），两个旧锚都由命令端 override 改名，故正文长期写着"override 旧锚"的说明。旧锚被 SKILL 废除后，命令端只剩一件事——把内容主文档名**映射**为 `01_研发需求.md`，override 语义随之退役，正文不再提旧锚。

## 表 E 完整性门与「表 F 机读副本」为何是两次调用

`check_semantic_change.py` 跑两次，职责不同，别合并：

- **第一次（无 `--emit-json`）= 判错门**：仅命中语义变更信号词或笼统豁免表述时生效，
  退出码 1 = 缺表 E 阻塞。专防「口径由仅企业改为企业+个人」这类语义变更时，派生说明文案漏改。
  无信号又无豁免则 grandfather 放行退出码 0。
- **第二次（带 `--emit-json`）= 产机读副本**：下游 `version-auditor` 审计 G/H、
  `dev-manual-testcase` 文案用例族都要读它。只留 markdown 时它们只能正则抽编号，
  而同仓 18 个版本出现过 4 种编号写法，正则方案很脆。

### 为什么第二次调用不能挂 `|| true`

三个退出码语义完全不同，而 `|| true` 把它们抹平成一个"成功"：

| rc | 含义 | 副本写了吗 | 该怎么处置 |
| :-: | :- | :-: | :- |
| 0 | 门过、副本已写 | ✅ | 继续 |
| 1 | **门未过**（表 E 有占位等），但副本**照写**且 payload 带 `gate.failed` | ✅ | **此处放行** —— 第一次调用已经阻断过了，这里再断一次是重复 |
| 2 | 入参/路径错，**副本根本没写** | ❌ | **必须阻断** |

要命的是 rc=2：副本没写成，而下游读时聚合会得到"没有任何作废记录"——
这与"本版确实没有作废"**在产物上完全同形**。表 F 的冗余副本被收敛掉之后，
这个文件就是唯一机读信源，它的产出失败必须响。

故只拦 rc=2，并额外断言文件非空（`-s`）——脚本在路径合法时**恒落盘**，
表 E/F 为空只是数组为空、文件仍在，所以"文件不存在或为空"一定是异常而非正常态。
