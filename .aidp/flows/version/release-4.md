#### Step 3.3.8.2：生成版本测试报告（单文件 HTML）

> ⛔ **仅当 3.3.8.1 的 `SKIP_338 == 0` 时执行本小节**；`SKIP_338 == 1` 直接跳到 **3.3.9**（不视为失败，也**不得**因此中断发布链）。

**输出路径**：`docs/reports/{version}/版本测试报告/{version}-测试报告.html`

**定位**：这是一份**版本的正式对外测试报告**（交付/存档用）——**去除所有 build 构建版本标识 + 不含任何应用截图**，读者只看到「本版本的测试结果」，不感知底层有几个 build。

**生成算法**：套用 `{{AIDP_HOME}}/templates/reports/版本测试报告/{version}-测试报告.html` 模板（完全自包含：CSS+JS+数据+SVG 图表全内联）：

1. 读 `$BTR_DATA/*.js`（排除 `示例_*`），取 `buildNo` 最大的那个 build（**最后收敛的一轮 = 最终验收态**）作为本版本最终测试结果。
2. **剥离后内联（关键 — 交付文件源码也无 build/截图痕迹）**：只把该 build 的 `summary` / `suites` / `cases` / `defects` / `runtimeErrors` 内联进模板 `<script>`（写成单元素 `window.__BUILDS__=[{...}]` 或模板约定结构），并**删除** `build` / `buildNo` / `version` 等 build 标识字段 + `screenshot` / `screenshots` 截图字段——使**最终生成的 HTML 源码里也不出现任何 build 号、任何截图路径**（不只是不显示）。
3. **填版本元信息**：写 `window.__VERSION_META__ = { version, milestone, releaseDate, environment:{deployMode,url} }`（从发布上下文取里程碑/发布日期/部署环境），与底层数据解耦，供报告头副标题 + 版本信息表用。
4. 模板 JS 渲染版本级视图：版本信息 + 测试总览 KPI + 通过率环形图 + 用例分布图 + 套件结果表 + 缺陷汇总表（编号/标题/严重度/状态，无 build 列、无截图列）+ 测试结论。
5. 标题取 `{version} 版本测试报告`，测试结论依最终通过率（✅通过 / ⚠️有遗留 / ❌不通过）。
