### Step 3.3.11：★ 全量详细设计生成（仅正式发布，变更范围增量重算 + 覆盖式只留最新、独立自包含）

**目标**：把「最新代码事实 + 全量历史需求 + 各版本详细设计」整合成一份**独立可交付的全量版本详细设计**，落 `docs/design/detail/全量/`。它是**跨版本累积的最新全量设计**（区别于 `docs/design/detail/{version}/` 的**单版本增量**设计），供交付 / 新人 / 审计**脱离其它文件独立通读、独立使用**。

**执行时机**：Step 3.3.10（`release-5.md`；发布期收敛）之后、Step 3.4.1（`release-7.md`；发布提交）之前——收敛完成、本版本设计已是最新干净态，再据此重算全量。

**★ 触发门（仅正式发布）**：**仅正式发布（打 tag）路径执行**；`--no-tag` 准发布（autopilot 无人值守）**跳过本步**。判定：本次调用带 `--no-tag` → 打印 "⏭️ 全量详细设计仅正式发布生成，准发布跳过" 并直接进 Step 3.4。
> ★ **dev/test 期不碰全量设计（约定 34 ⑤ 边界）**：本步是 `docs/design/detail/全量/` 的**唯一**生产/重算入口。故 `/sprint-dev`·`/sprint-test`·`/sprint-bugfix` 等 dev/test 期命令运行时，`全量/` 仍是"上一次正式发布"的旧口径 = **预期正常态**，**绝不在 dev/test 期提议 / 处理其"旧口径"**（如"全量详设仍写 V0.9.2 旧口径，要不要处理"——越界，答案恒为否），它由下次正式发布本步覆盖式重算。

**输入（多源整合，最新代码为唯一事实源）**：
- **最新代码事实（最高优先级）**：`code/` 实际状态 + 本版本 `docs/design/detail/{version}/*事实清单.md`（application.yml / 路由 / 表结构 / 跨项目接口的真值）。全量设计是**基于截至 `{当前版本}` 的最新代码实现的完整设计快照**，**不是"版本区间的叠加"**。
- **全量历史需求**：`docs/requirements/` 下【所有】`V*` 研发需求（`docs/requirements/{V*}/研发需求/`），**含仅有需求、无设计目录的早期版本**（如 V0.5.2 / V0.6）——**不设起始版本下界**；已按 Step 3.3.10 收敛结论排除的废弃 / 延期项不纳入。
- **各版本详细设计**：`docs/design/detail/` 下【所有】`V*`（**排除 `全量/` 自身**）收敛后的最新态。
- **★ 扫描范围 = 上述两目录 `V*` 的并集**（需求目录 ∪ 设计目录）；**严禁以"设计目录最早版本"作为范围下界**——早期只提需求、未产设计的版本同样纳入。
- **★ 事实源优先级（冲突裁决）**：**最新代码 > 事实清单 > 版本设计 > 版本需求**，四者冲突一律**以代码为准**（CLAUDE.md「代码作为最终事实源」）。

**输出（拆分态自包含，覆盖式只留最新）**：
- **目录 + 推荐分册骨架（拆分态自包含）**：`docs/design/detail/全量/`，内部按拆分态组织——`00_索引.md`（**仅目录内导航**）/ `01_详细设计.md` / `02_数据库设计.md` / `03_接口设计.md` / `04_集成对接.md`（+ 按需 `NN_<专题>.md`）/ `98_事实清单.md`（全量代码基线，如有）；命名 / 编号沿用设计目录 `00_` / `98_` / `99_` 槽位规则（`00_` 索引互斥、`99_` 末位）。
- **★ 自包含铁律（不引用外部文件）**：正文**只在 `全量/` 目录内组织与导航**，**严禁**引用 `全量/` 以外任何版本设计 / 需求 / 代码 / 原型文件——必要事实与溯源一律**内联成正文叙述**，不留 `../{version}/…`、`docs/requirements/…`、`code/…` 之类外链。生成后跑**自包含自检**（正文只许目录内 `./0N_` 互链；命中即外链残留，须改写为内联叙述）：
  ```bash
  grep -rnE '\.\./|docs/|code/|memory/|references|prototype/' docs/design/detail/全量/ \
    | grep -vE '\./(00|01|02|03|04|98|99)_'
  ```
  无输出 = 自包含通过；有命中逐条改写为内联叙述后复跑。
- **★ 变更范围增量重算（默认；缩小重算量而不降完整性）**：全量设计每次跟随正式发布更新，但**默认只重算「本次发布真正动过的专题」**、未动的专题从上一版全量**原样前滚**；完整性由「约定 22/34 扩范围安全网 + 全集索引核对」双重兜底，不因增量而降级。带 `--full-rebuild` 或命中自动兜底条件时退化为从零全量重算（见第 6 点）。
  1. **基线锚点（sidecar，不进交付正文）**：每次全量生成后把锚点写到 `docs/design/detail/.全量-baseline.json`——它在 `全量/` 目录**之外**、`.` 前缀隐藏、天然不匹配 `V*`、不受自包含自检约束：`{ "built_from_commit":"<sha>", "built_from_tag":"<tag|null>", "built_date":"<YYYY-MM-DD>", "rebuild_kind":"full|incremental", "releases_since_full":<int>, "topics":["01_详细设计", …] }`。**★ 版本溯源只落 sidecar / 发布报告，绝不进 `全量/` 正文**——正文统一表述「基于截至当前版本的最新代码实现的完整设计快照」（与本步「版本溯源不进交付件正文」铁律一致）。
  2. **算变更面 Δ**：以 sidecar `built_from_commit` 为基（无则触发第 6 点全量兜底），`git diff --name-only {base}..HEAD -- code/ docs/design/detail/{当前版本}/ docs/requirements/{当前版本}/` 取变更文件 → 按「代码路径归属的模块 + 变更的版本设计/需求所属专题」映射出**变更专题集 Δ**。
  3. **★ 约定 22/34 扩范围安全网（增量安全的核心，堵 git 文件级 diff 的语义盲区；根因见 `rationale.md`）**：必须**额外扫本版研发需求**：命中约定 22 第三类语义变更 或 表 F 判「作废/修订」的项 → 其受影响专题**强制并入 Δ**（即便无代码文件命中）；变更若落在**跨专题共享单元**（公共基础设施 / 基类实体 / 共享 DTO / 全局配置）→ 保守地把所有引用该单元的专题并入 Δ。**宁可多算一个专题，绝不漏传播一处语义。**
  4. **前滚未变专题 + 重算变更专题**：staging 组装时——**Δ 外专题**从旧 `全量/` 对应分册**原样复制进 staging**（信任前滚、不重新合成）；**Δ 内专题走下方 4bis 的 section 级前滚**，⛔ 不整册重写。
  4bis. **★ 分册内 section 级前滚（不做则增量退化为准全量，根因见 rationale.md「专题级增量为何不够」）**：
     - **重算前先报覆盖率**（⛔ 必须在开工前）：`python3 {{AIDP_HOME}}/scripts/design_full_rollforward.py scope --full-dir docs/design/detail/全量 --delta <Δ专题名逗号分隔>`，≥70% 时脚本会告警要求启用本条。
     - **以旧分册为底本、只重写 Δ 命中的 H2 章节**，其余章节原样保留：`design_full_rollforward.py rollforward --old 全量/NN_x.md --new .全量-staging/NN_x.md --sections "<待重写H2>" --out .全量-staging/NN_x.md`。**哪些章节要重写是语义判断**（由 Δ 映射决定），脚本只保证"没点名的章节一字节不动"、并对点名却在新内容里缺失的章节**报错而非静默丢弃**。
     - **守恒核对只对被重写章节做深核**；未动章节与前滚专题同待遇，交第 5 点全集索引核对兜底。
     - **本步派独立子 Agent 执行**（与 3.3.9.5 同规格；理据见 `rationale.md`）。
  5. **★ 全集索引核对（轻量完整性兜底，O(索引) 非 O(推导)）**：staging 组装完（前滚 + 重算混合）后，枚举**全集**代码事实索引（接口签名/路由 ∪ 表 ∪ 模块 ∪ 全量需求项），逐项核对「在某个 staging 分册里有归属」。发现**孤儿项**（某代码事实无任何分册覆盖，典型：该事实被改动但其专题未进 Δ、被错误前滚）→ 把其所属专题**补进 Δ 重算**后复跑本核对，直至无孤儿；反复补仍无法消解 → 触发第 6 点全量兜底。
  6. **兜底触发全量重算（`--full-rebuild` 或自动）**：下列任一 → 跳过增量、对**全部专题**从零重算（等价旧「覆盖式重算」）：① 显式 `--full-rebuild`；② sidecar 缺失（首次生成 / 从未建基线）；③ `built_from_commit` 非 HEAD 祖先（历史被 rewrite、无法 diff）；④ `releases_since_full` 达阈值（默认 **≥5**，防增量漂移累积；每次全量重建清零、每次增量 +1）；⑤ 第 5 点索引核对反复补 Δ 仍无法消解孤儿。
- **★ 只留最新、无历史（分块 staging 原子替换；理据见 `rationale.md`）**：目录内永远只有「当前最新全量设计」、不留历史版本 / `NN_补充-*.md` / 版本子目录；**生成方式为分专题产出（增量前滚 + 变更重算混合）+ 全部守恒通过才整体替换**：
  1. **分专题产出到 staging**：新全量**先写到临时目录** `docs/design/detail/.全量-staging/`，**按专题分块**组装（`01_详细设计` / `02_数据库设计` / `03_接口设计` / `04_集成对接` / …，每块独立成文）——**Δ 内专题现场生成、Δ 外专题从旧 `全量/` 前滚复制**（上「变更范围增量」第 4 点）。
  2. **逐块守恒核对**：**每个 Δ 内（现场生成）专题块**产出后立即做**守恒核对**——该专题涉及的接口/表/模块，在「最新代码事实 + 全量需求 + 各版本设计」里应覆盖的项逐条核对已写入 staging 块（不漏、不凭空造）；某块守恒不过 → **只标记该块欠账**、其余块继续（见失败兜底）。前滚块不重复深核，由第 5 点全集索引核对统一兜底。
  3. **全部块守恒通过 + 全集索引核对无孤儿 → 原子替换 + 更新 sidecar**：才 `git rm -r docs/design/detail/全量/`（若存在）+ 把 `.全量-staging/*` 搬入 `docs/design/detail/全量/`（原子切换），并**刷新 `.全量-baseline.json`**（`built_from_commit=HEAD`、`built_date`、`rebuild_kind`、`releases_since_full` 按第 6 点增/清零）。
  4. **有块未过 → 保留旧版 + 差异报告 + 不更新 sidecar**：任一专题块守恒未过 → **不替换旧 `全量/`**（旧版原样保留、绝不先 rm）、staging 保留供人工核对、产出「差异报告」（见失败兜底），且**不刷新 sidecar**（下次仍从上一成功基线 diff，未落地的变更自然进下次 Δ、不丢失）。
- **★ 现状 vs 规范如实留痕（"最新代码为唯一事实源"的落地）**：全量设计须**如实标注代码现状与理想规范的偏离**——占位桩 / mock 骨架、`@Deprecated` 等废弃接口、违反项目规范的存量写法等，一律照实写进设计（标注「现状：… ／ 规范应为：…」），**不得只写理想设计而掩盖代码现状**。

**编排（命令层整合合成为主，不改上游 SKILL）**：本步以**命令层文档整合合成**为主（类同 Step 3.3.10 收敛的合并思路）——把各版本收敛后设计**按专题合并** → 以**最新代码事实校正**（代码为准：删已被代码淘汰的设计、补代码已实现而设计漏写的）→ 以**全量需求**补全覆盖 → 产出自包含 `全量/`。可选调 `dev-logic-architect` 做设计正文的质量提升 / 查漏，但**全量目录组织 / 自包含改写 / 覆盖式只留最新是命令层职责**；若调 SKILL，命令端 override 输出路径为 `全量/` 并显式传「自包含、仅目录内导航、不引用外部文件、覆盖只留最新」打包约束，SKILL 内部规则为单一信源、命令端不复述（约定 21）。

**★ 执行清单（以真实代码为唯一事实源，如实标注现状 vs 规范）**：分专题产出每块时按此清单落地——
1. **枚举真实代码事实**：从 `code/` + 本版本 `*事实清单.md` 提取该专题的**真实**接口签名/路由、表结构/字段、跨项目调用、配置项（application.yml/vite）——这是**唯一事实源**。
2. **对齐设计正文**：把该专题各版本收敛后设计 + 全量需求**对齐到代码事实**——代码有而设计漏 → 补；设计有而代码已淘汰 → 删；两者冲突 → 以代码为准改写。
3. **如实标注现状 vs 规范**：占位桩/mock 骨架、`@Deprecated` 废弃接口、违反规范的存量写法 → 照实写进设计并标「现状：… ／ 规范应为：…」，**不掩盖代码现状**。
4. **守恒核对该块**：该专题「代码事实项 ∪ 全量需求项」逐条在 staging 块可查到，缺项即该块守恒不过、挂欠账。

**★ 上游收敛部分失败的容错（关键鲁棒性）**：Step 3.3.10（`release-5.md`）收敛**部分失败**（个别族/项挂欠账、主文档未完全收敛干净）时，**本步仍能基于代码产出可用全量**（理据见 `rationale.md`）；故上游文档收敛未尽善**不阻断**全量重算，只是把「还没收敛干净的主题」按代码现状如实写、并在报告注明「该主题以代码现状为准，上游收敛欠账见 `发布欠账.md`」。**绝不因上游收敛未完成就整步跳过全量重算**。

**排除（全量目录非版本目录）**：`全量/` **不是** `{version}` 版本目录——不进版本级收敛（3.3.10）/ 版本规划产物审计（Step 2.4.7）/ `DESIGN_COUNT` 版本探测；`/sprint-design` 前版基线扫描（Step 0.1 / 0.2）、`/health-check` 目录层级检查、`verify.py` 目录巡检均**豁免 `全量`、`.全量-staging` 与 `.全量-baseline.json`**（与 `README` 同级豁免，不当作 `V*` 版本目录/文件判违规）。`.全量-staging/` 是本步增量生成的临时暂存目录（`.` 前缀隐藏、天然不匹配 `V*`），成功即搬空、失败时保留供 `--finalize-docs`/人工核对；`.全量-baseline.json` 是变更范围增量的基线锚点 sidecar（`.` 前缀隐藏、`全量/` 目录之外、不进交付正文），随全量成功生成刷新。

**失败兜底（★ 保留旧版 + 差异报告 + 欠账登记，非整步放弃）**：
- **某专题块守恒未过** → **不替换旧 `全量/`**（旧版原样保留、绝不先 `git rm`）；产出**差异报告** `docs/audit/{version}/全量设计差异-YYYY-MM-DD.md`（逐块列「该块应覆盖项 vs staging 实际写入项」的差集：漏了哪些接口/表/模块 + 精确定位），并登记 `docs/audit/{version}/发布欠账.md`（步骤=Step 3.3.11，补跑命令 `/version {version} --finalize-docs`）。
- **能过的块先落 staging 保留**：守恒通过的专题块留在 `.全量-staging/`；**仅当全部块通过**才原子替换 `全量/`；未全通过则**整体保留旧 `全量/` + 保留 staging** 供人工据差异报告补齐后 `--finalize-docs` 重跑。
- **完全生成失败**（连 staging 都没建起来，如代码扫描异常）→ 保留旧 `全量/` 不动 + WARN + 欠账登记，继续 Step 3.4。
- 发布报告 Step 3.6 加对应 WARN + 差异报告链接；**绝不出现「旧版已删、新版没成」的空全量**。

**与 Step 3.4.1（`release-7.md`）的协作**：Step 3.4.1 的 `git add docs/` 会把 `全量/` 的 `git rm` 旧 + 重生新一并落到 `release({version})` 提交。

**发布报告段（版本溯源只进报告 / 生成日志，不进交付件正文）**：Step 3.6 发布报告新增「全量详细设计」段（**本次重算方式** `增量 / 全量` + 触发原因 / **重算专题 Δ 清单**（增量时）+ **前滚专题清单** / `releases_since_full` 计数 / 全集索引核对是否无孤儿 / 生成的分册清单 / 自包含自检是否通过 / **参考的历史版本文档清单**——本次整合扫描到的 `docs/requirements/` 与 `docs/design/detail/` 下各 `V*`）。**★ 版本溯源信息只允许出现在发布报告 / 生成日志**——`全量/` 交付件正文（含 `00_索引`）**严禁**出现「整合的版本范围 `Vx→Vy`」「整合版本范围」等字样；需溯源时正文统一表述为「基于截至 `{当前版本}` 的最新代码实现的完整设计快照」。

### Step 3.3.12bis：★ 零残留断言发布总闸（打 tag 前，⛔ 不接受任何 `skipped`）

> **发布前把登记表全部跑一次**——⛔ **不接受任何 `skipped`**。口径单一信源 =
> `dev-execution-planner`「轮次收尾验证任务」；形态机检归 `check_residual_assertions.py`，
> 本步只判**跑没跑过**。理据见 `rationale.md`。

```bash
VERSION="{version}"; case "$VERSION" in "{version}"|"") VERSION=$(python3 {{AIDP_HOME}}/scripts/baseline_edit.py current-version);; esac
[ -n "$VERSION" ] || { echo "⛔ 取不到版本号"; exit 1; }
# ⛔ --as-of 传【今天】：沿用上一轮的实跑日期不算"跑过"
# ⛔ 失败必须真落账（只喊话 = 与"总闸通过了"同形，见 rationale.md）
```
