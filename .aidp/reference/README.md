## ⛔ 维护边界（约定 16）

本目录是**脚手架契约文件**，随 `aidp-code-engineer` 下发/升级同步 —— 下游直接手改会在下次升级被覆盖。
需变更详规 → 改模板项目本体 → 镜像进 bundle。

**唯一例外：`子Agent必读.md` 是「用户填充型契约」。** 脚手架只发骨架（含 `<填写：…>` 占位符），
下游在开发期持续往里累积项目专属的坑。判定走 `scaffold_lib.py::decide_user_fillable()`，**权威判据 = 指纹台账**
`.aidp-user-fillable.json`（记「上次写给下游的那份骨架」的 sha256）：

| 下游那份 | 判定 | 动作 |
|---|---|---|
| 与台账指纹**逐字节相等** | 没人填过 | **刷新骨架** + 更新台账 |
| 与台账指纹**不同**，且新骨架 = 台账骨架 | 填过了，骨架没变 | 无动作（无可合并） |
| 与台账指纹**不同**，且新骨架 ≠ 台账骨架 | 填过了，骨架有变化 | **不覆盖**，进 `.aidp-rewrite-queue.txt` 交 Agent 语义并入新骨架段落；`finalize_upgrade.py` 收口时台账推进到新骨架 |
| 已等于新骨架 | 幂等 | 无动作（顺手补台账）|
| 台账缺失 | 与上一版脚手架安装件相等 → 刷新；否则退回 `_has_user_content()` 兜底 | 只朝「保护」一侧失真 |

⛔ 判据**不是**「占位符是否全部消失」——该文件有十几个槽位，团队填 2~3 个是常态，
按「填满才保护」会制造安全错觉。
⛔ 也**不能**拿下游内容去比【新】骨架：上游一删改行，下游那份**未经任何填写的旧骨架**里就会
出现「新骨架没有的行」→ 恒判已填 → **骨架升级对存量下游永久不可达**（实测 5 个历史骨架误判 4 个）。
⛔ 保护 ≠ 丢弃：保护分支**必须入改写队列**，否则新增必读段 / 新槽位 / 新维护规则对填过的下游
永久到不了，且连一条待办都不留。收口时机 = `/sprint-close` Step 5.1。
本文件**不参与** `verify.py::check_contract_drift` 的指纹比对（按设计允许偏离）。

## 新增文件时

1. 必须有**至少一处指针**指过来 —— 否则实际上没人会读到它。⚠️ **这一条目前没有机器门**：`verify.py` 的孤儿检查只管本体↔bundle 镜像，`check_singlesource_pointer.py` 只做**正向**指针可解析性，都不反向校验「本目录某文件有没有被指过」。靠人守。
2. 在上表登记一行。
3. 跑一次 `python3 {{AIDP_HOME}}/skills/aidp-code-engineer/scripts/mirror_to_bundle.py` 镜像进脚手架。
