# 部署操作约定

本文件是命令侧规则，不复制到下游 `docs/deployment/` 操作指引。

## 文档时机与内容

- `docs/deployment/` 只给运维实际怎么做：环境/服务/库、命令步骤、成功判据、必要回退。不写 AI 过程、授权对话、门禁预算、测试/审查报告、契约修订或 Git/流水线可取的历史。
- 仅版本规划、正式发布集中生成/校准必要指引。日常 dev / bugfix / 链外 / 部署仅把实际步骤变化引用写入既有 baseline 的 `deployment_doc_pending`，不新增部署 Markdown，不为日志额外 commit/push。用户明确要求报告才额外产出；正式 aiauto 报告与两路测试职责保持原约定。
- 版本根 `README.md` 若已承载唯一部署操作说明，原地校准，不再复制 `部署流程.md`。有实际部署产物才维护入口；无必要不造空目录或子索引。
- SQL 脚本继续全量/增量双轨。SQL执行台账默认只有 `目标数据库 | SQL脚本路径（按执行顺序）`；仅必要时分手工新装/升级/回退。自动启动迁移只注明无需重复手工执行；无手工 SQL 一句说明。执行结果、真实时间和 DDL 注释实查证据留在现有机器记录，不填多环境状态大表。
- 配置清单仅本版改动项与权威路径，不抄全量内容；部署流程引用该路径。发布期约定 37 的真实配置文件基线保持，但说明文件不携带审查分析。

集中汇合先读取机器待办：

```bash
python3 {{AIDP_HOME}}/scripts/deployment_ops.py pending --version "${VERSION:?}"
```

逐引用核对当前实际交付，更新唯一操作说明及必要 SQL/配置指引。成功合并后用 `baseline_edit.py` 删除 `deployment_doc_pending."{version}"` 中已覆盖项；有并发新增或遗漏时只结清对应项，不整段清空。不得把本次接近发布当成补做历史审计的授权。

SQL 指引可由已有机器记录提供 `{install|upgrade|rollback: [{database, scripts: [仓库相对路径]}], automatic: true|false}`；只取这些操作字段，脚本按数组顺序保留并校验存在与双轨归属：

```bash
python3 {{AIDP_HOME}}/scripts/deployment_ops.py sql-ledger --version "${VERSION:?}" --phase release --input "${SQL_OPERATIONS:?}"
```

规划时 `--phase planning`；日常 `--phase daily` 只返回待同步项、不写 Markdown。SQL_OPERATIONS 指向本项目既有运行记录中的操作输入，不为凑输入另造报告。

## 备份频率与真实记录

部署前读项目现有备份策略与真实记录，DB、完整冷备、迁移前快照按实际备份操作合并计数。一天最多一次就是合计一次，不能按调用方、类型、环境或版本拆额度，也不能把业务数据副本改名“前像”绕过。工具自身受管文件的原子写保护不属于业务备份；任何实际复制业务 DB/服务数据仍受本节约束。

同日复用必须核实目标覆盖、产物可用、真实备份时点。复用保留原时间，不把复用时间写成新备份时间；不承诺保护其后新增业务数据。达到频率上限且无适用备份、记录缺失/矛盾、上次操作未结清或备份失败时，明确报告前提缺口；不能自动追加备份、扩容、改策略或自动恢复。确需例外由用户明确决定，脚本没有绕限开关。

项目已有统一备份接口时直接使用它；未具备统一频率门且已有可调用备份命令时可使用 `deployment_ops.py backup` 小工具。配置位于 `memory/aidp-config.yaml` 的 `deployment.backup`（默认 null，不自动启用）：

- `max_per_day`、`timezone`：用户既有频率与时区；不得自行填宽松值。
- `record_file`：所有备份类型、触发入口共享的现有权威记录文件。跨主机必须接入项目中央接口/同一可靠锁，不能各自建本地记录。
- `commands.database|cold|migration`：项目已存在命令的 argv 数组，不臆造脚本或 flag。一次调用只承载一项真实备份操作；一个脚本内部捆绑多个独立备份时须由项目现有中央接口合计，不得按一次 argv 规避额度。命令 stdout 须有实际回执 `{backed_up_at: 带时区的真实时点, targets: [实际目标], artifacts: [可核验非空产物路径]}`；不支持时报告接口前提缺口，不临时开发控制器。
- `skip_args`：仅登记现有部署脚本已支持的跳过备份参数。空数组不表示脚本能跳过；部署器会内置备份却不能跳过时须说明接口缺口，不能直接运行造成第二次复制。
- 可选 `timeout_seconds`：项目命令现有超时（默认 3600 秒）。

`record_file` 必须事先依据真实历史核对，结构为 `{verified_at: 带时区的核对时间, backups: [...]}`；缺失不能初始化空表冒充零次。每条保留 `id/kind/targets/status/started_at/finished_at`，成功还需 `backed_up_at/artifacts`；历史核对不改变真实备份时间。运行中/已启动失败的操作可能已复制数据，保守占额，不自动重复；进程未启动则记录 `not-executed`，不占实际备份次数。成功回执与非零后续命令分别表达为真实备份成功和 `post-backup-failed`；终态登记失败返回 `recording-failed` 与 `operation_status`，不自动重跑。小工具只对产物做存在/非空检查，复用不读取完整大备份或复制新证据。它锁内检查并写运行占位、调用现成命令、核回执、记终态；不部署、不 Git、不恢复。

```bash
# 沿用父任务上下文；只检查现有 deploy 授权，不另授予动作、不重复扣已管理预算。
EXECUTION_CONTEXT="${EXECUTION_CONTEXT:?从父任务入参重绑真实上下文路径}"
python3 {{AIDP_HOME}}/scripts/execution_policy.py require-action --root . \
  --execution-context "$EXECUTION_CONTEXT" --action deploy || exit $?
# 授权门通过后，仍须符合项目备份策略；迁移/冷备也走这同一配方。
python3 {{AIDP_HOME}}/scripts/deployment_ops.py backup --kind database --target "${BACKUP_TARGET:?}"
```

此门只包围实际备份调用；`pending`、`note` 和 `sql-ledger` 不因复用本工具而索取 deploy 权限。

返回 `succeeded` 或 `reused` 后只按已核实的 `skip_args` 调现有部署器；`failed` / `prerequisite-missing` 返回非零并停止相关操作。迁移快照也先走同一门（`--kind migration`），不得在其后另跑一次复制。该工具不代替父执行授权，不因通过频率检查就产生 deploy 权限。
