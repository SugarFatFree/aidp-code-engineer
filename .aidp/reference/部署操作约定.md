# 部署操作约定

本文件是命令侧规则，不复制到下游 `docs/deployment/` 操作指引。

## 默认动作

用户说「提交推送并部署」，执行体默认只做三件事：`git commit`、`git push`、运行项目现有部署脚本。其余步骤（备份、部署后核验、写部署记录等）用户明确要求才做；不为这三个动作建任务上下文、写状态记录或修改被 git 跟踪的文件。

备份与部署后核验不属于 AIDP 通用要求，是项目自有运维策略（写在项目自己的部署文档或脚本里）；AIDP 不要求、不阻碍。部署脚本需要排除未跟踪目录（`docs/`、`memory/`）时，在脚本排除项或 `.gitignore` 中解决，不另行导出源码。

## `docs/deployment` 的定位与更新时机

- 本目录同时保存可执行部署资产与运维文档；文档只写每步做什么、怎么做，精简，不写原因、历史、AI 过程、授权对话、门禁预算或测试/审查报告。
- **数据库脚本、实际配置文件**可随开发或修复实时更新，只改当前任务涉及的部署资产；运行时原文件仍是权威，不为留痕复制配置。
- **文档性内容**（操作手册、部署说明、配置项清单、SQL 执行台账）集中在 `/version` 规划期与正式发布期对照本版 diff/现状整理。日常不要求同步这些文档或登记待同步引用；普通部署只执行既有脚本，不制造资产或文档改动。
- 版本根 `README.md` 若已承载唯一操作说明，原地校准，不再复制 `部署流程.md`。有实际部署产物才维护入口；无必要不造空目录或子索引。
- 不设「部署记录」「验证范围与告警」章节。

## SQL 与配置

- SQL 脚本继续全量/增量双轨，两套不可叠加；`sql/增量/*.sql` 是开发产物与可执行迁移，随开发产出，不属于部署记录。
- SQL执行台账仅规划/发布期生成，默认只有 `目标数据库 | SQL脚本路径（按执行顺序）`；仅必要时分手工新装/升级/回退；自动启动迁移只注明无需重复手工执行；无手工 SQL 一句说明。普通部署不写台账。
- 实际配置文件按需随开发更新；配置清单等 Markdown 留到规划/发布期，仅列本版增删改动项、权威路径与必要片段（按权威文件/dataId 给片段与短注释；nginx/compose/k8s 只给改动片段、插入位置与生效命令；删除标明单 key 或整段；秘密值不进 Markdown），不抄全量内容；部署流程只引用该清单，不双写。发布期约定 37 的真实配置全量基线保持。

发布期可由已有机器记录提供 `{install|upgrade|rollback: [{database, scripts: [仓库相对路径]}], automatic: true|false}` 渲染台账；脚本按数组顺序保留并校验存在与双轨归属：

```bash
python3 {{AIDP_HOME}}/scripts/deployment_ops.py sql-ledger --version "${VERSION:?}" --phase release --input "${SQL_OPERATIONS:?}"
```

规划期用 `--phase planning`。
