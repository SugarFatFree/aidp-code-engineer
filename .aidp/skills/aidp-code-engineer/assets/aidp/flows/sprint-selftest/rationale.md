> **谁读**：维护者改规则前读本文件理解意图；**执行期模型不读本文件**（命令主体只留精瘦骨架 + 指向 flow 的指针；详情在 `step-1-1.md` / `step-1-2.md` / `step-3-1.md` / `step-3-2.md`）。
> **渐进迁移**：命令主体与 `step-*.md` 里目前仍夹带的 `**Why**` / `根因` 叙述，会逐步搬来本文件，让执行路径只剩可核验的祈使清单。本文件随迁随长。

## Step 1 的根因（速查）

- **启动横幅 + 横幅后必有 `Skill` 调用**——根因：长任务里 skill 编排步骤最易被"默念跳过"，横幅是终端可见的"本步骤确被触发"锚点；横幅后无 `Skill` 调用即判违规，堵"输出横幅但没真调 SKILL"。
- **缺用例 / 缺方案 = 硬阻断 `exit 1`**——根因：SKILL 内部 QR 偶发未触发或输出到错目录时，命令端若不落盘核验就"当作已完成"继续，会让下游 `/sprint-aiauto-test` 读到空/缺产物；故方案缺失单独硬拦，不单依赖易被跳过的 Step 2 item 8。
- **约定 33 规划期基线显式传参**——根因：PRD 原文 / 原型内容基线 / 字段处置对照表等不显式传给 SKILL，"漏项/漏列/统计口径错"就测不出（AI 测试全绿却漏测）；命令层传参是约定 33「规划期基线→测试期消费」的落点。
- **跨版本继承基线喂给 SKILL**——根因：环境/账号跨版本一般不变，若每版重问重填会打扰用户；把上一版方案「环境」段作继承源，默认沿用、本版只补充。

## Step 3 的根因（速查）

- **全量继承 + 加法式增量补充（默认补充、非覆盖）**——根因：环境/账号跨版本稳定，"整份覆盖"会丢已手工填写的现场值；改为默认全量继承上版、只追加本版新增，除非本版 PRD/设计显式改/删，杜绝"本版没提到就清空"。
- **append-only、已填字段不覆盖**——根因：`01_测试环境与账号.md` 是人工填 Chrome IP / URL / 账号的现场配置，命令重跑时覆盖已填值会抹掉现场，故已存在字段一律不动、只补缺。
- **⛔ 远程连接铁律**——根因：远程 chrome 端点在 Claude Code 启动时锁定（MCP 配置只读一次），`.mcp.json` 写入由 `/sprint-aiauto-test` 统一处理；测试方案只填 Chrome IP，避免 .mcp.json 双处维护漂移。
- **与 SKILL「研发自测方案」职责隔离**——根因：连接配置 + 账号（本步 Write）与范围/通过准则/缺陷跟踪（SKILL 生成）是两类关注点，混在一份文档会双写、升级不同步。
