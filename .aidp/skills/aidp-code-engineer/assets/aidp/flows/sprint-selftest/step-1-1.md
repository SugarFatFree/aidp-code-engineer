使用 `Skill` 工具调用 `dev-manual-testcase`，由 skill 自主完成研发自测方案 + 自测用例生成 + 内置多维度独立 Agent 检查 + 多轮 Quality Review 阻塞完成判定。**SKILL 内规则为单一信源**，命令端按 CLAUDE.md 约定 21 不复述、不修改，仅做编排和项目级补充。

> 详细规则查 `.aidp/skills/dev-manual-testcase/SKILL.md`；命令端只负责传入路径上下文 + 输出位置 override。

**前置：定位「上一版本继承基线」**（本版未显式指定环境/账号时，SKILL 方案「环境」段沿用上一版；与 Step 3 同一 SemVer 扫描，此处只为把基线路径**喂给 SKILL 作输入**）：

```bash
CUR_V="{version}"
PREV_TEST_V=""
for d in $(ls -d docs/testing/V*/ 2>/dev/null | sed -E 's#.*/(V[^/]+)/#\1#' | sort -V); do
  [ "$d" = "$CUR_V" ] && continue
  [ "$(printf '%s\n%s\n' "$d" "$CUR_V" | sort -V | head -1)" = "$d" ] || continue   # 只留 < 当前版本
  [ -f "docs/testing/$d/研发自测/01_测试环境与账号.md" ] && PREV_TEST_V="$d"           # 取最近一个已有配置的旧版本
done
if [ -n "$PREV_TEST_V" ]; then
  echo "继承基线：docs/testing/$PREV_TEST_V/研发自测/01_研发自测方案.md（环境段）+ 01_测试环境与账号.md → 传给 SKILL 作本版环境/账号继承源"
else
  echo "无上一版继承基线（首版）→ SKILL 走第零步默认值 / 命令端 Step 3 fresh 生成"
fi
```

**调用参数**（按 SKILL 输入要求传入路径上下文）：
- **★ 需求规模档位（`--scale=S|M|L`，缺省 L）**：随 prompt **显式**传 `scale=<档位>` 给 SKILL（SKILL「需求规模档位」段接收，按档伸缩用例数基线；档位只伸缩产出规模、不放松任何 Critical 硬门）。档位来源：本命令 `--scale=` 入参 → `/version` Step 2.4.1.5 自动判档 → 均无则 L。**同一档位须在 Step 2 硬门的 `check_case_stats.py --scale <档位>` 里再显式传一次**（不传脚本按 L 档跑、只判 20 条硬下限，S/M 档漏判）。
- **★ 跨版本环境/账号继承基线（本版未显式指定环境/账号 → 复用上一版；环境跨版本一般不变，避免每版重填/重问）**：把上一版本 `docs/testing/${PREV_TEST_V}/研发自测/01_研发自测方案.md`「环境」段 + `01_测试环境与账号.md`（前置 bash 定位）作为**继承基线**显式传给 SKILL——SKILL 生成本版「研发自测方案」的「环境」段时**直接沿用上一版**，除非本版 PRD `autopilot_decisions.deployment` 显式给了新环境（才以 PRD 为准）；`PREV_TEST_V` 为空（首版）则走 SKILL 第零步默认值。**与 Step 3「测试环境与账号」的「全量继承 + 加法式补充」是同一原则的两半**（Step 3 全量继承配置文件本体并追加本版新增、本参数继承 SKILL 方案「环境」叙述段），口径一致：默认沿用上版、本版只做补充，除非明确改/删。
- **PRD 路径**：`docs/requirements/{version}/研发需求/`（含 `01_研发需求.md`（历史裸 `00_研发需求.md` 兼容）或拆分的 `0?_*.md`）
- **详细设计路径**：`docs/design/detail/{version}/`（skill 按 glob 加载全部分册，含事实清单的"路径消费者点"以构造跨系统验证用例）
- **研发执行计划路径**：`docs/plans/{version}/01_研发执行计划.md`（历史裸 `00_研发执行计划.md` 兼容；作为自测用例的追溯输入；增量 vs 全量由 prompt 描述驱动、分别产出 `02_增量自测用例.md` / `02_全量自测用例.md`，SKILL 无 mode 参数）
- **★ 规划期基线类文档 + PRD 原文（约定 33 强制输入，缺则 SKILL 无从消费、漏项/漏列/统计错测不出）**——把下列路径**显式**作为基线输入传给 SKILL，并笼统标注"这些是基线类文档、须为其中每个『实现』项逐项生成可验证断言用例"（约定 21 只传路径 + 笼统说明，不复述 SKILL 用例族机制）：
  - **PRD 原文**：`docs/requirements/{version}/产品提供/*.md`（**产品原始 PRD，与"研发需求"并列作独立基准**；用于 SKILL「PRD 原子条目存在性用例族」——以 PRD 原文为准、绕过研发需求层、引 PRD 行号，是唯一能捕获"设计本身漏项"的路径）
  - **原型内容基线**：`docs/design/detail/{version}/NN_原型内容基线.md`（约定 4；每个标「实现」的元素/交互态/操作流各生成一条断言用例，"标裁剪/延期仍存在"生成反向断言用例）
  - **设计令牌**：`docs/design/detail/{version}/NN_设计令牌.md`（约定 4 情形 B/C，如存在）
  - **字段处置对照表**：研发需求内「原型字段 → 处置」对照表（约定 4 三件套）+ **统计/汇总/计数/金额类字段**（据处置生成双源对账用例：页面取值 vs 等价 SQL 含软删/状态过滤，断言相等；DB 连接见 `step-3-2.md`「五、DB 连接」）
  - **表 E 语义变更→派生展示物影响清单**：研发需求内（约定 22 第三类；本版含语义/口径变更需求时存在）——供 SKILL「语义/口径变更类文案一致性用例族」为每个「改写」项生成正/反向文案断言（旧口径字样出现即判 Critical）
  - **文案落点表**：`docs/design/detail/{version}/` 详细设计内（约定 22 第三类，与表 E 配套）——文案改前/改后落点基线，缩小反向断言核对范围
  - **统计指标口径表**：`docs/design/detail/{version}/` 详细设计内（`dev-logic-architect` 检查项 34 产出的 8 列表）——SKILL「含数字的页」用例族**前五条以其逐行为基准**（单位/精度/时间窗/统计范围/跨页面同源；第 6 条另有基准，见下一行）；无则从 PRD + 页面现场取口径并把「设计缺口径表」登记进待澄清清单（约定39-R11/R12）
  - **渲染层归并声明表**：`docs/design/detail/{version}/` 详细设计内（`dev-logic-architect` 核心原则 29 / 检查项 37 产出的 5 列表）——SKILL「含数字的页」用例族**第 6 条「两位点数值自洽」**以其为基准：该表第 4 列「上游记录数 == 页面条目数?」填「否」的位点**逐个配用例**；无该表则从页面现场识别「同一指标出现在 ≥2 个位点」处并登记待澄清，⛔ 不得因上游没给就跳过该条（约定39-R12 的算术自洽维度）
  - **列表页数据量级与分页策略子表**：`docs/design/detail/{version}/` 详细设计内（`dev-logic-architect` 检查项 5 的子表）——列表页还原度模板「大数据量加载」一条的量级取自该表；⛔ 无该表也**不得**因「不知道多少条」跳过该条，须登记待澄清 + 给暂行量级（约定39-R13）
  - **上游调用日志与脱敏声明表**：`docs/design/detail/{version}/` 详细设计内（`dev-logic-architect` 检查项 35 产出的 6 列表）——**本次迭代新增或改动了出站调用时**触发 SKILL「日志可追溯」断言族，以表中**本轮新增/改动的那些行**为基准；无该表则从详细设计 / 执行计划识别本次改动的出站调用并登记待澄清。**本次未动出站调用则该族标「不适用 + 原因」**（约定 40）
  - > 上述均属约定 33「规划期基线 → 测试期消费入口」的命令层传参责任；未传 = 违反约定 33。

**输出路径约定**（命令端通过 prompt 显式传路径，以免 SKILL 按项目现有目录 `docs/test/`、`test/`、`tests/` 等自适应到别处）：
- **目标目录**：`docs/testing/{version}/研发自测/`（SKILL 产物先落 `{项目名}/` 子目录，命令端 Step 1 落盘核验后整体归一到此目录，保留 SKILL 的 `NN_` 前缀铁律）
- **单文件用例名**：`02_全量自测用例.md` / `02_增量自测用例.md`（遵 SKILL「同目录所有文件一律带 NN_ 前缀」铁律；`00_` 索引、`01_` 方案）
- **多文件拆分（skill 自身触发 — >40 用例或 >800 行/60KB）**：
  - `02_自测用例-总览.md`（用例总览主文档，**保留 SKILL 原名**；本目录导航锚 = SKILL 第八步收尾产出的 `00_索引.md`，方案在 `01_`，用例总览在 `02_`）
  - `03_<模块>.md`、`04_<模块>.md`…（业务模块用例，SKILL 从 `03_` 起编号）
  - 跨系统验证清单为 `98_跨系统验证清单.md`（skill 默认即 `98_`；`99_` 留给待澄清问题清单）

**额外提示**（命令端在调用 prompt 中说明）：
- 用例**不**包含接口/SQL 等代码级动作；用例之间共享登录态，按"测试套件"组织
- 让 skill 读 `docs/design/detail/{version}/*事实清单.md` 的「路径消费者点」表 + 反代/部署清单，把第三方系统（SSO 统一认证 / IM / 邮件 / Nginx 等）的"对方系统现象"显式写入用例
- skill 内部多维度检查会自动校验（覆盖率/一致性/拆分/待澄清等，详见 SKILL.md 单一信源），命令端不复述具体维度

**★ 项目级补充 — 信号传递（精简，按约定 21）**：
