**两行自检**（进入页面后先跑，两个都查才能定位问题）：

```js
window.isSecureContext      // 期望 true    —— 为 false 说明白名单没生效
typeof <能力入口>            // 期望 "object" —— 为 "undefined" 说明还缺实验特性开关
```

**常见失败原因**（按出现频率排序）：① **端口漏写**（`http://192.0.2.10` ≠ `http://192.0.2.10:8002`）
② scheme 不符（写了 `https://` 而实际 `http://`）③ 域名/IP 不一致（白名单写域名、实际用 IP 访问）
④ **只开了一个开关**（两个缺一则入口不存在）。

> 💡 `localhost` 本身就是 secure context，**本地跑一切正常、部署到 HTTP 环境才崩**——
> 本段的命令必须在**真实部署环境**验证过再登记。

## 八、写操作授权档位（★ 决定"缺数据时能不能自己造"）

> ⛔ **缺这一节的后果是确定的**：执行体只知道"能登录"、不知道"能改什么"，于是保守地什么都不动——
> 缺前置数据的用例一律标 `block(前置不满足)`，而其中很多只要造两条数据就能跑完。
> 下游实证：一轮 13 条 block 里有 7 条属于"有权限造却没去造"，实际造数后 5 条当场转 pass。

| 所属系统 | 只读 | 可逆写（须记原值、可还原） | ⛔ 不可逆写（禁止） |
|---------|:---:|--------------------------|-------------------|
| 被测主系统 | ✅ | `<如 建/改/删测试数据、上下架>` | `<如 删除全局共享的既有数据>` |
| 联动系统 1 | ✅ | `<...>` | `<如 新增用户（会真发短信）、重置密码>`（无则删除本行）|

- **授权来源**：`<谁 / 何时 / 口头或书面>`。⛔ **没有授权来源的行视同只读**，不得据此造数。
- **默认档位 = 只读（fail-closed）**：本表缺失、或某系统未登记 ⇒ 该系统按**只读**处理。
  ⛔ 不得把"表里没写"读成"没限制"——权限判断出错的代价不对称：少造数只是多一条 block，
  误做不可逆操作（真发短信 / 删了别人的数据）无法回滚。
- **造数留痕**：可逆写造出的数据须在用例 `note` 写明「本轮造数：<什么>」，便于事后清理与复现。
