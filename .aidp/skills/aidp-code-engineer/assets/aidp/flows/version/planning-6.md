#### Step 2.4.6：★ 关联文档交叉引用校验

四个子命令各自负责在生成的文档头部注入「关联文档」表（详见各子命令）。本命令在四者完成后做**整体校验**，确保不出现孤立文档。

> ★ **本交叉引用校验由独立子 Agent 执行（隔离上下文，不占主对话）**：本步要递归扫 `**/*.md` 跨 4 个目录做双向链接对账，会把大量产物文件读进上下文。**用 `Agent` 工具派一个 general-purpose 子 Agent**（需读+就地修复，不用 Explore），把**下方「路径约定」+「校验项」全文**作为 prompt 传入；子 Agent 自行读取产物文件逐项核验、就地修复可自动修复项（校验项 1~4 的补写/重写），**只回传紧凑结果**给主对话：① Pass/Fail 表（每项 ✅/❌）② 已修复项清单（file:line + 改动）③ 校验项 5/6 的 P0 告警（需人工裁决）。**主对话不读产物文件正文**，仅据回传结果决策。
> - 子 Agent 返回 P0 告警（base 变更但消费者未全联动 等）→ 按原规则**暂停命令**等用户裁决；
> - 子 Agent 失败（超时/异常/返回空）→ 命令端内联兜底跑同一清单（标注"⚠️ 子 Agent 失效兜底"），禁止静默放过。

**路径约定**（统一）：版本作用域内（`docs/{requirements,design,plans,prototype,testing,...}/{version}/...`）一律文件相对路径；全局锚点（`memory/`、`docs/architecture/`、根级 `code/` / `dev/` / `tests/` / `release/`）一律仓库根相对路径。

**校验项**（以下为传给子 Agent 的检查清单原文）：

1. **逐份扫描** 以下范围（用递归 glob `**/*.md` 涵盖拆分进子目录的补充文档，如 `08_补充-<业务主题>/00_索引.md`）：
   - `docs/requirements/{version}/研发需求/**/*.md`
   - `docs/design/detail/{version}/**/*.md`
   - `docs/plans/{version}/**/*.md`
   - `docs/testing/{version}/研发自测.md`、`docs/testing/{version}/研发自测/**/*.md`（★ **不含 `正式用例/`**：该目录是测试人员 territory，AIDP 只读、绝不写入/预建/补写——见 `docs/init/06 §2.4`、`docs/testing/README.md`、`planning-2.md`；且它不由任何子命令产出，要求它带「关联文档」表本身不可执行）（包含研发自动生成的环境配置 + 测试人员手动维护的用例方案 + 补充文件）
   - **排除**（命令端生成的元数据 / 摘要文件，不要求套用「关联文档」表）：
     - `docs/design/detail/{version}/*事实清单.md`
     - `docs/requirements/{version}/研发需求/输入变更-*.md`
     - `memory/{version}/.aidp-inputs-snapshot.json`（运行时元数据，非文档）
2. **检查每份文档头部是否存在「关联文档」章节**：
   - 缺失 → 按各子命令的模板直接补写
   - 存在但条目不全（如缺「⬅ 上游输入」/「➡ 下游引用」/「🔗 全局约束」中任一行）→ 补齐
   - 路径风格不符合「路径约定」（如本应文件相对路径但写成了 `docs/...` 绝对路径）→ 改写
3. **双向链接对账**（当前规范内容主文档为 `01_研发需求.md` / `01_详细设计.md`·`02_数据库设计.md`·`03_接口设计.md` / `01_研发执行计划.md`，历史裸名兼容识别）：
   - `01_研发需求.md`「➡ 下游引用」必须实指已生成的 `01_详细设计.md` / `02_数据库设计.md` / `03_接口设计.md` / `01_研发执行计划.md`
   - 详细设计系列「⬅ 上游输入」必须实指 `01_研发需求.md`
   - ★ **对外需求引用链（强制，缺失阻塞）**：子 Agent 先 `ls docs/references/{version}/`（递归）枚举本版本对外需求/对方资料文件；**该目录非空时**，`01_研发需求.md` 与详细设计（`01_详细设计.md` 或拆分分册）的「⬅ 上游输入」/「🔗 全局约束」**必须逐一实指**这些文件（提给第三方的需求是需求/设计的上游约束）。缺任一引用 = 引用链断裂，与研发需求↔详设引用密度铁律**同级阻塞**，回 `/sprint-bugfix` 或就地补引用。目录为空（本版本无第三方依赖）则跳过本项。
   - `01_研发执行计划.md`「⬅ 上游输入」必须实指 `01_研发需求.md` + 全部 `docs/design/detail/{version}/*.md`
   - **分册互链校验**：拆分时所有 `0N_*.md` 必须互相回链 + 回链 `00_索引.md`；`00_索引.md` 必须**逐行列全**所有 `0N_*.md`（不存在的不能列；存在的不能漏）
   - `plan-{user}.md`（多人协作时）「↔ 同版本平行」必须互相回链 + 回链总 `01_研发执行计划.md`
4. **路径有效性**：「关联文档」表内每一条路径分两类校验：
   - **可直接 `test -e` 验证**的（已生成的同版本文档、`docs/architecture/`、`memory/` 下已建文件）→ 命令端逐条验证
   - **Sprint 期才生成**的（`Sprint 期 code/ 实现`、`docs/testing/{version}/sprint-{NNN}/`）→ 必须**保留**且以括号注释标明"Sprint 期生成"，不视为缺失
5. **增量文档双向链接专项校验**（仅补充模式 B-2 执行）：
   - 本轮产出的每份 `NN_<业务主题>.md` → 目录 `00_索引.md`（类型=补充）**必须有一行指向它**；缺失则补
   - `00_索引.md` 索引表的每行 → 对应文件**必须实际存在**；不存在则告警人工裁决
   - 每份 `NN_<业务主题>.md` 头部「关联文档」必须回链 ① `00_索引.md` ② `输入变更-NN.md` ③ 同轮其他增量文档（如有）；缺任一项 → 补
   - 拆分进子目录的补充文档（如 `08_补充-<业务主题>/00_索引.md` + `0M_*.md`）也按上述规则要求子目录内分册互链
6. **事实清单消费者级联校验**（防 base 变更级联事故）：
   - 如 `docs/design/detail/{version}/*事实清单.md` 存在且「⚠️ 本次变更」表非空 → 必须验证「已联动消费者点」列**对每条变更都非空**（无需联动的应注明"无需联动 — 原因"）
   - 取「⚠️ 本次变更」表里**未声明已联动**的消费者点（按事实清单「路径消费者点」表的全集），与 `git diff --name-only HEAD~..HEAD`（首版 `/version` 则为 `git ls-files`）做交集——文件在消费者点表里但**不在本次改动中** → 标红写入「⚠️ 消费者级联告警」表
   - 反模式参考：base 变更后前端 URL 守卫漏改导致双前缀 404（详见事实清单「反模式提示」段）
   - **告警等级**：base 变更但消费者未全部联动 = P0 告警。**交互式** → 命令暂停，要求用户先补改再继续；**无人值守**（`--unattended` / `--no-tag` / `LOOP_UNATTENDED`）→ ⛔ **绝不停等**（无人可答，`/loop` tick 会空转到熔断）：WARN + 把未联动消费者点逐条经 `python3 {{AIDP_HOME}}/scripts/release_debt.py --version {version} --step 2.4.6 --level Critical --title "<消费者点> 未随 base 变更联动" --redo "<补改命令>"` 登记进 **`docs/audit/{version}/发布欠账.md`** + 在 Step 2.8 报告标注（⛔ **不要另起 `规划欠账.md`**：那份没有任何读者——`--finalize-docs` / `--rebuild-baseline` 的补跑入口只读 `发布欠账.md`，报告顶部的必打块也只渲染它，`check_release_debt_landing.py` 的扫描面更只覆盖 `release-*.md`。而本行恰好跑在**无人值守分支**上，等于把一条 P0 告警写进一个没人读的文件），然后**继续后续步骤**；本项不构成失败信号（真正的阻断由 Step 2.4.7 审计的 `audit-block` 承担）。

若发现缺失或路径无效（校验项 1~4），**子 Agent 就地修复**（追加/重写）后回传改动清单，不阻塞流程；校验项 5/6 的 P0 告警由子 Agent 标出并回传；主对话**交互式**据此暂停命令等待人工裁决，**无人值守**按上条降级（登记欠账 + 继续），不停等。修复日志由子 Agent 汇总后输出到本步末尾。
