## ★ 常用命令速查

> 💡 本节面向人给实操示例；Claude 自动路由自然语言到 sprint 命令的规则见项目记忆文件的「Sprint 命令清单 + 意图路由」段——⛔ **不在本文件里**（本文件是从那份抽出的实操示例面）。示例以 Claude Code / DeepSeek Harness 的 `/命令` 写法展示；Codex 使用同名 `$命令`，入口由 `agent_sync.py` 从 `.aidp/commands/` 生成。

### 阶段 A：版本规划（一次性）

```bash
/version V0.1.0 "M1 MVP"
# 内部串联：/sprint-requirements → 研发需求 ; /sprint-design → 详设/接口/数据库 + SQL + 架构文档 ; /sprint-plan → 研发执行计划 ; /sprint-selftest → 研发自测方案 + 自测用例 + 测试环境与账号
```

### 阶段 B：Sprint 执行（★ 三个常用入口）

```bash
# 场景 1：首次全量跑（跑完研发执行计划所有 Sprint + 末段 Step 6 询问部署 + AI 自动化测试）
/sprint-batch                         # 推荐入口；Step 6 调 /sprint-aiauto-test 端到端闭环（AI 测试恒全量，链内强制 --select all）
/sprint-batch 001-003                 # 只跑前 3 个
/sprint-batch skip-bugfix             # bug 留最后统一修
/sprint-batch --skip-aiauto-test      # 跳过 Step 6（纯开发模式）
/sprint-batch --auto-aiauto-test      # Step 6 不询问直接跑

# 场景 2：新增功能（自动累进 Sprint + 完整流程）
/sprint-dev "新增用户导出为 Excel 功能"   # 最推荐的新增入口
/sprint-dev "增加菜单缓存" backend        # 仅后端
/sprint-dev "xxx" skip-test              # 只开发不测试

# 场景 3：修复 bug
/sprint-bugfix                            # 修复已记录的零散 bug
/sprint-bugfix sprint-003                 # 按 Sprint 过滤
/sprint-bugfix "修复批量导入需新增接口"    # 较大 bug：自动累进 + 完整流程
```

### 阶段 C：7×24 全自动开发（开发链路 + 测试链路双进程）

```bash
# ★ 7×24 推荐：操作系统调度为两条链路各装一个定时任务（systemd --user / crontab / launchd / schtasks）
python3 .aidp/scripts/aidp_scheduler.py install [--agent claude|codex|dsh]   # 开发链路 10m + 测试链路 5m（scheduler 段可调）
python3 .aidp/scripts/aidp_scheduler.py status                               # 定时任务 + 两条链路心跳
python3 .aidp/scripts/aidp_scheduler.py uninstall
# 交互式短期用法（Claude Code 会话内；会话级、7 天过期、空闲才触发、同会话两条串行）
/loop 10m /sprint-autopilot --unattended   # 开发链路：监听 docs/requirements/ → PRD → /version → /sprint-batch + 里程碑通知
/loop 5m  /sprint-aiauto-test --unattended  # 测试链路：监听 baseline 新部署 → AI 实测 + 报告 + 里程碑通知
/sprint-autopilot                     # 首次直接调用 = 配置向导（不跑 Phase 2/3）
/sprint-autopilot --once|--no-loop|--skip-dev|--target V0.2.0|--skip-pre-release|--single-sprint|--reset-baseline   # --skip-dev = test-only 入口（子流程 R）；完整 flag 见命令文档
/sprint-aiauto-test --once|--select smoke|regression --role admin|--skip-login|--target V0.1.0|--reset-chrome-ip|--reset-credentials
```

> ⚠️ **前置**：①（可选）**里程碑通知渠道**（`memory/aidp-config.yaml` 的 `notify` 段 + 对应 webhook 环境变量，经 `notify.py --auto` 发送；未配置降级跳过不阻塞，约定 32）② **chrome-devtools-mcp**（随仓库以插件分发在 `.aidp/plugins/chrome-devtools-mcp/`，`agent_sync.py` 为 Claude Code 生成项目插件、为 Codex 生成 `.codex/skills` + MCP、为 DeepSeek Harness 生成 `.agents/skills` + `.dsh/mcp.json`；本机需 Node.js，Codex 需项目 trust；DSH init 会尝试安装 `dsh-plugin-commands@latest`）③ 每版 PRD 头部 `autopilot_decisions` YAML（视觉基准/缓存/Mock 位置/第三方未交付/测试策略/决策冲突 + **deployment** 段含 local/cloud 模式+启动命令+访问 URL+等待时长）④（部署走 CICD 时）**CICD 提供方**：`memory/aidp-config.yaml` 的 `cicd.provider`（默认 `github-actions`，另有 `gitlab-ci` / `jenkins` / `command` / `none`）与 `cicd.pipelines` 配好环境→流水线映射，提供方 CLI 已登录或令牌环境变量已设置（GitHub Actions 需 `gh` 已登录；`provider=none` 或未配置则只 push、不监听，约定 31.5）。
> ⚠️ **必须两条链路同时运行才是完整开发+测试闭环**（`aidp_scheduler.py install` 一次装齐两条）：只挂 `autopilot` 一条时浏览器实测永不自动开始——约 3 tick（`TEST_LOOP_MISSING_THRESHOLD`）后本 build 走静态-only finalize + `needs_human="测试链路未挂载"` 冻结（不挂死但闭环不完整）。7×24 标准姿势 = `aidp_scheduler.py install`。
> 🔍 **版本自动发现**：扫 `docs/requirements/` 的 `V*.*.*` 子目录按 SemVer 排状态（S0 仅 PRD / S1 进行中 / S2 待准发布 / S3 已准发布 / S4 已正式发布），**只跑最近一对**：S2 走 Phase 2 `/version --no-tag` 准发布 + S0/S1 走 Phase 3 全流程。
> 💡 **PRD 缺字段也能跑**：Phase 0.6 用 AskUserQuestion 一次性补全缺失字段写回 PRD，保证 Phase 2/3 不中途阻塞；`--strict-prd` 强制预填。Chrome 智能启动逻辑见 `/sprint-aiauto-test` 文档。
> 🔀 **双链路**：autopilot 只管开发链路（PRD 监听 + /version + /sprint-batch + 部署触发，不跑浏览器）；aiauto-test 管浏览器仿真测试。共享 `memory/.sprint-autopilot-baseline.json` 传版本状态。
> 🏷️ **准发布 vs 正式**：autopilot 跑 `/version --no-tag`（归档不打 tag）；运维 review/merge 后手动 `/version V0.X.X` 补 tag。tag 留给运维管控。
> 💡 **为何 7×24 用操作系统调度而不是 `/loop`**：`/loop` 是会话级定时任务——会话关闭即停、7 天后自动过期、只在会话空闲时触发，同一会话两条实际串行。操作系统调度让两条链路成为两个独立进程；每轮经 `agent_loop.sh --once` 自动补 `--unattended --no-loop`，任一链路心跳中断由 `aidp_scheduler.py watchdog` 写本地告警台账 `memory/.aidp/alerts.jsonl` 并发通知。非交互执行需预授权工具权限（Claude `permissions.allow` / Codex `codex exec --sandbox workspace-write` + 项目 trust / DSH 在 `scheduler.exec.dsh` 配置执行命令），详见 `.aidp/reference/agent-tools.md` 第三节。
> 🛡️ **无人值守判据稳健性 + 为何标准示例默认带 `--unattended`**：两命令的 `LOOP_UNATTENDED` 只由**本轮**的 3 个确定性信号派生（`/loop` 上下文探测 + `--no-loop` + `--unattended`）。⛔ **baseline 的 `autopilot.unattended_confirmed` 只写不读**——绝不用历史值把本轮自动升级成无人值守。于是不传 flag 时只剩 `/loop` 上下文探测这一个信号，若某些 runtime 唤起时 prompt 不含 `/loop` 字样就会误判为交互式、在全新项目上挂起等人，且**每个 tick 都会重犯**（没有“确认过一次就自动兜底”这回事）。故上方 7×24 标准示例**默认显式带 `--unattended`**（`/loop 10m /sprint-autopilot --unattended` / `/loop 5m /sprint-aiauto-test --unattended`），把该单点彻底消除；确需保留交互式判据（如挂 loop 期间仍想人工应答）才去掉该 flag。**★ headless 裸 `--once` 也须叠 `--unattended`**：`claude -p "/sprint-autopilot --once"` 不带 `--no-loop`/`--unattended` 时默认交互式，首个 `AskUserQuestion` 无人可答会挂起；headless 单次务必写全 `--once --unattended`（`agent_loop.sh` 已自动补齐 `--unattended --no-loop`）。
