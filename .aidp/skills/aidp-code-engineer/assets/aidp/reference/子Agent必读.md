# 子 Agent 必读 — 本项目固定上下文（每个开发类子 Agent 的第一动作 = 读本文件）

> ⚠️ **本文件是项目级"踩坑清单 + 固定约定"的单一信源**，由**开发期持续累积**（不是一次写完就不动的模板）。
>
> **给派发方（主 Agent）**：派发开发类子 Agent 时，prompt 里**只写本次任务特有的信息**
> （改哪个模块、验收标准、涉及哪几个文件），**不要**把下面这些项目级固定上下文再抄一遍——
> 只需在 prompt 首行写明：**「第一动作：`Read .aidp/reference/子Agent必读.md`」**。
>
> **给子 Agent（被派发方）**：**开工前先完整读完本文件**，再动手。本文件里的坑都是**实际踩过**的，
> 不是预防性猜测；忽略它们的典型代价是"改完发现验证方式根本跑不起来"或"重复踩同一个坑"。
>
> **为什么要有这份文件**（下游实测）：派发方担心子 Agent 不主动读项目文档，就把环境坑、技术栈约定、
> 本版特殊约定**每次手写进 prompt**，单次 prompt 达 **3000~5000 字**且高度重复。信息本身项目文档里都有，
> 重复的是"搬运"。把它固化成一份必读文件 + 强制第一动作，派发 prompt 可缩到本次任务特有的部分。

## 一、如何维护本文件（重要）

| 时机 | 谁写 | 写什么 |
| :- | :- | :- |
| `/sprint-init` | 脚手架 | 生成本骨架（各段留空或填已知项） |
| **开发中踩到坑** | 当轮主 Agent / 子 Agent | **当轮**就追加到对应段落——**别等"以后整理"**（那等于不写） |
| 环境/技术栈变更 | 变更执行者 | 就地更新对应条目，**删掉已失效的坑**（过期的坑会误导） |
| `/sprint-close` | 主 Agent | 扫一遍本轮新踩的坑是否已登记 |

**只登记"会让人白跑一趟"的事实**：环境缺件、非常规约定、反直觉的项目特例。
**不登记**：通用最佳实践、能从代码一眼看出的结构、项目记忆文件（AGENTS.md / CLAUDE.md）与各约定已写明的规则（那些指路即可，不复抄）。
