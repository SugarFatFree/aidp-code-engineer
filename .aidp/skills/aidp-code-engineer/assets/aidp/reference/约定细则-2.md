### 约定 22 — **★ 上游文档级联同步**
- **★ 高频漂移类型（均属实质变更、须级联；①② 见本条，③ 见下条）**：①「原型字段⟷接口字段」——代码按接口直透致列/字段与原型期望不一致，禁"代码改了文档没跟"，差异登记进研发需求「原型字段→处置」对照表（约定 4）+ 产品确认门；②「第三方 Mock→真实对接」（关联约定 26 阶段②/④）——切真实时**至少触发 L2**（详细设计/接口设计去 Mock 说明、改写真实端点/鉴权/字段映射/错误码/重试），契约变了（字段/结构/语义）**同触发 L1**（产品确认门），均下带 L3（桩任务转联调）/L4（用例转真实场景）。**详细设计最易被漏**（切真实常只改 baseURL 忘回写设计），本条专堵此口。
- **★ ③ 语义/口径/范围变更（无新增实体，页面零新增元素）**：同一实体的统计口径（"仅企业"→"企业+个人"）、单位（分→元）、默认值/开关语义反转、权限可见范围、状态机枚举语义、时间窗口（自然月→滚动 30 天）等发生变化，**代码改了数值/行为却不新增任何页面元素**——现有以"元素存在性"为核心的原型对齐/字段清单机制全部失效。此类变更**必然**有一批「派生展示物」需同步（说明提示 tooltip / 区块副标题 / 图例注释 / 空态文案 / 导出表头 / 报表标题 / 单位标注 / 筛选标签 / 告警提示等），**至少触发 L1**（研发需求「语义变更→派生展示物影响清单」表 E）→ 逐级下带 L2（详细设计「文案落点表」）/L3/L4（用例反向断言：旧语义字样出现即判 Critical 失败）。**严禁**用"页面版式/指标项全部不变""仅数值变化""UI 不变"等笼统表述覆盖说明性文案（对齐约定 4 内容层：说明性文案正确性 = 与当前实际行为一致，而非与原型/上一版一致）。派生清单机制单一信源 = `ux-logic-extractor` 表 E；回检 = `version-auditor` 审计 G。
- **统一入口**：`/sprint-dev` 末段 `Step X.0.0`，禁止绕过它直接调单一 SKILL 补单层（除非用户显式声明）
- **4 级触发**（最高一级触发 → 该级及以下全触发）——**★ 逐【变更条目】独立判定，⛔ 不按整轮取最大值**：

  一轮改动常同时含"真·口径变更"与"纯呈现层调整"。按整轮取最大值，会把后者一起拖进 L1~L4 全量级联：
  实测一次 15 行的区块重排（零业务规则、零契约变更）因为同轮有一条口径变更，被连带在详设里新开一节
  + 计划里加一个 Task + 用例里加一条 TC。**故触发级别按条目算**：口径变更那条走 L4，形态调整那几条
  各自按「仅设计层」甚至 L1，在增量文件的对应节下追加一行即可（⛔ 「追加一行」指追加到
  各族**内容主文档正文**（就地改 + 刷 `00_索引.md` 生成时间，⛔ 不新建分册）。

  > **怎么分条**：以「影响清单」的每一行为一个条目（它本就是逐条列的），台账条目也一一对应。
  > **怎么合并**：收口时同一目标文档的多个条目**合并为一次调用**——分条判级不等于分次级联，
  > 别把省下的级联量又变成多次往返。

  > ⛔ **别用它当降级借口**：拿不准某条是"口径变更"还是"形态调整"时**按高的算**。
  > 判据是**契约面有没有变**（对外行为 / 取值域 / 计数 / 状态机 / 权限范围），不是改动行数多少。

- **★ 落盘形态二分（开发期回填 vs 产品侧变更）+ 决策门 + 铁律**：**开发期级联**（攒批收口 / `--cascade-now`）四级一律传 `--ledger-cascade`，**直接就地改各族内容主文档正文** + 刷该目录 `00_索引.md` 生成时间；⛔ 不新建分册、不占 `NN_` 序号，**⛔ 不产任何中转增量册**（落盘规则 + **增量式读代码**详见 `.aidp/reference/开发期族增量.md`「收口执行要点」第 2/3 条）；**产品侧 PRD/原型变更与 `/sprint-dev` 口述累进**仍走 `--supplement={NN}`：4 级共用逻辑 NN、命名按约定 15（无"补充"字眼、身份记入 `00_索引.md`）；X.0.0 **默认直接自动级联、不弹 `AskUserQuestion`**（唯一确认门 = 破坏性变更二选一；单一信源 `postdev-writeback-1.md`）；**铁律**：上级触发则下级必自动触发（不可只补需求不补设计），任一级 SKILL 失败暂停链路提示接管、不静默继续。
- **★ 发布期收敛（`/version` Step 3.3.10，单一信源）**：本步只处理 `NN_<业务主题>.md` 一种增量形态（append-only；开发期约定 22 级联的内容在收口时已直接写进主文档、不经本步）；发布时把 4 类版本规划文档 + `docs/references/{version}` **共 5 个目标**收敛成只反映本版本实际交付的干净版本——① `NN_` 增量合并回 `01_` 主文档（应用结论取代、失效增量丢弃）+ **文件级**删除已合并增量（全部项并入才 `git rm`）+ 刷新 `00_索引.md`；② 清除废弃/延期需求（跨 5 目标联动删设计/接口/表/Task/用例/对外需求产物避免孤儿断链，死配置项走确认制），但**保留**约定 4 字段裁剪留痕、本期仍走 Mock 的待交付接口、被取代后已实现项、「范围外」scope 声明段。
- **Why**："代码已改、文档未跟"是最高频漂移源，4 文档失同步会让下个 Sprint 读到错误基线层层放大。

### 约定 24 — **★ 提交前门禁 `commit_gate.py`**
- **调用**：每次 `git commit` 前跑 `python3 .aidp/scripts/commit_gate.py --quiet`，读其 JSON 输出。总开关 = `memory/aidp-config.yaml` 的 `commit_gate.enabled`（缺省开启，仅显式 `false` 关闭）。
- **CLI**：`python3 .aidp/scripts/commit_gate.py [--quiet] [--context <ctx>] [--cascade-now] [--no-fail-on-debt]`。
- **输出字段（判定内幕以脚本输出为准）**：`pending_cascade` / `should_dispatch_cascade`（约定 22 台账积压）· `suspected_cascade_bypass`（裸对话绕过增量册）· `offchain`（约定 41 链外规模档位与动作预算）· `pending_cicd`（CICD 推送欠账，约定 31.5）· `has_business_code_change` · `is_scaffold_only_change` · `is_template_project` · `working_tree_dirty` · `today`。
- **退出码**：`0` = 无欠账；`3` = 有未落地义务（约定 22 台账积压 / CICD 推送欠账，其中之一）；`4` = 阻塞级（保留档位：当前判据集不产生该值，消费方仍须按阻塞处理）。**3/4 表示"本轮结束前有义务未落地"，不是"禁止 commit"**——照常 commit+push，之后按成因补做：
  - 台账积压（`should_dispatch_cascade=true`）→ 派台账收口子 Agent（后台优先，约定 36 先试后降）；
  - `suspected_cascade_bypass=true` → 补记增量册，或确属当场级联则显式 `--cascade-now`；
  - `pending_cicd` 非空 → 对欠账 commit 补跑 `cicd_watch.py` 监听，结束后 `classify_push.py --record-terminal` 记部署终态（约定 31.5）。
  欠账告警恒打印 stderr，`--quiet` 不压制。
- **★ 作用域 = 变更事实，与命令入口无关**：用户全程自然语言提需求、执行体改代码后直接 commit+push 的**裸对话路径同样必跑**（约定 36 已显式覆盖），⛔ 不得以"本轮没走 `/sprint-*`"为由跳过。
- **失败兜底**：门禁在 commit 前运行、不回滚已推送代码；脚本自身报错须终端告警、不静默吞错。
- **Why**：级联台账与 CICD 监听都是"事后义务"，没有一个每次必经的检查点就会静默积压；commit 前是唯一必经点。

### 约定 30 — **★ 命令 / Agent / 文档正文只陈述「最终行为」；版本号与变更历史收口归档**
- **★ 范式版本号只在 AIDP 模板仓库维护**：落点 = 模板仓库 `版本变更历史.md`「当前范式版本」（唯一权威源）→ 脚手架 `assets/SCAFFOLD_VERSION` 与 `assets/CONTRACT_MANIFEST.json` 的 `scaffold_version`（均由 `mirror_to_bundle.py` 派生，⛔ 禁手改）；提升版本只跑 `bump_version.py`（内部已调 `mirror_to_bundle.py`），然后跑 `verify.py . --template --read-only`（三处不一致即 ERROR）。下游项目只读脚手架版本戳 `memory/aidp-config.yaml` 的 `scaffold.version`。其它任何文件正文/头/尾都不带范式版本号。
- **禁止（A 类变更叙述，删）**：`XX 重大变更/修订/整合背景` 标题；`取消原…改为…`/`原来…现在…`/`由 X 改为 Y`/`废除旧版…`；`原名 /xxx 更名为…`/`取代原…`；`不再…`（仅当解释新旧对比时）；**B 类版本溯源戳**（`（Vx.y.z）`/`Vx.y.z 起`/`AIDP Vx.y 范式`/`最后更新：日期` 头尾戳）——一并删，溯源去 git / `版本变更历史.md`
- **允许保留**：C 类运行时回退/降级语义（"配置缺失回退交互式收集"等当前行为）；参数表废弃标记（`--old-flag ❌ 已移除 用 X 替代`，只写改用什么）；**功能性版本**（演示项目自身版本 `V0.0.1`、SemVer 排序示例 `V0.1.0 < V0.2.0`、占位符 `{version}`/`V*.*.*`）——不是范式版本戳，留  <!-- flag-check: ignore -->
- **判定速记**：句子删掉后执行者仍知道现在做什么 → A 类噪音 / 版本戳删；是当前规则/回退语义 → 留；是范式版本号或"何时引入"溯源 → 删（去 `版本变更历史.md`）
- **写新内容**：直接写最终行为；**不挂任何版本戳**；需记录改动往 `版本变更历史.md` 追加（一条通俗摘要，只记最终交付功能；**每条 ≤50 字、最多不超过 100 字**，改动多/超长时只留最核心一句、细节归 git commit）
- **范围 + 强制**：`commands` + `agents` + **`flows` + `reference` + `rules`** + `docs/init` + 根级文件（项目记忆文件 `AGENTS.md`（Claude Code 下为 `CLAUDE.md`）/ `README.md`）。**★ 契约正文的大头在 flows / reference / rules 三处，它们同受本条约束**；唯一例外 = `rationale.md`（承载「为什么这么定」的根因文件）与根级 `版本变更历史.md`。SKILL 同理（约定 16：`.aidp/skills/` 下全部 SKILL 由本仓库维护）。存量戳改到哪清到哪。**回检 = `check_convention30_prose.py`（由 `verify.py` 委派；历史叙事与范式版本戳新增即红、存量走 baseline 水位）+ 模板仓库 `verify.py --template` 的三处版本一致性（ERROR）**——⛔ 不是 `version-auditor`：它的 A–H 八项没有任何一项涉及版本戳，挂在它名下等于这条回检没有执行方。
