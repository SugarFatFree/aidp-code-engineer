## 〇、先对齐编号(不对齐必然引错)

本维度落地的是上下游共用的**通用规则集(AIDP 约定 39)**,规则号形如 `R1~R13`。

> ⚠️ **引用一律写全称 `约定39-RNN`,严禁写裸 `RNN`。**

> 实际查错了对象"。

**这批规则从哪来(决定了它值不值得做成维度):** 某实际项目(Vue3 + Spring Boot)
两个月内 5 个提测批次产生 **71 条已关闭缺陷**,逐条人工归因后提取出**与业务领域
完全无关**的 30 条 → 归纳为 13 条通用规则。两个决定方向的统计:

- **① 发现深度:96%(68/71)属「正常发现」** —— 走一遍正常流程就会碰到,不需要刁钻构造,却**全部漏到

  → 所以本文件把判据拆成**可逐条判定的规则**,不留"未按设计实现"这种筐。

## 一、维度 10:UI 还原度确定性检查(委派外部脚本 · 约定39-R2/R3/R10)

### 1.1 ⛔ 最高约束:本 SKILL 不得再写一份同判据实现

判据脚本 **`<被测项目根>/.aidp/scripts/check_ui_fidelity.py` 由 AIDP 脚手架下发到每个下游项目**,不在本 SKILL 的
`scripts/` 下、**也不许拷进来**。

> **Why(这不是洁癖,是最高频漂移源):** 同一判据两份实现 = 改一处漏一处、两处都自称权威。
> 一旦本 SKILL 自带一份「R3 截断无 tooltip」的正则,它与下游脚手架那份就会在第一次规则微调时分叉,
> 之后**两边给出的结论互相矛盾**,而使用者无从判断该信谁。
>
> 对照本 SKILL 已有的同类结构判据(维度 8「请求通道 URL 拼装单一信源」):**判据有几份实现**本身就是
> 缺陷。我们不能一边判别人「同一判据散落多份」,一边自己复制一份。

### 1.2 调用方式与退出码

```bash
# 全量(推荐)
python3 <被测项目根>/.aidp/scripts/check_ui_fidelity.py --json
# 单条规则
python3 <被测项目根>/.aidp/scripts/check_ui_fidelity.py --check R3 --json
```

- 退出码:`0` = 无 Critical / `1` = 有 Critical / `2` = 用法错误。
- 输出 `findings[]`,每条含 `rule` / `severity` / `file` / `line` / `message` / `evidence`。
- ⚠️ `--check` 后跟的是**脚本自己的规则号**(`R3`),那是脚本的命名空间;写进验收报告时仍按本文件
  第〇节的约定标注为 `约定39-R3`。

### 1.3 三条规则

| 规则 | 判据 | severity | 可豁免 |
| :-: | :- | :-: | :-: |
| **约定39-R3** | 文本截断(`text-overflow:ellipsis` / `-webkit-line-clamp` / `truncate`)而**同节点或父节点无 `title`/tooltip** | 🟡 Important | ✅ |
| **约定39-R10** | **导出方法体内透传分页参数**(`pageNo` / `pageSize` / `PageHelper` / `Pageable` / `limit`)——即"导出只导当前页" | 🔴 **Critical** | ⛔ **不设豁免** |
| **约定39-R2** | 状态标签**内容随数据变化**,而 `type` / `color` 是**字面量常量**——即状态变了颜色不变 | 🟡 Important | ✅ |

**为什么 R10 不设豁免:** 「导出只导当前页」**没有正当场景**。用户点"导出"的语义就是导出结果集,
不是导出他此刻正看着的那 20 行;真需要"只导当前页"必须是显式的另一个按钮。故这一条一旦命中即 Critical,
不接受 `fidelity-ignore`。

**R2/R3 为什么可豁免:** 存在正当例外——刻意的纯文本降级、装饰性文案、设计上就不该有 tooltip 的场景、
状态标签本就只有一种状态。机器侧已支持在代码里就近写 `fidelity-ignore: <规则号> <原因>` 声明豁免。
⚠️ **豁免必须带原因**;只写规则号不写原因的豁免,验收 Agent 应报为 Important 让其补齐——否则
`fidelity-ignore` 会退化成"一键关掉这条规则"。

### 1.4 脚本不存在时怎么办(判据固定,勿自行发挥)

| 情形 | 处置 |
| :- | :- |
| 脚本存在、退出码 0 | 维度 10 通过 |
| 脚本存在、退出码 1 | 按 `findings[].severity` 分档:有 Critical → 维度 10 不通过、回 Agent1 修;仅 Important → 报告列出、不阻断 |
| 脚本存在、退出码 2 | **入参/环境错,不是维度违规**:修正参数后重跑,**不得记为不通过**(与本仓库全仓退出码约定一致) |
| **脚本不存在** | 维度 10 标 **「不适用(未随脚手架下发 `check_ui_fidelity.py`)」跳过,不硬失败**;⚠️ **须先记录已解析的绝对路径与 `ls` 结果作为证据**——仅凭一次相对路径调用失败**不得**判定为未下发(验收 Agent 常带着代码目录参数被调起,cwd 未必是被测项目根,一次相对路径失败就让整档 Critical 维度以「不适用」消失,与本 SKILL 在维度 8/9 反复强调的「`skipped` 不等于通过」是同一条纪律)。**并须对 约定39-R10 做一次人工 grep 兜底**(导出方法体内 `pageNo`/`pageSize`/`PageHelper`/`Pageable`/`limit`)——R10 零豁免且判据纯词法、人工完全可判;**人工静态阅读不构成「第二份实现」**,⛔ 禁的是再写一个脚本。R2/R3 留待脚本下发后补 |

> ⚠️ **本维度的跳过是「技术栈门控」式的——标 N/A、报告里留行**,与维度 9(WebMCP)那种
> 「入参门控、连行都不留」**不是一回事**。留行是必要的:它告诉阅读者"这一档没跑过",
> 否则报告全绿会被读成"这三条规则查过且通过了",那正是假绿。

## 二、维度 11:失效实体与边界(语义核对 · 约定39-R5~R9 + R12)

这六条**机器检不了**(判据依赖业务语义:什么算"失效"、哪个数字和哪个数字该同源),须由验收 Agent
**静态读代码**核对。下表每条都给了「静态可查的信号」——本 SKILL 全程静态,**不起服务、不开浏览器**,
所以判据必须落到 grep 得到、读得出的东西上。

### 约定39-R5 失效实体的操作入口必须拦截 🔴

- **判据:** 已下架 / 已删除 / 已过期 / 已失效实体的**详情、跳转、购买、开通**入口必须**隐藏或禁用**,
  不得「按钮还在、点了报错或跳到空页」。
- **静态查法:** 找列表/卡片渲染处对 `status` / `state` / `isDeleted` / `expireTime` 的判断——
  行内是否有 `v-if` / `disabled` / 条件渲染把入口收掉;只在**点击后**的处理函数里报错 = 不通过。
- **反例(下游真实缺陷):** 已下架的商品,列表仍可点详情并**跳转成功**。

### 约定39-R6 被引用实体已删除时降级为可读展示 🔴

- **判据:** 引用方**不得裸露编码 / ID / 空值**,须保留快照名或显式展示「已删除的 XX」。
- **静态查法:** 找跨系统/跨表引用的展示位——取名字的地方是否有 `?? code` / `|| id` / `|| '-'`
  这类回退;数据模型里有没有存快照名字段(`xxxNameSnapshot`)。回退到 code/id 即不通过。
- **反例:** 订单中心已下架的商品,订单列表展示**商品编码**而非原有名称。

### 约定39-R7 加载未完成不得渲染「看起来是真的」的脏数据 🔴

- **判据:** 异步数据到达前**不得用旧值 / 缓存值 / 默认值**渲染出与最终结果不一致的内容,
  应用骨架屏 / 空态 / 隐藏。
  > **口诀:未取到配置先隐藏——少显示一个按钮无伤,闪出一个点了就死的按钮才是要消灭的现象。**
- **静态查法:** 看列表/开关类数据的**初始值**:`ref([...默认项])` / `data(){return {list: 预置数组}}`
  这类"先给一份假的"即高危;再看渲染处有没有 `v-if="!loading"` / `v-if="loaded"` 守卫。
  初始值非空 **且** 渲染无加载守卫 = 不通过。
- **反例:** 套餐选择页**加载中展示 14 个选项,加载完只剩 3 个**。

### 约定39-R8 编辑成功后当前视图必须自动同步 🔴

- **判据:** 不得要求用户**切页 / 刷新浏览器**才能看到变更。
- **静态查法:** 找保存/编辑成功回调(`then` / `await` 之后、`ElMessage.success` 附近),
  是否调用了列表刷新 / store 更新 / 局部数据回写。只弹成功提示、无任何刷新动作 = 不通过。
  ⚠️ 注意**跨组件**场景:详情页改了、列表页没刷新,是同一条的高频形态。
- **反例:** 部门名称编辑后页面不同步。

### 约定39-R9 存量数据兼容性 🔴

- **判据:** 改数据结构 / 加必填字段 / 收窄取值范围时,须**显式验证改动前产生的存量数据**在新代码
  路径下的表现。
- **静态查法:** 对照本轮 DDL 变更与代码:新增必填字段有没有 `DEFAULT` / 迁移脚本 / 读取侧空值兜底;
  收窄枚举取值时,老值走到 `switch` 的哪个分支(有没有 `default` 落到抛异常)。
  只加了字段、没有任何存量处理 = 不通过。
- **反例:** 对「旧数据」点击编辑**直接报错**。

### 约定39-R12 同一指标跨页面必须同源 🔴

- **判据:** 同一业务指标在多页面出现,必须**来自同一取数口径**,禁止各页面各算一遍。
  > **口诀:判据全站唯一化,不在 N 处各写一遍。**
- **静态查法(与维度 8 同一形态,查的是「判据有几份实现」):** 拿一个指标名,grep 它的计算/取数点——
  落在 **≥2 个文件各自算一遍**即高危;再核对每处调的是不是同一个接口/同一段聚合。
- **上游契约(有则强制消费):** `dev-logic-architect` 详细设计的「**统计指标口径表**」第 8 列
  「权威取数口径」就是本条的基准表——逐个指标核对**实现取数点是否等于表里声明的权威口径**。
  上游没产出该表时回退为纯 grep 结构判断,并把"设计缺口径表"作为 Important 报出去。
- **反例:** 总览页订单量 / 订单管理页订单量 / 销售报表页订单量三者**互不一致**。

### 2.1 维度 11 的通过判据

| # | 判据 | severity |
| :-: | :- | :-: |
| 1 | 本轮涉及的失效态实体(下架/删除/过期/失效),其详情·跳转·购买·开通入口逐个核过隐藏或禁用 | 🔴 Critical |
| 2 | 跨系统/跨表引用的展示位,已删除时不裸露 code/ID/空值 | 🔴 Critical |
| 3 | 异步渲染处无「先给一份假的再纠正」的初始值 + 无守卫组合 | 🔴 Critical |
| 4 | 编辑/删除成功后当前视图有明确的刷新或回写动作(含跨组件场景) | 🔴 Critical |
| 5 | 本轮结构变更配有存量数据处置(默认值 / 迁移 / 读取侧兜底),或书面说明本轮无结构变更 | 🔴 Critical |
| 6 | 同一指标的取数点未散落多处;有上游「统计指标口径表」时逐指标核对权威口径 | 🔴 Critical |
| 7 | 上游未产出「统计指标口径表」时,已将该缺口报为 Important(不静默放过) | 🟡 Important |

**不适用时怎么标:** 某条在本轮**确实无对应场景**(如本轮无任何删除/下架语义实体)时,标
**「不适用 + 一句话理由」**,不得直接省略——省略与"查过且通过"在报告里长得一模一样。

## 三、与其它维度的边界(不重复登记)

- **维度 1「功能完整性」** 管"该有的东西在不在"(按钮/列/操作存不存在);**本文件两维度管"在了之后
  行为对不对"**(截断有没有 tooltip、失效了拦不拦、编辑完刷不刷新)。同一处问题按缺失记维度 1、
  按行为错记维度 10/11,不重复登记。
- **维度 4「视觉还原两支柱 + 字段/列对账」** 管展示列集合与样式一致性;**约定39-R2** 管状态标签的
  颜色是否随数据变——是行为不是集合,记维度 10。
- **维度 3.7「出参字段变更消费点穷举」** 与 **约定39-R12** 形态同源(都查"多处消费同一份数据"),
  但对象不同:3.7 查**字段结构变更后漏改的消费点**,R12 查**同一指标被各算一遍**。同一处问题只登记一次。
- **维度 5「技术债与风险」** 只收非阻断技术债;本文件两维度命中的都是行为缺陷,**不降级到维度 5**。
