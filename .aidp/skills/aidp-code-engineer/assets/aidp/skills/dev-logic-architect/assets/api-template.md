**填表铁律（违反任一 → 维度 31 不通过）:**

1. **五列齐全**，缺一列即不合规；旧版「错误码 | HTTP Status | 说明」三列表已作废。
2. **错误码全局统一**——每个码必须能在 A.4「GlobalErrorCode 全局错误码」枚举里逐条对应上，
   且「错误码」「HTTP Status」与枚举**逐字一致**；本表只写本接口的触发条件 / 用户提示 / 失败降级行为，
   **不得**改码值与语义、**不得**就地新造。
3. **面向用户的中文提示逐行填实**——必须是中文、面向最终用户、有指导意义；
   **严禁**出现内部代号 / 服务名 / IP / URL（❌ `order-svc 连接失败` → ✅ `订单中心服务无法连接，请稍后再试`）。
4. **失败/降级行为逐行填实**——默认「不降级、快速失败」；
   **确需降级**（如字典类回退默认值）必须就地写明**降级理由 + 降级范围 + 用户是否可感知**
   （例：`降级：置 partial=true，缺失字段返 null，理由=主列表可用性优先，范围=仅扩展列`）。
5. **安全判据默认 fail-closed**——鉴权 / 权限 / 数据归属 / 签名校验，凡「取不到 / 解析失败 / 查询异常」
   一律拒绝或报错，**严禁** fail-open（把"取不到"当"无限制"放行）。
6. 上游不可达行**必须有**（本接口调上游时），文案格式固定为「{上游中文名}服务无法连接，请稍后再试」。
