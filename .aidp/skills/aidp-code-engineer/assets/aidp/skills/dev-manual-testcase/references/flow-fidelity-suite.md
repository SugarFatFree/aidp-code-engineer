## 一、Why:为什么这批用例可以"不读业务语义"就生成

某实际项目(Vue3 + Spring Boot)两个月内、5 个提测批次产生 **71 条已关闭
缺陷**,逐条人工归因后提取出**与业务领域完全无关**的 30 条。两个决定方向的统计:

- **① 发现深度:96%(68/71)属「正常发现」** —— 走一遍正常流程就会碰到,不需要刁钻构造,却**全部漏到
  QA 侧**(`findMethod` = 用例执行 65/71)。**问题不是测得不够狠,是测得太晚。**
- **② 二级归因失效:69%(49/71)被打成「未按设计实现」** —— 这个标签同时装着「口径没对齐 / 原型没照做 /
  设计本身就没写」三种东西,按它统计得到的结论永远是「下次按设计实现」,**零可执行性**。

**推论(本套件的立论):** 既然这 30 条与业务领域无关、且走正常流程就会碰到,那它们**能被固定模板用例
覆盖**——生成过程**不需要理解这个页面在做什么业务**,只需要知道"这是一个列表页 / 详情页 / 表单页 /
含数字的页"。这是本套件与其余用例族的根本区别:**其余族靠读懂需求,本族靠页面类型**。

**这批用例拦的是什么(下游真实缺陷,逐条可对上模板项):** 少了「已购商品数」列 · 详情缺提交人 ·
没有导出按钮 · 少一个排序按钮 · 汇总卡片四个与功规不符 · 保存配置缺二次确认 · 员工姓名过长展示不全 ·
积分分配导出只导当前页 · 部门名称编辑后页面不同步 · 按量计费开通页加载中展示 14 个商品加载完只剩 3 个 ·
已下架产品仍可点详情 · 已删除商品展示编码而非名称。

`auto-test-runner` 跨端识别。

> **★写法固定:守恒/核对类步骤的动作动词用「核对」或「观察」,⛔ 别写「查看」。**
>
> 本族十条里大半是"看页面上有没有、对不对"的核对动作,最自然的写法「查看」**不在
> `check_testcase_format.py` 的动作动词白名单里**(实测报 Important `invalid_action_verb`),

## 四、强制产出:「通用还原度覆盖表」(硬门据此判定)

放在**用例总览文档**(多文件模式 `02_自测用例-总览.md` / 单文件模式 `02_全量自测用例.md`)里,
固定 4 列,**一个页面一行**:

```markdown
## 通用还原度覆盖表

| 页面 | 页面类型 | 还原度用例数 | 用例编号 |
| :- | :- | :-: | :- |
| 用户与组织列表 | 列表页 | 10 | TC-UO-F01~F10 |
| 员工详情 | 详情页 | 4 | TC-UO-F11, TC-UO-F12, TC-UO-F13, TC-UO-F14 |
| 新增部门表单 | 表单页 | 2 | TC-UO-F15, TC-UO-F16 |
| 用量概览 | 含数字的页 | 6 | TC-BILL-F01~F06 |
```

> ⛔ **落盘时不要连 ```` ```markdown ```` 围栏一起复制**——围栏内的表会被硬门的
> `strip_code_fences` 跳过,覆盖表等于没写,直接吃一条 F1 Critical。

- **页面类型**取值**只有四个**:`列表页` / `详情页` / `表单页` / `含数字的页`。
  一个页面同时属多类时**拆成多行**(如"用量概览列表"既是列表页又是含数字的页 → 两行),
  **不要在一格里塞两个类型**——硬门按行判基线,塞一格会让基线判错。
- **用例编号**支持逗号/顿号/空格分隔的列表,或 `TC-XX-F01~F10` 这类**同前缀连号区间**。
- 表里声明的每个编号,文档里**必须真有一条同编号且标 `[还原度]` 的用例**(硬门逐个回查,防空头支票)。
- 某页面某模板项**确实不适用**时(如该列表页产品明确不提供导出),**表里数字照实填**,并在对应用例位置
  就地按以下正式记账规则处理;**⛔ 不得为了凑数写一条假用例**。

### 模板项不适用的正式记账规则

- 该用例**照常生成并占用编号**,保持编号连续,让列表页 F3 的 10 条结构基线不因不适用项被误判为缺条。
- 执行结果记 **`na`**,不是 `pass`、`skip` 或 `block`。`na` 表示本场景不存在该能力、以后也不测;`skip` 表示本轮跳过但未来仍应测,`block` 表示前置/环境未就绪、补齐后可测,三者不能混用。
- 用例标题后缀统一为 **`（不适用：<一句话理由>）`**;理由必须非空,并能追溯到需求/设计/裁剪决策(例如 `（不适用：产品未要求本页导出，Q-102）` 或 `（不适用：隐私收敛待授权口径确认，详见设计 D-204）`)。
- `na` **不计入通过率分子与分母**;报告必须单列「不适用 N 条」,与 Pass/Fail/Block/Skip 分开统计。状态闭环必须满足 `pass + fail + block + skip + na == total`。
- **⛔ 严禁把不适用记为 `pass`**——那会把“本场景没有该能力”读成“该能力已验证通过”。**⛔ 不要记为 `skip`**——那会把永久不适用错误地列为待执行遗漏。

> 「本页不该有导出」本身若是需要长期守护的业务事实,应在模板项 `na` 之外另立独立的反向用例(例如 `TC-X-0NN: 本版不提供导出（Q-102）`),归入反向断言族并实际断言「不存在导出入口」。`na` 负责还原度模板项记账,反向用例负责防止未来误加能力,两者不可互相替代。

**为什么只有列表页 ≥10 是 Critical:** 「任一列表页至少 10 条」是上游给出的**明确验收基线**;
详情页 4 / 表单页 2 / 含数字页 6 是**按模板条目数派生**的,派生基线当硬门容易在模板微调时变成假红,
故只作 Important 提示。

**门控:** 本维度**无门控入参**——它对任何有 UI 页面的项目都适用。文档里显式写明
「本轮无 UI 页面用例」时整维度跳过(硬门同款判定),**跳过须写明原因、不得静默**。

> ⚠️ **本族失败不锁 Critical(与 `[PRD存在性]`/`[回归]`/`[文案一致性]` 三族刻意不同)。**
> 下游 `auto-test-runner` 的 `CRITICAL_FAMILY_MARKERS` **刻意不含 `[还原度]`**:本族十条里既有
> 「导出只导当前页」这种确定的 Critical,也有「截断没 tooltip」这种 Important,整族锁 Critical 会把
> 后者拔高成阻断项。**执行结果按每条用例自身的 severity 判**,别"顺手"把它加进那个常量。
