# 第三方系统对接测试规则(含 SUITE-PAY 示例)

> 本文件是 `SKILL.md` 的第三方对接分片,按需 Read。

## 第三方系统对接测试规则

**当 PRD 中涉及第三方系统对接时,必须生成对应的测试用例和跨系统验证清单:**

### 用例生成规则

| 对接方向 | 必须生成的用例类型 | 说明 |
|---------|-----------------|------|
| 我方调用第三方 | 正向调用成功用例 + 第三方异常降级用例 | 验证调用成功时的 UI 反馈 + 第三方不可用时的降级表现 |
| 第三方调用我方 | 回调/通知接收成功用例 | 验证第三方触发后本系统的 UI 变化(如状态更新、消息通知) |
| 双向调用 | 以上两类均需覆盖 | — |

### 预期现象描述规则

- **我方调用第三方成功**:描述本系统 UI 的变化(如"页面提示'短信已发送'"、"跳转到支付成功页")
- **第三方系统的预期现象**:明确说明"在 {第三方系统名} 中应出现 {具体现象}"(如"手机收到验证码短信"、"企业微信收到审批通知卡片")
- **第三方不可用时**:描述本系统的降级 UI 表现(如"页面提示'服务暂不可用,请稍后重试'"、"按钮恢复可点击状态")
- **严禁描述第三方系统的内部处理逻辑** — 仅描述用户可观察到的外部现象

### 跨系统验证清单(全量"四、" / 增量"五、")

全量模式和增量模式均必须有"跨系统验证清单"章节汇总所有涉及第三方系统的用例(**全量模式编号为"四、";增量模式因"一、"被本次迭代变更清单占用,该章节顺延为"五、"**),按以下结构组织(增量模式若用例少可用扁平表替代 4.1~4.4 子结构):
- 4.1 对接总览(系统名、场景、方向、关联用例)
- 4.2 我方触发 → 第三方响应(我方操作、预期第三方现象、验证方式)
- 4.3 第三方触发 → 我方响应(第三方操作、预期我方现象、验证方式)
- 4.4 第三方不可用时的降级验证(模拟场景、预期降级表现、验证方式)

**不涉及第三方对接的项目,该章节标注"本系统不涉及第三方系统对接,跳过本章"。**

### 第三方接口未交付时的用例处理

**当详细设计 Module E 登记了"⏳ 待第三方交付"或代码中存在 `THIRD_PARTY_MOCK` 标注时，涉及该接口的用例必须按以下规则处理：**

#### 1. Mock 全生命周期测试场景覆盖（Critical）

**第三方接口 Mock 全生命周期包含 4 个阶段，每个阶段必须有对应的测试场景：**

| 阶段 | 场景名称 | 测试目的 | 必须验证的点 | 用例标识 |
|------|---------|---------|-------------|---------|
| **阶段 1** | **开发期用 Mock** | 验证前端 UI 联调可行性 | Mock 数据能正常展示、页面跳转正常、状态流转正常 | `[待第三方交付-开发期Mock]` |
| **阶段 2** | **开发期用真实接口** | 验证真实接口对接前的切换机制 | 关闭 Mock 开关后，前端能正常调用后端"占位接口"（返回固定格式但无真实业务逻辑） | `[待第三方交付-切换测试]` |
| **阶段 3** | **部署后用 Mock（UAT/Demo 环境）** | 验证 Mock 是运行时可控的，部署后仍可启用 | 打包后部署到 UAT/Demo 环境，修改环境变量启用 Mock，页面功能正常展示 | `[待第三方交付-部署Mock]` |
| **阶段 4** | **真实对接后清理验证** | 验证 Mock 彻底清理，真实接口正常工作 | Mock 代码/fixture/开关已删除，扫描脚本无残留，真实接口联调通过 | `[真实接口已交付-清理验证]` |

#### 2. 用例标题前缀与分类

- **阶段 1~3（开发期/部署期 Mock）**: 用例标题加前缀 `[待第三方交付-XXX]`，**不计入正式回归覆盖率**，跳过冒烟测试和上线前验收
- **阶段 4（真实对接后清理）**: 用例标题改为 `[真实接口已交付-清理验证]`，**必须在真实接口可用后执行并通过**，通过后前 3 个阶段用例归档

#### 3. 前置条件标注

用例的"前置条件"章节必须明确标注：
```markdown
前置条件：
- 第三方接口交付状态：⏳ 未交付（预计 YYYY-MM-DD）
- 当前使用 THIRD_PARTY_MOCK 占位（参考 详细设计 Module E > D-NNN）
- Mock 实现位置：前端拦截器（运行时可控，环境变量 `VITE_THIRD_PARTY_MOCK_ENABLED`）
- Mock 实现方式：✅ 运行时环境变量开关（非构建期守卫）
- 真实接口可用后，需重新执行阶段 4 清理验证用例
```

**判断口诀**:
- 前端 mock 拦截的用例：在浏览器 DevTools Network 面板确认请求被前端拦截（Response 来自本地 fixture）
- 后端 mock 用例：检查后端日志确认 mock 分支被执行（运行时 `if (mockEnabled)` 判断）

#### 4. 跨系统验证清单（第四章）的标注

在 4.1 对接总览中，新增"交付状态"列和"Mock 实现方式"列：
```markdown
| 系统名 | 场景 | 方向 | 关联用例 | 交付状态 | Mock 实现方式 |
|-------|------|------|---------|---------|-------------|
| 支付宝 | 退款 | 我方调用第三方 | TC-PAY-001~004 | ⏳ 未交付（预计 2026-09-01） | ✅ 前端运行时可控（`VITE_THIRD_PARTY_MOCK_ENABLED`） |
| 阿里云SMS | 验证码 | 我方调用第三方 | TC-SMS-001~004 | ✅ 已交付 | N/A（真实接口） |
```

#### 5. 真实接口可用后的用例迁移

当第三方接口交付后，对应用例必须：
- 执行阶段 4 清理验证用例（TC-PAY-004）
- 清理验证通过后，归档阶段 1~3 的 Mock 用例（不再列入回归）
- 创建真实接口的正向/异常/边界用例（计入正式回归覆盖率）
- 更新跨系统验证清单，交付状态改为 `✅ 已交付`，Mock 实现方式改为 `N/A`

#### 6. 严禁基于 Mock 验证业务正确性

`[待第三方交付]` 用例只能验证 UI 联调可行性（如表单提交后页面跳转），**不得**作为业务规则验证依据（如金额计算、退款到账金额、支付宝流水号格式），业务规则必须等真实接口可用后重新验证（阶段 4）。

**与下游 SKILL 的协作：**
- `code-verification-loop` 维度 2B 第三方临时 mock 全生命周期检查中，若发现反模式（构建期裁掉/真实对接后残留），本 SKILL 生成的对应用例必须重新执行
- 用例覆盖率统计时，`[待第三方交付]` 用例不计入覆盖率，避免虚假达标
- 阶段 4 清理验证用例（TC-PAY-004）必须在真实接口可用后执行并通过，作为 Mock 清理的验收标准
