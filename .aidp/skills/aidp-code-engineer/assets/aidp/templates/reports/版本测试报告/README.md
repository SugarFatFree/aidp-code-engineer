# 版本测试报告（发布时单文件 HTML）

> `/version` 正式发布（情况 B-3）时生成的**版本级正式对外测试报告**，一个完全自包含的单文件 HTML。**去除所有 build 构建版本标识 + 不含任何应用截图**——读者只看到「本版本的测试结果」，不感知底层有几个 build。与 AI测试报告（per-build 明细 + 截图）定位区分开。

## 产物

`{version}-测试报告.html`（如 `V0.1.0-测试报告.html`）——CSS + JS + 数据 + SVG 图表**全部内联在这一个文件里**，发给任何人**双击即看**，不依赖任何外部文件 / 目录 / 网络。

## 内容（版本级，无 build 痕迹、无截图）

- 报告头：`{version} 版本测试报告` + 里程碑 / 发布日期 / 测试结论徽章
- 版本信息表 + 测试总览 KPI（总用例 / 通过 / 失败 / 阻塞 / 忽略 / 不适用 / 通过率（分母 = 总用例−不适用））
- 通过率环形图 + 用例分布图（手写内联 SVG）
- 套件结果表（套件名 / 总数 / 通过 / 失败 / 阻塞 / 忽略 / 通过率）
- 缺陷汇总表（编号 / 标题 / 严重度 / 状态——**无 build 列、无截图列**）
- 测试结论（✅通过 / ⚠️有遗留 / ❌不通过）

## 生成（/version Step 3.3.8）

1. 读 `../AI测试报告/data/*.js`（排除 `示例_*`）所有 build 数据，内联进单文件。
2. **聚合到版本级**：取 `buildNo` 最大的 build（最后收敛的一轮 = 最终验收态）作为本版本最终结果渲染；**不**逐 build 展示、**不**出现 build 号、**不**含截图。
3. 套用本目录模板 `{version}-测试报告.html` 渲染。

> AI测试报告项目保留作 per-build 历史（含截图）；版本测试报告是发布交付的版本级单文件快照。数据契约见 `../README.md`。
