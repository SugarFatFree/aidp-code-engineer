## 三、执行参数(阈值配置化,执行子 Agent 读此为准,缺省才用默认)

- 用例来源:`{dev-manual-testcase 用例路径}`
- 测试产物目录:`{产物根目录}`(build-{N}/round-{M}/ 下含 tasks.md / results/ / evidence/)
- 证据归档目录:`round-{M}/evidence/`
- 通过准则:P0=100% / P1≥95% / P2≥80%(默认,或取自自测方案)

| 配置键 | 默认值 | 说明(远程/慢网可上调) |
| :- | :-: | :- |
| `step_timeout_s` | 3 | 单步操作等待上限(秒) |
| `heartbeat_cmd` | (空) | 存活心跳命令;非空时每完成一个模块 / 每 10 条用例执行一次,失败忽略 |
| `first_open_timeout_s` | 30 | 首次打开页面/App 等待上限(秒) |
| `entry_probe_timeout_s` | 60 | 功能入口探测总时长上限(秒) |
| `retry_limit` | 3 | 单操作/驱动调用失败重试次数上限 |
| `driver_health_timeout_s` | 15 | **驱动健康探活**单次上限(秒);连续多次原子调用全超时 + 探活无回应 = 判驱动进程级卡死 |
| `driver_heal_retry_limit` | 3 | **驱动卡死自愈**(resetSession→重登→续跑)连续失败上限;到顶才判 `block(driver-hung)` |
| `module_parallelism` | 1 | 模块间并行度;1=串行(默认);>1 须为每 slot 分配隔离会话 |
| `capture_warnings` | false | **是否记录 severity=P3 的告警类运行时错误**。默认 **关** —— 真实前端的框架废弃警告/devtools 提示极多,恒记录会让每条用例都挂一串不影响判定的 P3、显著抬高报告体积与 token,而它们既不改变 pass/fail 也很少被跟进。需要排查时显式开。⚠️ P1/P2(JS 未捕获异常、接口非 2xx)**不受本开关影响、恒记录** |
| `free_scan` | false | **是否做自由巡检**(全部用例跑完后,对「菜单可达但未被任何用例覆盖」的页面逐个导航 + 拉运行时错误)。默认 **关**。见下方说明 |
| `free_scan_max_pages` | 20 | 巡检页数上限(仅 `free_scan: true` 时生效)。超出时**不静默截断**,须按方法论 12.6 单写一条 block 巡检项列明被跳过的页面 |

> **`free_scan` 自由巡检说明:** 用例集**永远无法穷举页面**——菜单点得到、但本轮没有用例覆盖的页面,其接口 500 / JS 报错目前完全测不出来。开启后,在**全部模块用例跑完之后**(不是每个模块之后:那时"已覆盖页面集合"还不完整,会把后面模块要测的页面误判为未覆盖)对这批页面各导航一次并拉运行时错误,结果以 `case_id="运行时-<页面>"`、**`entry_kind:"free-scan"`** 写入 `results/`。
>
> ⚠️ **巡检项不计入用例统计、不进缺陷列表**,单列报告 §2.6 —— 它没有断言,混进 `total` 会让"巡检页越多通过率越好看",方向恰好是反的。巡检发现是**线索**:人工确认后转 bug,或补成正式用例进下一轮。执行细则见 `../references/execution-methodology.md` 第十二节。

## 四、关键元素定位方式 + 常用测试数据(执行前一次性静态预置 · 执行中只读)
