#### 维度 11: 失效实体与边界（语义核对·约定39-R5~R9 + R12）

> 🎯 **与维度 10 同源、互补的另一半**：那三条能被脚本抓，这六条**机器检不了**（判据依赖业务语义：
> 什么算"失效"、哪个数字该和哪个数字同源），须验收 Agent **静态读代码**核对。**全程静态**——不起服务、
> 不开浏览器，所以每条判据都落到 grep 得到、读得出的信号上。

| 规则 | 判据（一句话） | 静态信号 | severity |
| :-: | :- | :- | :-: |
| **约定39-R5** | 已下架/删除/过期/失效实体的**详情·跳转·购买·开通入口必须隐藏或禁用** | 渲染处对 `status`/`isDeleted`/`expireTime` 有无 `v-if`/`disabled`；只在点击后报错 = 不通过 | 🔴 |
| **约定39-R6** | 被引用实体已删除须**降级为可读展示**，不裸露编码/ID/空值 | 取名处是否 `?? code` / `\|\| id` 回退；有无快照名字段 | 🔴 |
| **约定39-R7** | 加载未完成**不得渲染"看起来是真的"的脏数据** | 列表/开关类初始值是否预置了假数据 **且** 渲染无 `v-if="!loading"` 守卫 | 🔴 |
| **约定39-R8** | 编辑成功后**当前视图必须自动同步**，不得要求切页/刷新 | 保存成功回调里有无刷新/回写；**跨组件**（详情改了列表没刷）是高频形态 | 🔴 |
| **约定39-R9** | **存量数据兼容性**——改结构/加必填/收窄取值须验证改动前的存量数据 | 新必填字段有无 `DEFAULT`/迁移/读取侧兜底；收窄枚举时老值落到哪个分支 | 🔴 |
| **约定39-R12** | **同一指标跨页面必须同源**，禁止各页面各算一遍 | 指标计算/取数点散落 **≥2 个文件**即高危（与维度 8 同一形态：查判据有几份实现） | 🔴 |

#### 维度 12: 上游调用日志可见性与脱敏（委派外部脚本 + 语义半场·约定40）

> 🎯 **和维度 10 同一种结构**：确定性部分**一律委派**被测项目侧脚本，本 SKILL 只承接脚本做不到的

> **⚠️ 全程静态** —— 本维度查的是**代码里有没有打日志的语句、打了什么、脱敏发生在哪一层**，

> 最容易诱发"跑起来看一眼"的题材，而 `SKILL.md` 角色定义下方的维护者注记已写明：这类事故的根因不是有人写了

> ⚠️ **术语消歧：** 这里的「**上游**」= **被本项目调用的第三方 / 上游服务**（第三方 HTTP API /
> 微服务 RPC·Feign / 对象存储 / 短信邮件消息网关 / 支付鉴权中心），**不含本地 DB 与本地缓存**；
> 与「上游 SKILL 产出的设计文档」里的「上游」不是一回事。通用规则号写全称 **约定40**，别写裸 `RNN`。

**⛔ 最高约束：本 SKILL 不得再写一份 C1–I3 的 grep 实现。** 判据脚本
`<被测项目根>/{{AIDP_HOME}}/scripts/check_upstream_call_log.py` 由 AIDP 脚手架下发到**被测项目**侧
（不在本 SKILL 的 `scripts/` 下、**也不许拷进来**、不受版本门控）。项目侧与 SKILL 侧各存一份平行判据时，
两套口径会各自演进、其中一份带着静默漏检长期存活——与维度 10 是同一条纪律。

```bash
python3 <被测项目根>/{{AIDP_HOME}}/scripts/check_upstream_call_log.py --json
# 退出码 0=无 Critical / 1=有 Critical / 2=入参或环境错（**不是维度违规**）
# JSON 顶层：scanned_files / outbound_files / critical / important / waived / findings[]
# 每条 finding：check(C1/C2/I1/I2/I3) / severity / file / line / message / evidence
```

| 判据 | 含义 | severity |
| :-: | :- | :-: |
| **C1** | 出站调用类**零日志** | 🔴 Critical |
| **C2** | **成功路径不可见**（该类日志全是 warn/error） | 🔴 Critical |
| **I1** | 无一条日志提到 URL | 🟡 Important |
| **I2** | 成功路径只有 `debug` | 🟡 Important |
| **I3** | 疑似凭据明文入日志 | 🟡 Important |

**⚠️ 「成功路径必须可见」是本维度的核心，别弱化成"有日志就行"**——真实缺陷正是「只有出事才出声」：
成功时什么都不打，既定位不了"对方成功返回了但内容不对"，也拿不到耗时基线。

**本 SKILL 承接的三条语义判据（脚本做不到，是本维度的真正价值）：**

| # | 判据 | 怎么静态查 | severity |
| :-: | :- | :- | :-: |
| **12.1** | **脱敏是否覆盖嵌套结构** | 静态读代码确认脱敏发生在**序列化环节**（自定义 Serializer / `@JsonIgnore` / 脱敏 ObjectMapper），而不是只在最外层拼串时替换——`log.info("req={}", toJson(request))` 里 `request` **内嵌**的 `password`/`token` 是纯词法扫描够不着的一层 | 🔴 |
| **12.2** | **二进制降级是否真的只打元信息** | 沿文件流 / 字节数组 / `MultipartFile` / `InputStream` 路径核对：打的是**文件名 + 大小 + contentType**，不是把整个 base64 或 `new String(bytes)` 塞进日志 | 🔴 |
| **12.3** | **拦截器是否真的覆盖了全部出站客户端** | 核对「项目里有几个出站客户端 **vs** 拦截器实际注册到了几个 Bean 上」，差集逐个点名。⚠️ **抵扣了哪些一律以脚本 `--json` 的 `waived` 字段为准**，⛔ 不要凭记忆假设它抵扣了什么——对象存储 / 短信 SDK 这类**非 HTTP 机制**通常不在 HTTP 拦截器覆盖面内，但这属**脚本侧口径、随它演进**，本 SKILL 不复述 | 🔴 |

> ⚠️ **本 SKILL 不复述该脚本的内部实现口径**（它抓什么、抵扣什么、怎么抵扣）——脚本不在本 SKILL 目录内

> 判据名 + 一句话含义 + severity 是复述的**上限**；细粒度口径一律**以 `--json` 的实际输出为准**，
> 照 `dev-logic-architect` 检查项 31「以上游契约为准，上游变更即需跟进」的既有写法。

**上游契约（有则强制消费）：** `dev-logic-architect` 检查项 35 的「**上游调用日志与脱敏声明表**」是本维度

#### 维度 13: 实现偏离设计（委派外部脚本·设计锚点落点）

> 🎯 本维度只回答一层问题：**详细设计点名的字段/常量，在源码中是否能找到实现落点**。不做代码与设计的语义等价证明；找不到落点不直接认定实现错误，必须给出交代。

**委派脚本（确定性采集）：**

```bash
python3 <被测项目根>/{{AIDP_HOME}}/scripts/check_design_anchor.py --version <版本号> --json
# 例：python3 <被测项目根>/{{AIDP_HOME}}/scripts/check_design_anchor.py --version V0.14.0 --json
# 退出码 0=未发现未落点锚点 / 1=发现需交代的未落点锚点 / 2=入参或环境错
```

> ⚠️ **本维度比维度 10 / 维度 12 多一个必填参数 `--version`，且它是「带值」参数、不是查版本号的开关。**
> `check_ui_fidelity.py`（维度 10）与 `check_upstream_call_log.py`（维度 12）都只需 `--json`，
> 按那两个的经验照搬就会写出 `check_design_anchor.py --version`（缺值）或 `--json <路径>`（缺 `--version`）。
> 这类**用法错**按全仓退出码约定落在 `exit 2`（「入参/环境错」，**不是**维度违规）——调用方据此
> 「修正参数后重跑」，于是这一档在报告里既不算过也不算不过，实际是**静默没跑**。
> **`--version` 的值由调用方脚手架契约传入**（当前验收的版本号，如 `V0.14.0`），⛔ 不得由本 SKILL 自拟或省略；
> 取不到版本号时按「不适用（未取到 `--version` 值）」标注留行，**不得**用一个猜的版本号把脚本跑绿。
>
> ⚠️ **参数形态以下发到被测项目的那份脚本 `--help` 为准，本节只给「必须带 `--version <值>`」这条结论。**
> 脚本不在本 SKILL 目录内（由脚手架下发到被测项目 `{{AIDP_HOME}}/scripts/`），本 SKILL **没有任何机制能发现这里的参数描述过期**——与维度 12 的同款注记是同一条纪律，
> 失效方向同样是**假绿**（命令写错 → `exit 2` → 被当成环境问题略过）。**首次调用前先跑一次
> `check_design_anchor.py --help` 核对参数**；与本节不一致时以 `--help` 为准，并在报告里记一句。

脚本未随脚手架下发时，维度 13 标「不适用（未下发 `check_design_anchor.py`）」跳过，报告仍留行；不得把脚本缺失读成通过。脚本返回的锚点清单是采集依据，最终是否为设计过时、设计变更或实现缺口由 Agent 结合版本与上下文判断。

**强制判据：**

- 详细设计中点名的业务字段、配置常量或取数锚点，必须在源码找到对应落点；命名匹配须容忍 `createTime` / `getCreateTime()` / `create_time` / `CREATE_TIME` 等 camelCase、snake_case、SCREAMING_SNAKE 变体。
- 匹配只放宽**前边界**，不放宽后边界：`userId` 可命中 `getUserId()` / `user_id`，不得命中 `userIdentifier` / `user_id_suffix` 等更长标识符。匹配结果仍需 Agent 阅读上下文确认是实现落点而非注释、测试样例或无关同名文本。
- 每个未落点锚点只能采用一种处置并写明理由：①修改代码补齐实现；②修改设计，并按约定 22 级联更新相关产物；③使用行内 `design-anchor-ignore: <理由>` 显式豁免，理由必填。
- 本维度判 **Important，不判 Critical**：它的目标是暴露设计与实现的断点并要求闭环，不把“设计已过时”误阻断为代码缺陷。判不准时按高一档补查，不得直接静默放行。

**豁免格式：**

```text
// design-anchor-ignore: 设计中的 createTime 已由本版字段迁移为 createdAt，详见设计 §B-2.1
```

**与其它维度边界：** 维度 3 管接口契约是否正确，维度 4 管代码自身质量与字段/列对账，维度 13 管设计点名锚点是否在实现中有可追溯落点；不替代语义等价审查，也不重复字段集合对账。
#### 维度 14: 样式重构编译等价性对照（技术栈门控·改动了样式时才触发）

> 🎯 **维度 7 的 🎯 已经点明「`vue-tsc` 与 `eslint` 都不编译 `<style>` 块」，但它只回答一件事：
> 预处理器有没有在 `package.json` 声明。** 样式**重构**（抽公共 / 参数化 / 移动位置）的正确性
> 目前**零覆盖**——而「类型检查过了」对样式**毫无意义**，这是使用者最容易误采信的一句话。
>
> **本维度仍是纯静态、零构建**：只编译**改动的样式段**、不打包、不起任何服务，
> 成本与维度 7 同量级，与最高约束第 0 条不冲突。

**方法（三步，改动前后各编译一次）：**

```
改动前的样式段 → 预处理器编译 → old.css
改动后的样式段 → 预处理器编译 → new.css
归一（压空白 / 单位等价形式统一）+ 排序 + diff  ⇒ 要求【零差异】
```

**这是样式重构目前唯一可行的静态正确性证明**——重构的定义就是「产物不变」，
产物一致即证明重构没有改变行为；产物有差异，那个差异要么是本次有意的、要么就是缺陷。

**实证价值（下游首轮对照就抓到两个会静默进产物的真问题，两者在 `vue-tsc` + `eslint` 下全绿）：**

| # | 问题 | 后果 |
| :- | :- | :- |
| ① | 作者写的**文档块注释**被编译进 CSS | 污染产物 29 行 |
| ② | 公共 mixin **无条件输出一条 `margin` 声明** | 给原本没有该声明的调用方**凭空加上** |

**判定口径：**

| 项 | 口径 |
| :- | :- |
| **触发条件** | 本次改动**涉及样式文件或 `<style>` 块**（`.scss` / `.less` / `.styl` / `.css` / `.vue` 的 `<style>`）。没动样式 = 整维度跳过 |
| **技术栈门控** | 扫不到前端样式源码 = 整维度跳过（不计入通过/不通过） |
| **编译器** | 用**被测项目自己的** `sass` / `lessc` / `stylus`（`./node_modules/.bin/…`），⛔ 不联网装、不全局装 |
| **判定** | 归一后仍有差异 = 🔴 **Critical**，除非差异**逐条被本次改动的意图解释**并写进报告 |
| **编译器缺失** | 标「不适用（预处理器未安装）」跳过，**报告仍留行**（与维度 10 / 12 / 13 同款：留行才能让阅读者知道这一档没跑过） |

**硬门脚本**（纯标准库，只做**归一 + 比较 + 基线有效性判定**这一段；两次编译由上面的命令产生）：

```bash
# 1) 取基线样式段并编译（示例，命令随项目而定）
git show HEAD:src/styles/card.scss > /tmp/old.scss && ./node_modules/.bin/sass --no-source-map /tmp/old.scss /tmp/old.css
./node_modules/.bin/sass --no-source-map src/styles/card.scss /tmp/new.css
# 2) 归一 + 比较
python3 <SKILL_DIR>/scripts/check_css_equivalence.py /tmp/old.css /tmp/new.css --json
```

退出码 `0`（等价 / N-A 跳过）/ `1`（有差异）/ `2`（入参或环境错，含**基线无效**）。

**⚠️ 两条配套判据（并入本维度）：**

1. **公共样式文件的文档注释必须用行注释 `//`，⛔ 不用块注释 `/* */`。**
   预处理器会把 `/* */` **编译进产物**，`//` 不会。写给人看的说明进了 CSS 产物既没用又占体积
   （下游实测污染 29 行）。
2. **前端最低静态验证组合 = 类型检查（带阳性对照）+ lint（同文件集基线对照）+ 预处理器编译（改样式时）**，
   三者各有盲区、**缺一不可**：

   | 手段 | 能抓什么 | ⛔ 抓不到什么 |
   | :- | :- | :- |
   | **类型检查** | 类型错、未定义符号 | **不编译 `<style>`**；**模板语法错误零报错**（把注释写进标签的属性列表中间会导致整模板解析失败，而 `vue-tsc` 一声不吭） |
   | **lint** | 模板语法错、代码风格 | 不编译样式；不保证类型正确 |
   | **预处理器编译** | 样式语法错、产物差异 | 与逻辑正确性无关 |

   ⚠️ **「类型检查带阳性对照」不是废话**：`vue-tsc` 会因 `tsconfig` 的 `types` 指向未安装的包而
   **提前中止**，此时**源码零检查却报「0 错误」**——与本 SKILL 反复强调的「失效形态是 0 命中假绿」
   完全同源。跑之前先故意注入一个类型错误，确认它**能红**。

**与维度 7 的边界（不重复登记）：** 7 管**预处理器有没有装**（`<style lang>` 声明的包在不在
`package.json`），14 管**样式重构后产物变没变**。7 是「能不能编译」，14 是「编译出来一不一样」。

#### 维度 15: 同族增量项一致性（委派外部脚本 + 语义半场·被测项目 约定 20）

> 🎯 **立论：同一形态连续复发 3 个版本。** 场景是一个页面承载「每版各加一个同构成员」的家族
> （隐藏运维页的历史数据处理入口，V0.9 / V0.10.2 / V0.10.3 / V0.13.0 / V0.14.0 / V0.15.0 各一个，
> 外观相同、只有标题与说明不同）。每次新增都出**同样两个**问题：**① 新成员没有公共外壳**
> （家族没抽公共单元，父页样式是 `scoped`、传不进子组件，于是每个成员各自复制一份样式，漏抄即失效）；
> **② 新成员插错顺序**（顺序靠在模板里手工插位 + 一行注释提醒，**无任何机器约束**）。
>
> **⚠️ 失败形态是本维度存在的全部理由：** 类型检查、lint、单测全绿，构建通过，
> **只有人打开页面并排比对才看得出来**——而「照着隔壁那个成员复制一份」恰恰是执行体**最自然**的动作。
> 它同时绕过了维度 7（预处理器装没装）、维度 14（样式产物变没变，复制不改动既有产物）与
> 维度 4 的复杂度阈值，**既有维度一条都够不着**。

**★ 判据是「有没有兄弟」，不是「我写了几遍」。** 家族已有同构成员 **≥2** 即适用，
**哪怕本次只新增 1 个**。这是与既有「复用 / 重复」类检查的**关键区别**：在这类场景里
执行体**主观上正在复用**（他确实是照着兄弟改的），所以按「重复 N 次」设阈值的规则**不会触发**。

> ⚠️⚠️ **与维度 4「文件复杂度 + 复用封装」的边界（两条规则在 N=2 时直接冲突，必须按此判）：**
> 维度 4 写着「**3+ 次重复必抽**」与「**过度抽象禁令：3 次以下复用禁止抽**」，
> 而本维度在成员数 = 2 时就要求有公共外壳——**照维度 4 的字面，N=2 时抽外壳反而违规。**
> **判据分野在「家族性是不是已声明的事实」**：维度 4 那条管的是「同一段逻辑**偶然**出现了 N 次」
> （不知道将来还会不会有第 N+1 次，故用次数做保守阈值，立意是防「为两处偶然相似就造抽象」的反向超调）；
> **本维度管的是「这是一个已经确定还会继续加成员的家族」**——下一个成员**确定会来**，
> 不是从重复次数推断出来的猜测。**故：命中本维度（上游设计已声明该家族，或项目侧 `SIBLING-FAMILY:`
> 已登记）时，维度 4 的「3 次以下禁止抽」不适用**，⛔ 不得拿它去驳回本维度的公共外壳要求；
> 反之，**没有任何家族声明的两处偶然相似仍按维度 4 判**，⛔ 也不得拿本维度去要求抽象。

**⛔ 最高约束：本 SKILL 不得再写一份同判据实现。** 判据脚本
`<被测项目根>/{{AIDP_HOME}}/scripts/check_sibling_family.py` 由 AIDP 脚手架下发到**被测项目**侧
（不在本 SKILL 的 `scripts/` 下、**也不许拷进来**）。**判定细则以该脚本与被测项目
`{{AIDP_HOME}}/rules/code.md`「约定 20 —『同族增量项』」为单一信源，本 SKILL 不复述判据**——
与维度 10 / 12 / 13 是同一条纪律（项目侧与 SKILL 侧各存一份平行判据，两套口径必然各自演进）。

