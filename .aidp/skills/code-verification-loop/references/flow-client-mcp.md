## 纯静态语义核对

以 architect 的客户端/实现形态/工具清单与入出 Schema/源码落点为基准,逐工具核对:注册与停用位置真实存在、**身份与权限**取自可信登录态/服务端校验而非客户端自报、列出/详情/执行三处权限不扩张、写操作确认对任意调用方生效、错误与合法空结果不同、审计日志记录工具/主体/结果且敏感值脱敏、调用证据落点可指认。**另须核 SKILL.md 维度 9 表里的 9.4 / 9.5 / 9.6 三条端无关判据**(写操作复用业务既有执行通道 / 凭据密钥令牌**含脱敏片段**一律不经工具通道返回〔⚠️ 与上句「审计日志脱敏」**不是一回事**:那管日志,这管**工具出参**〕/ 可调用集合用白名单且列表·详情·执行三处共用同一判据),判据全文在那张表、此处不复述。**只做代码事实与设计锚点核对,不起服务、不运行浏览器**;运行时四态证据归 `auto-test-runner`。缺实现证据时报告未落地,不得以“应用使用 Appium MCP”充当证明。

**Web** 继续调用本 SKILL 自带的 `check_webmcp_adapter.py` 只判 Web 入口单一性及不存在的 unregister 调用,其余 Web 静态语义按 `flow-webmcp.md`。**Web 专项只执行一次**;通用半场读取同一实现落点,不再单列相同的工具/确认门违规。**非 Web** 仅静态读已证实的**应用自有 MCP 服务或桥接**实现/注册/鉴权代码,不向 Web 脚本传 App/小程序/桌面源码,不为它们自造浏览器入口标识符或 Chrome 前提。声明未提供时无本维度行;声明启用但实现文件/服务证据未取到则维度不通过,不是跳过成功。

| 情形 | 正向 | 必拒绝的反例 |
| :- | :- | :- |
| Web 已实现 | Web 源码唯一适配入口 + 工具注册/权限/确认有落点 | 仅 Chrome 驱动 MCP 可用便报 WebMCP 已实现 |
| 非 Web 已实现 | App 自有服务/桥接有可指认注册与鉴权代码 | 用 `check_webmcp_adapter.py` 扫 App 源码得到零命中就判合规 |
| 非 Web 未实现 | 声明未提供,原 UI 验收照常 | 臆造通用桥接入口并给出通过 |
| 只有测试驱动 | Appium/小程序驱动正常操作 UI,产品能力仍关闭 | 将驱动的 MCP tools 当成应用业务工具 |
