#### 维度 9: 客户端应用 MCP 业务能力实现合规（**条件启用**·WebMCP 为 Web 专项）

> 🎯 **与维度 6/7/8 同一类的门控型维度，只是门控信号不同**：那三个由**技术栈**门控（扫不到该栈
> 源码即整维度跳过），本维度由**调用方入参**门控。判据同样是**纯静态分析**——符合本 SKILL
> 「不用跑起来」的立论，不启动浏览器、不发请求、不装任何东西。

**门控（先判这一条，再决定要不要往下看）：**

| 项 | 口径 |
| :- | :- |
| **启用条件** | 调用方显式 `client_mcp.enabled: true` 或旧 Web `webmcp_enabled: true`；两者均未启用 → 整维度不告警、**报告不留行**。两声明的客户端/启停/形态冲突须报错,不静默覆盖 |
| **⛔ 严禁自行探测** | 不 grep PRD/代码或据 Chrome/Appium **测试驱动 MCP** 推断应用已提供业务工具,启用权只归调用方 |
| **入口标识符** | **仅 Web+WebMCP** 由 `webmcp_entry_symbols`（数组）传入。⚠️ **挂载位置已迁移过一次、规范仍在演进，脚本与文档都不得写死任何一个名字**——写死后的失效方向是「扫不到 → 0 命中 → **假绿**」。缺该入参时**报入参错而不是猜默认值** |

**通用静态半场(已声明端均查):** 必读 [`references/flow-client-mcp.md`](./flow-client-mcp.md),对设计工具清单/入出 Schema、应用自有实现落点、主体权限、写确认、生命周期、错误、审计日志逐项读源码。非 Web 没有已证实的**应用自有 MCP 服务或桥接**则不能判实现通过;不启动服务/浏览器。Web 通用半场只补下面六项未覆盖的声明/Schema 来源/审计落点,同一权限/确认/错误问题只登记一次;非 Web 则完整执行通用半场。

**9.1 / 9.2 / 9.3 与 `check_webmcp_adapter.py` 仅 Web+WebMCP 时执行**（判据全文见 [`references/flow-webmcp.md`](./flow-webmcp.md)）;**9.4 / 9.5 / 9.6 对所有已声明端执行**——⚠️ 这三条是**端无关的安全判据**(写操作走哪条通道、凭据出不出工具通道、可调用集合是白名单还是黑名单),与浏览器无关;整族划进 Web 专属会让**非 Web 启用项目的三条 Critical 无人查**,而通用半场并不覆盖它们。⛔ 别把它们再抄进 `flow-client-mcp.md` 的正文判据——判据本体只在本表这一份，那边只写结论指回来：**

| # | 检查 | 判据要点 | severity |
| :-: | :- | :- | :-: |
| 9.1 | **单一适配层** | 入口标识符在前端源码里的**命中文件数必须 == 1**。⚠️ **注释里写了也算命中**——否则 grep 形同虚设（实际项目中触发过这条） | 🔴 Critical |
| 9.2 | **无「先登记后撤销」时序** | 登记调用不得早于配置就绪；且**代码里出现 `unregisterTool` 即 Critical**（实测该 API 不存在，据草案臆想它存在会让撤销**静默失效**——实际项目中曾用可选链做防御，撤销悄悄没生效、代码零报错、文档与实际不符） | 🔴 Critical |
| 9.3 | **错误契约无死文案** | 每个错误契约常量都有实际使用面。⚠️ 新增一条错误文案时须 grep **旧文案的全部使用点**逐一判断该不该改——只改「发现问题的那一处」会留下**姊妹路径**（实际项目中踩过） | 🟡 Important |
| 9.4 | **写操作未绕开业务既有执行通道** | 工具的写操作必须复用业务既有执行通道，绝不另写一条。否则会出现「**手工操作能通、让助手做就不通**」，且两条链路的日志形态、参数校验、变量替换各不相同 | 🔴 Critical |
| 9.5 | **敏感字段未经工具通道外泄** | 凭据 / 密钥 / 令牌类的值一律不经工具通道返回，**包括脱敏片段**；只返回名称、位置、作用域这类元信息 | 🔴 Critical |
| 9.6 | **可调用对象用白名单而非黑名单** | 业务对象有多种类型时，工具暴露的集合必须**白名单列举**可调用类型。⛔ 黑名单会随类型增加而失效，把不可调用的对象放进去、助手拿它执行会产生意外副作用。**列表、详情、执行三处须共用同一判据，任一处放行即构成绕过** | 🔴 Critical |

**硬门脚本**（零依赖纯标准库，`--json` 供 Agent 解析）：

```bash
# 前两项是纯词法、零主观，已脚本化
python3 <SKILL_DIR>/scripts/check_webmcp_adapter.py <前端源码目录> \
    --entry-symbols <符号1> <符号2> ... --json
# 已声明单一适配层文件时，口径反转为「信源之外一处都不许有」
# ⚠️ --allow 的 glob 基准是**仓库根**、不是扫描目录：前端嵌在子路径下时必须写全路径，
#    写错会把「全项目唯一那处合法信源」判成平行实现（纯假红），故一个都没匹配上时直接 exit 2
python3 <SKILL_DIR>/scripts/check_webmcp_adapter.py <前端目录> \
    --entry-symbols <符号1> --allow 'code/frontend/web/src/webmcp/adapter.ts'
# 让「超限 / 不可读」这类未参与检查的缺口也卡住闸门（推荐验收时带上）
python3 <SKILL_DIR>/scripts/check_webmcp_adapter.py <前端目录> \
    --entry-symbols <符号1> --strict
```

退出码 `0`（闸门通过，含「扫不到前端源码 → 跳过」）/ `1`（未通过）/ `2`（入参或环境错：路径不存在、
缺位置参数、**未传 `--entry-symbols`**、`--max-file-bytes` 非正、显式传的文件全不在可扫类型内、
**`--allow` 一个 glob 都没匹配上**）。输出 19 个字段（清单与语义以 [`references/flow-webmcp.md`](./flow-webmcp.md) 为单一信源，本节不复述——脚本一改、抄件必漂移）——**判「过没过」读 `gate_passed`**；`skipped=true`
只表示 Web 机器叶子未扫到前端源码、**不等于维度 9 通过或整维度跳过**;非 Web 已声明应用服务/桥接的通用静态核对照常执行,报告就地标明 Web 子项未跑原因。

> ⚠️ **脚本只做 9.1 与 9.2 的 `unregisterTool` 两项。** 9.2 的时序、9.3~9.6 四项须由验收 Agent
> 静态读代码人工核对——**脚本全绿 ≠ 维度 9 通过**。

**⚠️ 概念前提（写错会让整维度查偏）：** WebMCP **不是网络协议、没有传输层**，消费方必须先能进入

**与其它维度的边界（不重复登记）：** 9.1 与**维度 8**是同一类结构判据的两个实例——都不判「这一处

#### 维度 10: UI 还原度确定性检查（委派外部脚本·约定39-R2/R3/R10）

> 🎯 **为什么值得单开一维度**：某示例项目 71 条已关闭缺陷里 **96%（68/71）属「正常发现」**——走一遍正常

> 是其中**能被确定性脚本抓住**的部分，正该在静态验收期拦下。

> ⚠️ **编号消歧：** `约定39-RNN` 是上下游共用的通用规则号，**引用一律写全称**。姊妹 SKILL 里裸 `RNN`
> 已被占用成别的东西（`dev-logic-architect` 的 `R1/R2/R3` = 上游溯源三项；`dev-manual-testcase` 的
> `R1~R12` = 反向覆盖维度），裸写必混淆。

**⛔ 最高约束：本 SKILL 不得再写一份同判据实现。** 判据脚本 `{{AIDP_HOME}}/scripts/check_ui_fidelity.py`（`{{AIDP_HOME}}` 由安装方渲染、相对被测项目根，见 [`../SKILL.md`](../SKILL.md)「运行路径约定」）
由 AIDP 脚手架下发到**被测项目**侧，不在本 SKILL 的 `scripts/` 下、**也不许拷进来**。同一判据两份实现
是最高频漂移源（改一处漏一处、两处都自称权威）——本 SKILL 维度 8 判别人「同一判据散落多份」，不能
自己复制一份。

```bash
python3 {{AIDP_HOME}}/scripts/check_ui_fidelity.py --json            # 全量
python3 {{AIDP_HOME}}/scripts/check_ui_fidelity.py --check R3 --json # 单条
# 退出码 0=无 Critical / 1=有 Critical / 2=用法错；输出 findings[]（rule/severity/file/line/message/evidence）
```

| 规则 | 判据 | severity | 可豁免 |
| :-: | :- | :-: | :-: |
| **约定39-R3** | 文本截断（`text-overflow:ellipsis` / `-webkit-line-clamp` / `truncate`）而同节点或父节点无 `title`/tooltip | 🟡 Important | ✅ `fidelity-ignore:` |
| **约定39-R10** | 导出方法体内透传分页参数（`pageNo`/`pageSize`/`PageHelper`/`Pageable`/`limit`）——即"导出只导当前页" | 🔴 **Critical** | ⛔ **不设豁免** |
| **约定39-R2** | 状态标签内容随数据变化、而 `type`/`color` 是字面量常量——状态变了颜色不变 | 🟡 Important | ✅ `fidelity-ignore:` |

**R10 为什么零豁免**：「导出只导当前页」**没有正当场景**——用户点"导出"的语义是导出结果集，不是导出
他此刻看着的那 20 行。**R2/R3 可豁免**：存在刻意的纯文本降级、装饰性文案等正当例外，机器侧支持就近
写 `fidelity-ignore: <规则号> <原因>`；⚠️ **只写规则号不写原因的豁免须报 Important 让其补齐**，否则
它会退化成"一键关掉这条规则"。

**脚本不存在时**：维度 10 标 **「不适用（未随脚手架下发 `check_ui_fidelity.py`）」跳过，不硬失败**。
⚠️ 这是**技术栈门控式的跳过——标 N/A、报告里留行**，与维度 9 那种「入参门控、连行都不留」不是一回事：
留行才能让阅读者知道"这一档没跑过"，否则全绿会被读成"查过且通过了"。**退出码 2 是入参/环境错，
不是维度违规**，修正参数后重跑、不记为不通过。

#### 维度 11: 失效实体与边界（语义核对·约定39-R5~R9 + 约定39-R12）

> 🎯 **与维度 10 同源、互补的另一半**：那三条能被脚本抓，这六条**机器检不了**（判据依赖业务语义：
> 什么算"失效"、哪个数字该和哪个数字同源），须验收 Agent **静态读代码**核对。**全程静态**——不起服务、
> 不开浏览器，所以每条判据都落到 grep 得到、读得出的信号上。

| 规则 | 判据（一句话） | 静态信号 | severity |
| :-: | :- | :- | :-: |
| **约定39-R5** | 已下架/删除/过期/失效实体的**详情·跳转·购买·开通入口必须隐藏或禁用** | 渲染处对 `status`/`isDeleted`/`expireTime` 有无 `v-if`/`disabled`；只在点击后报错 = 不通过 | 🔴 |
| **约定39-R6** | 被引用实体已删除须**降级为可读展示**，不裸露编码/ID/空值 | 取名处是否 `?? code` / `\|\| id` 回退；有无快照名字段 | 🔴 |
| **约定39-R7** | 加载未完成**不得渲染"看起来是真的"的脏数据** | 列表/开关类初始值是否预置了假数据 **且** 渲染无 `v-if="!loading"` 守卫 | 🔴 |
| **约定39-R8** | 编辑成功后**当前视图必须自动同步**，不得要求切页/刷新 | 保存成功回调里有无刷新/回写；**跨组件**（详情改了列表没刷）是高频形态 | 🔴 |
| **约定39-R9** | **存量数据兼容性**——改结构/加必填/收窄取值须验证改动前的存量数据 | 新必填字段有无 `DEFAULT`/迁移/读取侧兜底；收窄枚举时老值落到哪个分支 | 🔴 |
| **约定39-R12** | **同一指标跨页面必须同源**，禁止各页面各算一遍 | 指标计算/取数点散落 **≥2 个文件**即高危（与维度 8 同一形态：查判据有几份实现） | 🔴 |

**口诀两条**（写进报告便于复述）：**未取到配置先隐藏**——少显示一个按钮无伤，闪出一个点了就死的按钮
才是要消灭的现象（R7）；**判据全站唯一化，不在 N 处各写一遍**（R12）。

**上游契约（有则强制消费）**：`dev-logic-architect` 详细设计的「**统计指标口径表**」第 8 列「权威取数
口径」是 R12 的基准表——逐指标核对实现取数点是否等于表里声明的权威口径。上游没产出该表时回退为纯
grep 结构判断，并把"设计缺口径表"报为 🟡 Important，**不静默放过**。

**不适用时怎么标**：某条本轮确实无对应场景（如本轮无任何删除/下架语义实体）时标**「不适用 + 一句话
理由」**，不得直接省略——省略与"查过且通过"在报告里长得一模一样。

#### 维度 12: 上游调用日志可见性与脱敏（委派外部脚本 + 语义半场·约定40）

> 🎯 **和维度 10 同一种结构**：确定性部分**一律委派**被测项目侧脚本，本 SKILL 只承接脚本做不到的
> 语义半场。**门控是双重的**——脚本未下发 / 非 JVM 项目，都标「不适用」跳过、**报告里仍留行**。

> **⚠️ 全程静态** —— 本维度查的是**代码里有没有打日志的语句、打了什么、脱敏发生在哪一层**，
> ⛔ **不是把服务跑起来看日志输出**；跑起来读实际日志归 `/sprint-aiauto-test`。三条语义判据全部落到
> grep 得到、读得出的信号上。**这一条必须就地重申**——本维度的主题「日志」是**运行期产物**，是全 SKILL
> 最容易诱发"跑起来看一眼"的题材，而维护者注记（`../SKILL.md`「角色定义」下方）已写明：上次事故的根因不是有人写了
> "起服务"，而是**默认口径不够硬、AI 的本能会补上那一步**。

> ⚠️ **术语消歧：** 这里的「**上游**」= **被本项目调用的第三方 / 上游服务**（第三方 HTTP API /
> 微服务 RPC·Feign / 对象存储 / 短信邮件消息网关 / 支付鉴权中心），**不含本地 DB 与本地缓存**；
> 与「上游 SKILL 产出的设计文档」里的「上游」不是一回事。通用规则号写全称 **约定40**，别写裸 `RNN`。

**⛔ 最高约束：本 SKILL 不得再写一份 C1–I3 的 grep 实现。** 判据脚本
`{{AIDP_HOME}}/scripts/check_upstream_call_log.py` 由 AIDP 脚手架下发到**被测项目**侧
（不在本 SKILL 的 `scripts/` 下、**也不许拷进来**、不受版本门控）。调用方此前踩过：项目侧与 SKILL 侧
各存一份平行判据，两套口径随后各自演进，其中一份带着三处静默漏检活了很久——与维度 10 是同一条纪律。

```bash
python3 {{AIDP_HOME}}/scripts/check_upstream_call_log.py --json
# 退出码 0=无 Critical / 1=有 Critical / 2=入参或环境错（**不是维度违规**）
# JSON 顶层：scanned_files / outbound_files / critical / important / waived / findings[]
# 每条 finding：check(C1/C2/I1/I2/I3) / severity / file / line / message / evidence
```

| 判据 | 含义 | severity |
| :-: | :- | :-: |
| **C1** | 出站调用类**零日志** | 🔴 Critical |
| **C2** | **成功路径不可见**（该类日志全是 warn/error） | 🔴 Critical |
| **I1** | 无一条日志提到 URL | 🟡 Important |
| **I2** | 成功路径只有 `debug` | 🟡 Important |
| **I3** | 疑似凭据明文入日志 | 🟡 Important |

**⚠️ 「成功路径必须可见」是本维度的核心，别弱化成"有日志就行"**——真实缺陷正是「只有出事才出声」：
成功时什么都不打，既定位不了"对方成功返回了但内容不对"，也拿不到耗时基线。

**本 SKILL 承接的三条语义判据（脚本做不到，是本维度的真正价值）：**

| # | 判据 | 怎么静态查 | severity |
| :-: | :- | :- | :-: |

#### 维度 15: 同族增量项一致性（委派外部脚本 + 语义半场·被测项目 约定 20）

> 🎯 **立论：同一形态连续复发 3 个版本。** 场景是一个页面承载「每版各加一个同构成员」的家族
> （隐藏运维页的历史数据处理入口，V0.9 / V0.10.2 / V0.10.3 / V0.13.0 / V0.14.0 / V0.15.0 各一个，
> 外观相同、只有标题与说明不同）。每次新增都出**同样两个**问题：**① 新成员没有公共外壳**
> （家族没抽公共单元，父页样式是 `scoped`、传不进子组件，于是每个成员各自复制一份样式，漏抄即失效）；
> **② 新成员插错顺序**（顺序靠在模板里手工插位 + 一行注释提醒，**无任何机器约束**）。
>
> **⚠️ 失败形态是本维度存在的全部理由：** 类型检查、lint、单测全绿，构建通过，
> **只有人打开页面并排比对才看得出来**——而「照着隔壁那个成员复制一份」恰恰是执行体**最自然**的动作。
> 它同时绕过了维度 7（预处理器装没装）、维度 14（样式产物变没变，复制不改动既有产物）与
> 维度 4 的复杂度阈值，**既有维度一条都够不着**。

**★ 判据是「有没有兄弟」，不是「我写了几遍」。** 家族已有同构成员 **≥2** 即适用，
**哪怕本次只新增 1 个**。这是与既有「复用 / 重复」类检查的**关键区别**：在这类场景里
执行体**主观上正在复用**（他确实是照着兄弟改的），所以按「重复 N 次」设阈值的规则**不会触发**。

> ⚠️⚠️ **与维度 4「文件复杂度 + 复用封装」的边界（两条规则在 N=2 时直接冲突，必须按此判）：**
> 维度 4 写着「**3+ 次重复必抽**」与「**过度抽象禁令：3 次以下复用禁止抽**」，
> 而本维度在成员数 = 2 时就要求有公共外壳——**照维度 4 的字面，N=2 时抽外壳反而违规。**
> **判据分野在「家族性是不是已声明的事实」**：维度 4 那条管的是「同一段逻辑**偶然**出现了 N 次」
> （不知道将来还会不会有第 N+1 次，故用次数做保守阈值，立意是防「为两处偶然相似就造抽象」的反向超调）；
> **本维度管的是「这是一个已经确定还会继续加成员的家族」**——下一个成员**确定会来**，
> 不是从重复次数推断出来的猜测。**故：命中本维度（上游设计已声明该家族，或项目侧 `SIBLING-FAMILY:`
> 已登记）时，维度 4 的「3 次以下禁止抽」不适用**，⛔ 不得拿它去驳回本维度的公共外壳要求；
> 反之，**没有任何家族声明的两处偶然相似仍按维度 4 判**，⛔ 也不得拿本维度去要求抽象。
