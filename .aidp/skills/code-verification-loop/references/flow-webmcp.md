# 维度 9：WebMCP 前端能力实现合规（条件启用 · **Web 专项**）

> ★ **本文件仅 Web 客户端适用**；跨端的应用业务能力静态核对见 [`flow-client-mcp.md`](./flow-client-mcp.md)。
> `check_webmcp_adapter.py` 只判 **Web 前端入口**，⛔ 非 Web 的服务 / 桥接实现**不要传给它**。
>
> **本文件只在 `webmcp_enabled: true`（或归一后 `client_mcp.enabled: true` 且客户端 = Web、实现形态 = WebMCP）时适用。**
> ⚠️ Web 未启用时**只跳过本 Web 叶子**——非 Web 若已显式声明应用 MCP，维度 9 的**通用静态半场仍照跑**。
> ⛔ 两类能力都未启用才整维度跳过：不计入通过/不通过、不影响其它维度结论、不产生告警、不在验收报告里留行。
>
> ⚠️ **门控机制与技术栈门控维度 6/7/8 同类，但「留痕口径」更严，别照抄它们的处理方式**：
> 6/7/8 未命中技术栈时会在报告里标一行「跳过」；**本维度未启用时连行都不留**——「不占篇幅、
> 不在报告里留位置」是调用方给的硬前提，**标「跳过」也算留位置**。

## 一、门控与入参（本 SKILL 不自行探测）

| 入参 | 形态 | 说明 |
| :- | :- | :- |
| `webmcp_enabled` | `true` / `false` | Web 旧版兼容开关；新 Web + WebMCP 声明同样启用本叶子。⛔ 维度 9 的**通用半场不依赖它** |
| `webmcp_entry_symbols` | 数组 | 该项目**实测**的能力入口标识符，供本维度扫描定位。⚠️ 挂载位置已迁移过一次、规范仍在演进，**脚本与文档都不得写死任何一个名字** |

**⛔ 严禁本 SKILL 自行判定是否启用**——不 grep PRD、不扫代码里有没有相关标识符。**Why：判定
散落多处必然漂移，而一处判错就会给未启用的项目凭空长出 Critical。** 启用判定归调用方。

**⛔ 严禁把 `webmcp_entry_symbols` 写死进脚本或本文件。** 缺该入参时**报入参错（exit 2）而不是
猜一个默认值**——猜错的方向是「扫不到 → 0 命中 → 假绿」，正是本维度最不能出的错。

## 二、六项检查（全部静态分析，符合本 SKILL「不用跑起来」的立论）

### 9.1 单一适配层（🔴 Critical）

**判据：** `webmcp_entry_symbols` 里的标识符在前端源码里的**命中文件数必须 == 1**。

⚠️ **注释里写了也算命中** —— 否则 grep 形同虚设（下游实际触发过这条：第二处适配层被注释掉一半
留在文件里，按「只扫有效代码」的口径直接放行）。

**Why 是 Critical 而不是 Warn：** 一旦有第二处直接碰能力入口，「停用能否真正生效」「规范迁移时
要改几处」全部失控——这与维度 8「请求通道 URL 拼装单一信源」是同一类结构性缺陷，判的都不是
「这一处写对没写对」，而是**「这条判据有几份实现」**。

### 9.2 无「先登记后撤销」时序（🔴 Critical）

**两条判据：**

1. **登记调用不得早于配置就绪** —— 先登记再回头撤销是错的时序，中间那段窗口里工具是可调用的。
2. **代码里出现 `unregisterTool` 即 Critical** —— 实测该 API **不存在**。据草案臆想它存在会让
   撤销**静默失效**：下游曾用可选链（`?.`）做防御，于是撤销悄悄没生效、**文档与实际不符**，
   而代码看起来完全正常、没有任何报错。

> ⚠️ 第 2 条是纯词法判据、零主观，最适合脚本化。第 1 条须由验收 Agent 读时序（配置就绪信号
> 与登记调用的先后）人工核对。

### 9.3 错误契约无死文案（🟡 Important）

**判据：** 每个错误契约常量都有**实际使用面**（被引用到）。

⚠️ **新增一条错误文案时，须 grep 旧文案的全部使用点逐一判断该不该改** —— 只改「发现问题的
那一处」会留下**姊妹路径**（下游真实踩过：同一语义两套文案并存，其中一套永远走不到、另一套
还是旧的）。这与维度 3.7「出参字段变更消费点穷举」是同一类漏改形态。

### 9.4 写操作未绕开业务既有执行通道（🔴 Critical）

**判据：** 工具的写操作**必须复用业务既有的执行通道**，绝不另写一条。

**Why：** 另写一条的后果是「**手工操作能通、让助手做就不通**」（反之亦然），且两条链路的
**日志形态、参数校验、变量替换各不相同** —— 排查时两边现象对不上，定位成本极高。

### 9.5 敏感字段未经工具通道外泄（🔴 Critical）

**判据：** 凭据 / 密钥 / 令牌类的**值**一律不经工具通道返回，**包括脱敏片段**；只返回名称、
位置、作用域这类元信息。

> 「脱敏片段也不给」不是洁癖：调用方不可信（任何能在本页执行 JS 的主体都能调），而脱敏片段
> 在多次调用与交叉比对下会显著缩小猜测空间。

### 9.6 可调用对象用白名单而非黑名单（🔴 Critical）

**判据：** 业务对象有多种类型时，工具暴露的集合**必须白名单列举可调用类型**。

**⛔ 黑名单会随类型增加而失效** —— 新增一个类型、忘了加进黑名单，它就自动变成可调用的，
助手拿它执行会产生**意外副作用**。

**⚠️ 列表、详情、执行三处须共用同一判据**，**任一处放行即构成绕过**（典型形态：列表按白名单
过滤了，执行入口却只按 ID 取对象、没再判类型）。

## 三、硬门脚本

前两项（单一适配层、`unregisterTool`）是纯词法、零主观，已脚本化：

```bash
# 基本用法：传入实测的能力入口标识符 + 前端源码目录
python3 <SKILL_DIR>/scripts/check_webmcp_adapter.py <前端源码目录> \
    --entry-symbols <符号1> <符号2> ... --json

# 已声明单一适配层文件时，口径收紧为「信源之外一处都不许有」
# ⚠️ glob 基准是**仓库根**（向上找 `.git`），不是你传的扫描目录
python3 <SKILL_DIR>/scripts/check_webmcp_adapter.py <前端目录> \
    --entry-symbols <符号1> --allow 'code/frontend/web/src/webmcp/adapter.ts'
# 验收推荐带 --strict：让「超限 / 不可读」这类未参与检查的缺口也卡住闸门
python3 <SKILL_DIR>/scripts/check_webmcp_adapter.py <前端目录> --entry-symbols <符号1> --strict
```

**退出码：** `0` = 闸门通过（含「扫不到前端源码 → 整维度跳过」）/ `1` = 未通过 / `2` = 入参或
环境错（路径不存在、缺位置参数、`--entry-symbols` 未传或为空、`--max-file-bytes` 非正、
显式传的文件全不在可扫类型内、**`--allow` 一个 glob 都没匹配上**）。

**三类会被判 error 而不是「放行」的情形（都是实测踩出来的假绿方向）：**

| 情形 | 判 | Why |
| :- | :-: | :- |
| **0 命中入口标识符** | 🔴 error | 本脚本仅在 `webmcp_enabled: true` 时调用 = 该项目**确实有**这个能力。0 命中只有「符号过期」「路径传错」两种解释，**没有一种是合规**。判 warn 的话默认口径下 `gate_passed=true`，等于符号写错就全绿 |
| **`--allow` 命中 ≥2 个文件** | 🔴 error | 9.1 的判据就是「命中文件数必须 == 1」，声明两个信源本身即违反。否则 `--allow '*'` 直接把整道闸门关掉 |
| **超限 / 不可读文件** | 🟡 warn（`--strict` 下卡闸门） | **不等于干净**——里面若有第二处适配层或 `unregisterTool` 一律看不见。早期只登记不告警，`errors`/`warns` 双空，连 `--strict` 都放行 |

**`--json` 字段：** `{passed, gate_passed, strict, skipped, skip_reason, repo_root, scanned_files,
entry_symbols, hit_sites, distinct_files, distinct_file_list, single_source,
allow_matched_files, allow_unmatched_globs, unregister_sites, skipped_large,
unreadable_files, errors, warns}`（19 个，与脚本 `result` 一一对应）
——**判「过没过」读 `gate_passed`**（`--strict` 下 WARN 也计入）；`skipped=true` 表示未扫到
前端源码、整维度跳过，**不等于通过**，报告里须如实标「跳过（原因）」；`single_source` 在
`--allow` 模式下回落为那个**唯一**已声明信源（声明了多个则为 `null` 并同时判 error）。

**扫描面：** `.ts/.js/.mjs/.cjs/.mts/.cts/.tsx/.jsx/.vue/.html`，**含 `.html`**（登记写在
`index.html` 内联 `<script>` 里是很自然的形态）、**不跳过 `public/`**（其中的文件被原样拷进产物、
照样会执行登记）。这与「注释也算命中、`.vue` 整篇扫」是同一条从宽口径：本维度判的是**这条判据
有几份实现**，任何一份写在哪都算。

**`unregisterTool` 零豁免是刻意的。** 项目若自己封装了一个同名辅助函数（靠重登记全量来实现
撤销），照样判 Critical —— **名字本身就在误导读者「这个 API 存在」**，而这正是本条要堵的认知
错误。正确处置是**改名**（如 `revokeAllAndReregister`），而不是给脚本开豁免口子。

**覆盖边界（别当已查）：** 脚本只做 9.1 与 9.2 的第 2 条。**9.2 的时序、9.3~9.6 四项须由验收
Agent 静态读代码人工核对**——脚本全绿 ≠ 维度 9 通过。
