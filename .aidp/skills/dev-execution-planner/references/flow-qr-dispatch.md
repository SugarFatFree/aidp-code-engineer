# 质量检查派发流程(QR Dispatch)

> 本文件是 `SKILL.md` 的 QR **派发流程**分片(bash 硬核回检命令 + 子 Agent prompt + 循环终止),按需 Read。
> **14 维度清单本身不在这里**,在 [`quality-review-checklist.md`](./quality-review-checklist.md) —— 两者互补:清单是「查什么」,本文件是「谁来查、怎么派、跑哪些脚本」。

## Post-Generation Quality Review (执行计划生成后独立 Agent 检查)

**强制要求:研发执行计划生成后,必须调用一个独立的 Agent 执行 14 维度质量检查(始终必查 12 项 + 多用户/多文件模式各 +1),核验三方一致性、完备性、可执行性和上游溯源完备性。**

> 🧹 **执行主体与上下文隔离(Critical):** 本节全部检查——`🛡️ 落盘后 bash 硬核回检` 的脚本 **+** 14 维度语义审查——一律在**独立子 Agent**内完成。主流程**禁止**在当前对话上下文内联跑脚本或内联逐维度自查(脚本输出与逐项核对会挤占/污染主上下文)。主流程只负责:① 派发子 Agent(传入执行计划/PRD/详细设计/原型路径);② 接收子 Agent 回传的**精简结构化报告**(含每个脚本退出码 + 各维度通过/不通过 + 修订建议);③ 据报告决定修订并重新派发,循环至全部通过或达 3 轮上限。

### 🛡️ 落盘后 bash 硬核回检(子 Agent 强制第一步,先于语义维度审查)

**执行计划落盘后,以下 bash 脚本由下方派发的**质量检查子 Agent**作为强制第一步执行(见子 Agent prompt 步骤 0),任一命中即拒绝标记完成、强制重写违规段落。主流程**禁止**在当前上下文内联运行这些脚本:**

> **`<SKILL_DIR>` 占位符:** SKILL 实际安装位置(本项目 = `{{AIDP_HOME}}/skills/dev-execution-planner`),由子 Agent 在执行前替换。

```bash
# 1. 任务粒度 + AI 锚点 + 9 列任务表 + 链接合规(退出码 1 = 判错,分档看 --json severity;2 = 入参错)
python3 <SKILL_DIR>/scripts/check_task_granularity.py <研发执行计划路径>

# 2. 命名规范 + 子目录嵌套(平铺硬门) + 碎片检测 + Task 编号全局唯一(多文件模式)
#    注:中文文件名判据在 check_sql_path_handoff.py(P3),不在本脚本
python3 <SKILL_DIR>/scripts/check_doc_split.py <执行计划目录> --check-tasks

# 3. SQL 路径交接一致性(详细设计 → 执行计划 SQL 落地路径对齐)
python3 <SKILL_DIR>/scripts/check_sql_path_handoff.py <研发执行计划路径>
```

**脚本搬进子 Agent 后仍然必跑(护栏不变)**,只是改由子 Agent 在其上下文内确定性执行、回传退出码,主上下文不被脚本输出占用。**严禁**子 Agent 只做语义维度审查而跳过本 bash 步骤。

### 执行方式

使用 Claude Code 的 Agent 工具派发独立检查任务(推荐 `subagent_type: general-purpose`),传入:
- 生成的执行计划文档路径
- PRD 文档路径(最高准则)
- 详细设计文档路径
- 原型文件路径

```
调用示例:
Agent({
  description: "执行计划质量检查",
  subagent_type: "general-purpose",
  prompt: "你是一位资深 Tech Lead + 项目经理。请对 {执行计划路径} 执行 14 维度质量检查(始终必查 12 项 + 多用户/多文件模式各 +1),对照 PRD {PRD路径}、详细设计 {设计路径}、原型 {原型路径}。

  执行步骤(必须按顺序):
  0. **(先于一切,强制)** 逐个运行本 SKILL『🛡️ 落盘后 bash 硬核回检』列出的全部脚本(将 <SKILL_DIR> 替换为本 SKILL 实际安装目录),把**每个脚本的退出码 + 报告正文原样贴进报告**作为证据。**退出码判定按全仓统一约定(见 CLAUDE.md):0=通过或 N/A 跳过 / 1=检出违规 / 2=入参或环境错(非维度违规、不计失败);严重度分档一律读 `--json`,不占退出码**:
     - `check_task_granularity.py`:0=通过;1=判错(含两档:警告=疑似粗粒度 / EPIC 缺端 / AI 锚点不足;**必修**=确证粗粒度 / 旧版 6 列任务表 / 9 列任务表行三锚点不全);2=输入路径错误(修正参数后重跑,**非维度违规、不计失败**)。⚠️ **两档靠退出码分不出**——必须读 `--json` 的 `findings[]`(**顶层是对象**,含 `scanned_tasks`/`skipped`/`findings`)每条的 `severity`;⚠️ **先看 `skipped`**——`true` 表示一个 Task 段都没识别到、本次并未实质核验,不等于通过:`2`=必修(维度 3/14 不通过)/ `1`=警告(需复核修订)。严重度不占退出码是全仓统一约定,见 CLAUDE.md。注:旧版 6 列任务表命中即 `severity=2`(硬拦),勿当作可放行的软警告
     - `check_doc_split.py --check-tasks`(**多文件模式专用**,传执行计划**目录**):0=通过(含仅历史 grandfather 告警 warn:裸单文件 / 历史 `00_*-总览.md` 主锚 / `NN_补充-` 中缀均放行不硬失败);1=不通过(维度 11 多文档拆分:缺主锚 / 序号缺失 / 碎片 / 裸「补充-」开头等 error);2=**路径不存在或既非文件也非目录**(入参错);⚠️ **传入单个 .md 属合法单文件模式,返回 0 + `skipped:true`,不是 2**——二者曾共用 exit 2,而本条口径把 2 当「不计失败」,于是路径打错即整档闸门静默消失。现行规范主锚为 `00_索引.md`(内容主文档从 `01_研发执行计划.md` 起);单份内容目录仍需 `00_索引.md` + `01_*` 两文件
     - `check_sql_path_handoff.py`:0=通过;1=不通过(维度 9 详细设计 SQL 路径交接);2=输入路径错误(修正后重跑)
     除上述「N/A 跳过」与「输入路径错误」外,任一脚本判不通过即对应维度直接判不通过,无需再做语义判断;
     ⚠️ **哪个维度由哪个脚本判、哪些脚本刻意没接进来** → 见 checklist 顶部「维度成本与裁剪索引表」;
     ⛔ 别把 `check_service_impl_stub.py` / `check_third_party_dep_reverse.py` / `scan_aidp.py` /
     `scan_mock_data.py` 塞进本步骤——它们的入参是**被测项目源码根**,传文档目录只会
     「没扫到文件 → exit 0」,那是 N/A 跳过、**不是通过**,塞进来等于凭空多四个恒绿灯;
  1. 读取 PRD,提取所有功规点(五、页面交互明细)、字段规格(六、数据字段)、状态机(七、字典枚举);
  2. 读取详细设计,提取接口定义(A.2)、数据库 Schema(A.3)、技术栈(A.1)、功规点实现映射(B.1);
  3. 读取执行计划,提取所有 Task、Phase、前置依赖、验收标准、AI 执行指令;
  3'. **(本轮范围,先判后做)** 读 checklist 顶部「QR 变更范围裁剪协议」。本轮 `qr_delta_scope` = {未传则全量}。
     **机器门一律全量跑**;标「全量」档的维度(6 依赖链条 / 7 框架中间件 / 10 / 11 / 13 / 14 EPIC 完整性)
     **不接受裁剪**——环由新旧 Task 共同构成、缺端也只有端到端看才看得出,裁了等于精准关掉增量最需要的两道门;
     语义/口径类变更**强制扩散**到受影响 Phase/Task;算不出 Δ **退回全量并注明**;
  4. 对照 14 个维度逐项检查(始终必查 12 项 + 条件触发 2 项):
     - 维度 1:三方一致性深度核验(PRD → 详细设计 → 执行计划覆盖度,冲突项识别)
     - 维度 2:详细设计完备性评估(数据库 Schema、接口定义、算法逻辑、外部依赖)
     - 维度 3:迭代粒度与 AIDP 范式对齐(阶段划分、任务命名、目录结构、产出物类型)
     - 维度 4:指令化(Command-Driven)检查(5 级优先级:AIDP 命令 > 项目 .claude/ > 系统 Claude Code > 通用工具 > Shell)  <!-- runtime-path-ignore: 指 Agent 自身目录这一概念，非运行契约路径，两包均保持原样 -->
     - 维度 5:提示词(Prompt)的上下文关联性(每个 Task 的 AI 执行指令是否包含必要上下文)
     - 维度 6:依赖链条与前置条件核对(无循环依赖、依赖链合理、前置条件明确)
     - 维度 7:代码框架与中间件配置检查(框架初始化、中间件配置、依赖安装指令完整)
     - 维度 8:增量开发与回归验证指令(每个 Task 包含增量开发步骤和回归验证指令)
     - 维度 9:详细设计一致性深度核验(执行计划与详细设计的接口/数据表/字段/枚举完全一致)
     - 维度 10:多用户分配一致性(仅多用户模式触发,否则标 N/A)
     - 维度 11:多文档拆分一致性(仅多文件输出模式触发,否则标 N/A)
     - 维度 12:上游引用完整性 — 四源追溯(主文档/子文档/每个 Task 的 PRD/原型/设计/产品文档/高保真溯源)
     - 维度 13:待澄清问题清单完整性(不中断原则的强制落地)
     - 维度 14:EPIC 完整性 + AI 指令上下文锚点透传(EPIC 三类小节、任务表 9 列、链接合规)
  5. 针对每个维度输出【通过/不通过 + 具体问题 + 修订建议 + 引用证据(Task ID/PRD章节/设计章节)】;
  6. 不通过项必须给出具体到 Task ID 或 PRD 章节的修订建议。

  原则:只读审查,严禁改动文档;输出结构化检查报告,**强制附一张「QR 执行台账」**(格式见 checklist 同名小节):
  逐维度写明 `本轮范围(全量/Δ/前滚/基线缩放/N/A) | 机器门退出码 | 语义结论 | 依据`,**14 行一行不少**——
  **条件维度 10(多用户)/11(多文件)未触发时照样留行**,写明 `N/A + 触发条件为何不满足`;
  脚本返回 `skipped:true` 属**跳过不是通过**,台账里记 `N/A`、⛔ 不得记「通过」;
  标「前滚」的行必须写明依据的上一轮报告,写不出来一律按**未跑**处理、退回该维度全量核对。"
})
```

主流程根据检查报告修订计划,再次调用检查 Agent,循环至全部通过或达到 3 轮上限。

**⚠️ 阻塞完成规则(Critical):**
- Quality Review **全部通过**后,SKILL 才可标记任务完成并向用户报告"执行计划已生成"
- 若 3 轮后仍有**不通过项**,SKILL **禁止**标记完成,必须:
  1. 向用户输出最终一轮的检查报告(含不通过维度 + 具体问题 + 修订建议)
  2. 明确告知"以下维度未通过,需人工介入或追加修订"
  3. 等待用户指示(用户可选择豁免某维度、手动修复、或要求继续循环)
- **严禁**在 QR 未通过的情况下静默结束、跳过报告、或声称"执行计划已完成"

### 14 维度检查清单(始终必查 12 项 + 条件触发 2 项)

> 📎 **必读：** Quality Review Agent 执行检查前，必须读取 `references/quality-review-checklist.md` 文件。该文件包含 14 维度的详细检查项、检查报告输出格式、循环终止条件。不读取该文件无法执行完整的质量检查。

**始终必查 12 项:**
1. 三方一致性深度核验（PRD → 详细设计 → 执行计划）
2. 详细设计完备性评估
3. 迭代粒度与 AIDP 范式对齐
4. 指令化（Command-Driven）检查
5. 提示词（Prompt）的上下文关联性
6. 依赖链条与前置条件核对
7. 代码框架与中间件配置检查
8. 增量开发与回归验证指令
9. 详细设计一致性深度核验
12. 上游引用完整性 — 四源追溯(**Critical 强制项**)
13. 待澄清问题清单完整性(**Critical 强制项**,不中断原则的强制落地)
14. EPIC 完整性 + AI 指令上下文锚点透传(**Critical 始终必查**)

**条件触发 2 项(按场景启用):**
- 10. 多用户分配一致性(仅多用户模式触发)
- 11. 多文档拆分一致性(仅多文件输出模式触发)

完整的检查项逐项展开、不通过示例、检查报告模板、循环终止条件请查阅 `references/quality-review-checklist.md`。
