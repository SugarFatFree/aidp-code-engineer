# 技术栈命令细则 · 按需加载索引

> **为什么拆**：本 SKILL 的**跨技术栈通用**规则（Task 拆分粒度、EPIC 完整性、依赖关系、验收标准写法、AI 锚点透传、字段处置 → 独立 Task）写在 `SKILL.md`；**语言/框架专有的命令**（脚手架生成、开发期轻量验证、单测、构建、依赖安装）拆在本目录 `stack-*.md`。生成执行计划时**按项目已选技术栈只加载命中的 1~2 份**，不要全量读。

## 探测 → 加载

| 探测信号（任一命中） | 技术栈 | 加载文件 |
| :- | :- | :- |
| `*.java` + `pom.xml` / `build.gradle` | Java / Spring | `stack-java-spring.md` |
| `*.vue`，或 `package.json` 依赖含 `vue` | 前端 Vue | `stack-vue.md` |
| `*.jsx`/`*.tsx`，或 `package.json` 依赖含 `react` | 前端 React | `stack-react.md` |
| `package.json` 依赖含 `express`/`koa`/`@nestjs/core` | Node.js 后端 | `stack-nodejs.md` |
| `go.mod` | Go | `stack-go.md` |
| `requirements.txt` / `pyproject.toml` + `*.py` | Python | `stack-python.md` |

前后端分离项目通常**同时命中 1 个后端栈 + 1 个前端栈**，两份都加载。若详细设计已给出技术栈选型，直接按选型加载、无需探测。

## 各文件覆盖什么

每份 `stack-*.md` 统一给出四类命令，供写进 Task 的「执行步骤 / 验收标准 / AI 执行指令」：

| 类别 | 用途 |
| :- | :- |
| **脚手架生成** | 建工程骨架、生成 CRUD 模板的命令 |
| **开发期轻量验证** | ⚠️ **Task 验收标准里该写的就是这一类**——只做类型/语法检查，**禁全量 build** |
| **单元测试** | Phase 2 核心业务逻辑验证 |
| **依赖安装 / 构建** | 依赖安装命令；构建命令**仅供发布/部署期（CICD）参考，不写进开发期 Task** |

## ⚠️ 贯穿全栈的铁律：开发期验证 ≠ 发布期构建

- **开发期验证**（Task 验收标准、骨架校验任务）：只跑**轻量类型/语法检查**（秒级~十几秒）
- **发布/部署期构建**（构建机 / CICD，非开发期 Task）：才用完整打包命令（分钟级）

把全量 build 写进开发期 Task 的验收标准，会让每个 Task 的验证耗时翻几十倍、拖垮迭代节奏。**前后端对称适用**，各栈的具体命令见对应文件。
