# 兜底与中断护栏细则(不臆造 / 不中断)

> 本文件是 `SKILL.md` 两条 Critical 护栏原则的细则分片,按需 Read。**灰区判据(什么算允许的兜底、什么算臆造)全在这里**,骨架只留结论。

## ⚠️ 不臆造兜底原则(Critical)

**PRD/需求文档中没有明确说明"需要兜底/容错/默认值/降级方案"的地方,详细设计中严禁自行增加任何形式的兜底数据源、缺省回退、容错降级、默认值注入。**

> 🔗 **与核心原则 23.2「降级须注明理由与范围」的衔接:** 本原则禁的是**PRD 没说就自作主张加降级**;核心原则 23.2 要求的是**确需降级时必须就地写明理由 + 范围 + 用户可感知性**。二者不冲突——先过本原则(该不该降级),再过 23.2(降级怎么写清楚)。**未写明理由与范围的降级 = 臆造兜底**。

❌ **严禁臆造的兜底类型**:
- **数据源兜底**: PRD 没说"接口失败时显示默认数据",不要在详细设计中加"接口异常时回退到本地静态列表 / 上次缓存 / 内置示例数据"
- **Mock 兜底**: 严禁在前后端任意层加"真实接口失败时回退到 mock 数据",这与 `code-verification-loop` 维度 2 零 Mock 容忍直接冲突
- **字段兜底**: PRD 没说"为空时显示 N/A",不要在 A.3/B.2 中默认所有字段加"NULL → 横线/空字符串/0"
- **业务规则兜底**: PRD 没说"未配置时按某规则",不要在 B.1 自己加"如未配置审批流则默认走单级审批"
- **权限兜底**: PRD 没说"无权限时如何处理",不要在 B.1 加"无权限时显示降级视图/只读模式"
- **状态兜底**: PRD 没说"枚举外的值如何处理",不要在 A.4 加"未知状态显示为'其他'"
- **加载兜底**: PRD 没说"加载失败的容错",不要在前端章节加"加载失败显示骨架屏 + mock 列表"
- **数据库默认值兜底**: PRD 没说"该字段需要默认值",不要给 NOT NULL 字段任意加 `DEFAULT` (与核心原则 8「字段宽容原则」呼应:NOT NULL 必须有充分理由,DEFAULT 同样需有业务依据)
- **🔗 第三方接口参数臆造**: 第三方/外部接口只有 URL、缺入出参契约时,严禁按命名习惯臆造入参/出参参数名(`startDate/endDate`、`pageNo/pageSize`、`code/msg/data` 等),必须走 D-NNN 待澄清 + 主动询问(详见核心原则 19「第三方接口入出参契约不臆造铁律」)

✅ **正确做法**:
- 严格按 PRD/详细设计上游已写明的规则实现,PRD 未覆盖的边界**走「不中断原则」流程**: ❓ 待澄清 + 🔧 暂行方案(Agent 推断) + 汇总到 Module E
- Agent 推断的兜底**必须**显式打标 `🔧 暂行方案(Agent 推断): [方案]`,**不得**与 PRD 已确认内容混排成"事实需求"
- 推断为"无兜底"也是合理结论(行业惯例是"快速失败 + 错误提示")——若行业惯例是无兜底,暂行方案直接写"无兜底,失败抛出标准错误码,由前端按统一错误处理章节展示"
- 异常处理章节(B.x 异常路径)与"兜底"严格区分:**异常处理 = 出错后的告知/恢复路径**(必须有,本身就是设计职责);**兜底 = 用替代数据假装成功**(无 PRD 明示禁加)

**Why:** 设计中臆造的兜底会:
1. **改变业务语义** — "无数据"和"接口失败显示示例数据"用户体验完全不同,但代码表现一样,产品验收时无法分辨真假需求
2. **掩盖真实故障** — Mock 兜底/缓存兜底会让生产故障在监控里隐身,延误发现
3. **触发下游违规** — 详细设计写了 mock 兜底,代码必然实现,直接违反 `code-verification-loop` 维度 2 零 Mock 容忍,验收阶段反复返工
4. **虚假的需求蔓延** — 详细设计 → 执行计划 → 代码,每层都会按"已设计"实现,最后产品发现"我没要这个功能但你们做了"

**例外:** PRD 明确写了"接口异常显示默认 XX / 缺失时使用 XX / 失败时降级到 XX"等字样,正常引用 PRD 章节并实现即可。

### ✅ "数据源兜底"与"空状态 UI 展示推断"的区别(允许的灰区)

**严格区分两种情况,后者属于合理 UI 推断,无需 PRD 明文授权:**

| 类型 | 是否允许臆造 | 说明 | 示例 |
| :- | :-: | :- | :- |
| **数据源兜底**(本原则禁止) | ❌ 禁止 | 数据为空/接口失败时,**用替代的真实数据假装有数据**,改变业务事实 | 接口失败 → 显示上次缓存 / 显示静态示例 / 回退 mock 接口 |
| **空状态 UI 展示推断**(允许) | ✅ 允许 | 数据真的为空时,设计**给用户的视觉反馈/文案**,不替代数据 | 列表为空 → "暂无数据"插画 + 居中布局;搜索无结果 → "未找到匹配记录"文案 + 引导操作按钮 |
| **加载中状态推断**(允许) | ✅ 允许 | 数据真在加载时,设计**过渡态的视觉表现**,不替代数据 | 列表加载中 → 骨架屏 / 旋转 loading;详情页加载 → 占位卡片(无内容) |
| **错误反馈推断**(允许) | ✅ 允许 | 失败时**告知用户错误并提供恢复路径**,不替代数据 | 接口失败 → 错误 Toast + 重试按钮 + 错误码展示 |

**判断口诀:** "用真实数据替代不存在的数据 → 数据源兜底(禁);告诉用户没数据/在加载/出错了 → UI 展示(允许推断)"

**允许推断的常见 UI 兜底场景**(无需 PRD 明文授权,但建议在设计中标注"空状态 UI 推断,可后续按设计规范统一"):
- 列表/表格为空 → 空状态插画 + "暂无数据"文案 + 可选的"创建/添加"引导按钮
- 详情页数据缺失 → 占位卡片 + "数据不存在"文案 + 返回上一级按钮
- 搜索/筛选无结果 → "未找到匹配结果"文案 + 清空筛选条件按钮
- 加载中 → 骨架屏 / Spinner / 进度条
- 接口失败(非业务错误) → 错误 Toast + 重试按钮(注意:**不显示替代数据**)
- 长文本/列表截断 → "查看更多" / 分页加载

**不允许推断的常见数据源兜底**(必须 PRD 明文授权或 Module E 暂行方案):
- 接口失败显示上次成功的缓存数据
- 接口失败回退到本地静态数组/示例数据
- 字段缺失时填充业务默认值(如"未填写省份默认为北京")
- 枚举值越界时归类为"其他"
- 配置项缺失时按某默认规则执行(如"未配置审批流默认走单级")

**质量检查:** 详见 `references/quality-review-checklist.md` 检查项 19「不臆造兜底(Critical)」
