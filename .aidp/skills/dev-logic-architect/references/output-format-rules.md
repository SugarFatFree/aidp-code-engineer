> 本文件隶属于 `dev-logic-architect` SKILL，供 `flow-output-format.md`章节生成详细设计文档时按需查阅。
> 上级文档：`../SKILL.md` > 「输出规范」
>
> **使用说明：** 本文件收录多文件拆分模式下的**目录结构骨架、主/子文档骨架、字典枚举索引/子文档示例、跨文档引用与拆分一致性检查表**等"按需查阅的格式骨架"。
> `flow-output-format.md`正文保留拆分触发条件、命名约束、碎片化/职责边界等所有 Critical/必须/禁止规则；具体骨架与示例落在本文件。
> 多文件拆分一致性的**权威审查维度**仍以 `quality-review-checklist.md` 检查项 12 为准，本文件中的检查表为生成期的格式自检参考。

## 命名形态总览(新生成 = 索引态(唯一);单份态·总览态·并列态 = 历史 grandfather)

> **AIDP 命名范式**:`00_` 槽位恒给专职索引 `00_索引.md`,内容主文档一律从 `01_` 起。**新生成一律走索引态**——即便只产 1 份内容文档,也产 `00_索引.md` + `01_<专题>.md`(≥2 文件)。**单份态 `00_<专题>.md` / 总览态 `00_*_总览.md` / 并列态裸名 = 历史存量兼容形态,新生成不再产出**。`check_doc_split.py` grandfather 识别放行历史存量(warn、exit 0);**`00_` 槽位唯一、任一时刻目录内 `00_` 文件唯一 = `00_索引.md`**。

| 形态 | 触发条件 | 主锚命名 | 正文/分册命名 | 示例 |
| :- | :- | :- | :- | :- |
| **索引态(新生成唯一)** | 所有新生成(1 份或 ≥2 份内容文档) | `00_索引.md`(专职索引,`00_` 槽位恒给它) | `01_..98_<中文>.md` 内容主文档(`98_事实清单.md` 代码事实基线保留位,如有)+ `99_待澄清问题清单.md` | `00_索引.md` + `01_详细设计.md` + `02_接口设计.md` + `03_数据库设计.md` + `98_事实清单.md`(如有)。**只有一份内容**时:`00_索引.md` + `01_详细设计.md` |
| **单份态 ⚠️ 历史 grandfather** | (仅存量)目录恰 1 份 `00_<专题>.md` | `00_<专题>.md`(`00_` 即主文档本体) | — | `00_详细设计.md`(**新生成改走索引态 `00_索引.md` + `01_详细设计.md`**) |
| **总览态 ⚠️ 历史 grandfather** | (仅存量)主锚为 `00_*_总览.md` / `00_*-主文档.md` | `00_*_总览.md`(`00_` 让位给总览) | `01_..` 分册 | `00_{项目名}_详细设计方案_v{版本号}_总览.md` + `01_..`(**新生成统一 `00_索引.md`**) |
| **并列态(约定15)⚠️ 历史 grandfather** | (仅存量)同目录并列 ≥2 份专题主文档、无任何 `NN_` 序号文件 | 各份**裸中文名、不加 `00_`**(grandfather 放行) | — | `详细设计.md` + `接口设计.md` + `数据库设计.md`(**新生成改走索引态,不再产出**) |

**`00_索引.md` 三项必载**:① 全部内容文档(`01_`+)清单 + 每份一句话范围;② 每份文件生成时间(`YYYY-MM-DD HH:MM`,区分首次产出/最近修订,用 shell `date +"%Y-%m-%d %H:%M"` 打戳,**AI 不得凭空填**);③ 主/补充标识(首产=「主」,`--supplement` 增量=「补充」)。建议列 `| 序号 | 文件 | 生成时间 | 类型 | 说明 |`;补充轮再加 `关联输入变更 | 状态 | 取代关系` 列。

**补充文档(`--supplement`)**:文件名**不带「补充」字眼**,直接 `NN_<业务名>.md`(序号顺延);`--supplement` 给 `00_索引.md` 追加一行(类型=补充 + 生成时间),不改内容主文档正文。

> 下文「目录结构」「专职索引必备内容」等骨架均以**索引态**为例;历史单份态/总览态/并列态仅存量兼容,新生成不再产出。

## 目录结构

```
docs/design/{项目名}/
├── 00_索引.md                                     # 专职索引(导航入口,必需,00_ 槽位恒给它)
├── 01_技术架构与基础框架.md                      # Module A.1-A.2
├── 02_数据库设计.md                              # Module A.3(单文件,数据表少时)
│   或按业务域拆分(数据表多时):
│   ├── 02_用户域数据表.md                       # Module A.3 用户域
│   ├── 03_订单域数据表.md                       # Module A.3 订单域
│   └── 04_商品域数据表.md                       # Module A.3 商品域
├── 05_字典与枚举定义.md                          # Module A.4(单文件,字典枚举少时)
│   或按业务域拆分(字典枚举多时):
│   ├── 05_字典与枚举索引.md                    # Module A.4 索引主文档(必需)
│   ├── 06_用户域枚举.md                        # 用户类型/性别/状态/角色...
│   ├── 07_订单域枚举.md                        # 订单状态/支付方式/物流状态...
│   ├── 08_商品域字典.md                        # 商品分类/品牌/规格...
│   └── 09_全局通用字典.md                      # 是否启用/审批状态/通用排序...
├── 10_功规点实现映射.md                          # Module B.1
├── 11_内部接口契约.md                            # Module B.2 内部接口(需登录)
├── 12_对外开放接口.md                            # Module B.2 对外接口(免登录,可选)
├── 13_接口索引.md                                # Module B.2 接口索引(可选,接口超过30个时)
├── 14_异常处理与容错.md                          # Module B.3
├── 15_性能与边界设计.md                          # Module B.4
├── 16_状态机模型.md                              # Module B.5
├── 17_存量数据兼容.md                            # Module B.6
├── 18_外部依赖与集成.md                          # Module B.7
├── 19_测试方案.md                                # Module C
├── 20_版本归档.md                                # Module D
└── 99_待澄清问题清单.md                          # Module E(如有,序号固定 99,永远最后)
```

**注意**：上述序号仅为示例，实际生成时根据模块组合灵活调整。例如：
- 数据库设计单文件时：`02_数据库设计.md`(占用序号 02)
- 数据库设计按业务域拆分时：`02_用户域数据表.md`、`03_订单域数据表.md`...(占用多个序号)
- 后续文件序号接着上一个文档序号自动累进(不跳号,不嵌套二级序号)

## 字典/枚举拆分的索引与子文档骨架

> 字典/枚举单独拆分的判定条件与拆分原则见 `flow-output-format.md`正文。以下为索引主文档与子文档的格式骨架。

**字典枚举索引主文档(`05_字典与枚举索引.md`)必备内容**:

```markdown
# A.4 字典与枚举定义(索引)

> **隶属**: 详细设计方案 v{版本号} > Module A.4
> **专职索引**: `00_索引.md`

## 字典/枚举全局清单

| 名称 | 类型 | 业务域 | 编码空间 | 定义文件 | 关联表.字段 | 关联状态机 |
|------|------|--------|---------|---------|------------|-----------|
| OrderStatus 订单状态 | 枚举 | 订单 | 1-9 | `07_订单域枚举.md > 订单状态` | biz_order.status | B.5 订单状态机 |
| PaymentMethod 支付方式 | 字典 | 订单 | PM_xxx | `07_订单域枚举.md > 支付方式` | biz_payment.method | — |
| UserStatus 用户状态 | 枚举 | 用户 | 0-3 | `06_用户域枚举.md > 用户状态` | biz_user.status | B.5 用户状态机 |
| ProductCategory 商品分类 | 字典 | 商品 | 树形 | `08_商品域字典.md > 商品分类` | biz_product.category_id | — |
| ... | ... | ... | ... | ... | ... | ... |

## 跨文档引用规则

- 其他设计文档引用字典/枚举时,必须用以下格式:
  - 短引用: `参考 A.4 OrderStatus`(适合专职索引 `00_索引.md` 的索引中)
  - 完整引用: `参考 ../07_订单域枚举.md > 订单状态(L80-L120)`(子文档间)
- 引用必须可定位:文件存在 + 章节存在 + 行号(若已确定)正确
```

**子文档(如 `07_订单域枚举.md`)规范**:

```markdown
# A.4.x {业务域}枚举/字典定义

> **版本**: v{版本号}
> **隶属**: Module A.4 字典与枚举 > {业务域}
> **索引主文档**: `05_字典与枚举索引.md`
> **PRD 来源**: [§字典枚举章节](../requirements/{version}/研发需求/xxx.md#章节锚点)

## OrderStatus 订单状态(枚举)

> **应用场景**: biz_order.status 字段;前端订单列表筛选/详情展示
> **关联状态机**: 详见 `../16_状态机模型.md > B.5 订单状态机`

| code | label | 业务含义 | 颜色(color,状态类必填) | 排序 | 是否默认 | 备注 |
|------|-------|---------|----------------------|------|---------|------|
| 1 | 待支付 | ... | 橙色 | 1 | ✅ | ... |
| ... | ... | ... | ... | ... | ... | ... |

**代码契约(Critical 强制小节,所有字典/枚举无一例外都必须填写)**:

| 项目 | 要求 |
|------|------|
| 后端枚举类名 | `OrderStatusEnum` |
| 后端文件路径 | `src/main/java/com/{project}/enums/OrderStatusEnum.java` |
| 前端枚举/常量类名 | `OrderStatus` |
| 前端文件路径 | `src/enums/orderStatus.ts` |
| 前端定义方式 | TypeScript `enum` 或 `as const` |
| 数据库映射方式 | MyBatis `TypeHandler` / JPA `@Convert` |
| Mapper/ORM 引用 | A.3 枚举字段 COMMENT 引用本枚举类(如 `参考 OrderStatusEnum`) |
| 前后端 code/label 对齐 | code 完全一致;label 完全一致 |

**前后端对齐方案**: ...

## PaymentMethod 支付方式(字典)
...
```

> ⚠️ **拆分模式同样不豁免「错误契约」5 列**(见 `output-module-examples.md` B.2 / `quality-review-checklist.md` 检查项 31)。接口子文档(`11_内部接口契约.md` / `12_对外开放接口.md`)里**每个接口**都必须原样带上 `| 错误码 | HTTP Status | 触发条件 | 面向用户的中文提示 | 失败/降级行为 |` 小节——`check_error_contract.py` 是按**接口章节**逐个查的,拆到子文档里照样查得到、照样判不通过。模板见 `../assets/api-template.md`。

> ⚠️ **拆分模式同样不豁免「代码契约」8 项**(见 `output-module-examples.md` A.4.3 / `quality-review-checklist.md` 检查项 11)。子文档模板里必须原样带上这张表——`check_enum_contract.py` 是按**枚举条目**逐条查的,拆到子文档里照样查得到、照样判不通过。

**跨文档引用的硬性要求**:

| 引用方 | 引用方式 | 示例 |
|-------|---------|------|
| 专职索引(`00_索引.md`)引用 | `参考 05_字典与枚举索引.md` | `字典/枚举完整定义见 05_字典与枚举索引.md` |
| A.3 数据表文档引用枚举 | `字段值 → 参考 ../07_订单域枚举.md > 订单状态` | `status TINYINT NOT NULL COMMENT '订单状态(参考 07_订单域枚举 > OrderStatus)'` |
| B.1 功规点引用枚举 | `状态流转 → 参考 ../07_订单域枚举.md > 订单状态` | `订单状态变更需校验 OrderStatus(详见 07_订单域枚举.md > 订单状态)` |
| B.2 API 契约引用枚举 | `字段枚举值 → 参考 ../07_订单域枚举.md > 订单状态` | `Response.status: integer(枚举值参见 07_订单域枚举.md > 订单状态)` |
| B.5 状态机模型引用枚举 | `状态节点 → 参考 ../07_订单域枚举.md > 订单状态` | 状态机图节点名称必须与 OrderStatus.label 完全一致 |

**字典/枚举拆分一致性检查**:

| 检查项 | 要求 |
|-------|------|
| 索引主文档 | `05_字典与枚举索引.md` 必须存在,列出所有字典/枚举的全局清单 |
| 编码全局唯一 | 所有字典/枚举编码在多个文件间不重复(如不允许两个文件同时定义 `OrderStatus`) |
| 引用可定位 | 引用格式见 Phase 2 引用规范章节 |
| 状态机对齐 | 涉及状态流转的枚举,B.5 状态机模型节点名必须与枚举 label 完全一致 |
| 数据库注释引用 | A.3 数据表的枚举字段 COMMENT 必须引用 A.4 对应文件和章节 |
| 拆分粒度合理 | 单个字典枚举子文档不应超过 800 行,若超过需进一步拆分 |
| 避免碎片化 | 单个字典枚举子文档**不得同时**「少于 150 行」**且**「小于 6KB」(即:**行数 ≥150 或 体积 ≥6KB,满足其一即合规**);两者都不足时合并回 `05_字典与枚举定义.md` 单文件 |

## 子文档头部规范

每个子文档必须有以下头部(所有上游来源字段均必填或标注"无"):

```markdown
# {两位数字序号} {模块编号} {模块名称}

> **版本**: v{版本号}(与主文档一致)
> **隶属**: 详细设计方案 v{版本号} > {模块编号}
> **专职索引**: `00_索引.md`
> **相关文档**:
> - 上游引用: `[依赖的本设计内其他子文档列表]`(如 A.4 字典枚举可能被 A.3 数据表引用)
> - 下游引用: `[被本设计内哪些子文档引用]`
> **上游输入来源(溯源必填)**:
> - **研发 PRD 来源**: `[PRD文件路径]` > [对应章节编号及名称] > [页码/行号范围]
> - **原型来源**: `[原型路径]`(+ 路由 + 多页共文件时的锚点/屏位;若本子文档不涉及页面,标"无")
> - **产品需求文档来源**: `[产品需求文档路径]` > [对应章节](模式 B 时填,不涉及则标"无")
> - **高保真设计来源**: `[高保真设计文件路径]`(如有则填,不涉及则标"无")
```

**上游溯源强制说明**:
- **模块级溯源**(本头部)是 M 级别最小要求;**条目级溯源**(表内每行功规点/接口/数据表)仍需单独标注 PRD 来源,精确到章节+页码/行号
