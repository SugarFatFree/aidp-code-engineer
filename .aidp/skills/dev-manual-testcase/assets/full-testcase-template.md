### 1.5 执行规则（重要）

**问题记录优先原则：**

> ⚠️ **关键规则**：自测执行过程中发现 Bug、卡点、异常现象时，**不要立即中断测试去修复问题**。
>
> **正确做法**：
> 1. **先记录问题**：在用例步骤的"实际结果 / 备注"栏标注问题现象（如"❌ 不通过: 2026-05-13 点击保存后页面无响应"）
> 2. **继续执行后续用例**：跳过当前失败步骤，继续测试其他功能点
> 3. **统一修复**：等所有用例执行完毕后，汇总问题清单，再统一修复
>
> **原因**：
> - 避免频繁切换上下文，提高测试效率
> - 完整了解系统问题全貌，避免遗漏关联问题
> - 便于批量修复相同类型的问题
> - 保持测试节奏连贯，减少重复登录/导航操作
>
> **适用对象**：
> - 人工测试人员
> - AI 浏览器工具（Claude Code + chrome-devtools-mcp（推荐）/ Playwright MCP / OpenClaw / browser-use 等）
> - 自动化测试脚本

**问题记录格式：** 在对应步骤的"实际结果 / 备注"中标注 `❌ **Bug**: {现象 + 控制台报错}`，测试完成后统一汇总到"六、问题汇总清单"。

## 三、测试套件详情

> **步骤验收锚点约定(维度 13-B):** 每个用例步骤的"预期现象"列在断言真实结果时,**应额外标注**对应详细设计验收章节的精确锚点(markdown 链接,严禁纯文本),格式 `(验收: [§C-x.y 章节名](../docs/design/detail/{version}/19_测试方案.md#C-x-y))`,便于 QA 跑用例时双向追溯到设计验收标准。下例已在各用例的关键断言步骤示范;纯粹的输入回显步骤(如"输入账号→显示账号")无对应设计验收章节,可不标。
>
> **语义断言约定(可选,配合自动化执行):** 关键断言步骤(提交成功 / 列表增减 / 状态迁移 / 字段展示 / 校验拦截)可在"预期现象"后附一行机器可判的语义断言 `断言: <表达式>`(反向用例用 `断言(反向): <表达式>`),供下游 `auto-test-runner` 做确定化判定。断言只用页面可见文案(禁选择器/字段名),DSL 语法与完整表达式见 SKILL `references/test-design-methodology.md`「八之二」节。下例已在部分关键步骤示范(如 `断言:列表行数+1`),非必填、增量附加。
>
> **前置探测约定(可选,供浏览器前批量探测):** 若本用例依赖可通过只读接口/数据面确认的实体状态,在用例元信息中增加 `> **前置探测:** ED-001`。`ED-NNN` 必须引用主文档「前置探测项定义」表中唯一且一致的四列定义(前置项 / 探测实体/状态 / 探测方式（只读） / 不满足时 block 归因);相同前置复用同一编号。探测失败不得伪装成合法空结果,具体纪律见 `references/flow-principles.md`。
>
> **环境能力前置约定(可选,供第零步一次性集合运算):** 若本用例依赖的是**环境提供不提供某能力**(部署形态 / 日志通道 / 靶场资产 / 环境级数据形态)而非某条数据样本,在用例元信息中增加 `> **环境能力前置:** EC-001, EC-002`,并引用 §1.3.2 表中的四列定义。⛔ 不要与 `ED-NNN` 混用:那一档管「样本在不在」、每轮重探;这一档管「环境给不给得了」、整轮探一次、不满足时整批 block。
>
> **步骤级加速标注约定(可选):** **状态准备类**步骤(登录 / 切环境 / 选中某条记录 / 构造参数)可在**步骤号后**加 `[加速可选]`,形如 `| 1 [加速可选] | 登录 | … |`,提示下游执行端可用 WebMCP 工具调用替代多次 DOM 往返。⚠️ **是提示不是许可**:没标不等于禁止加速,标了也不等于必须加速。⚠️⚠️ **`[还原度]` 及一切视觉 / 布局 / 样式断言整条禁走 WebMCP**(下游 `check_result.py` C14 判 Critical),⛔ **不要为此另发明 `[必须DOM]` 标记** —— 那会让没标的还原度用例被放行,方向恰好相反。判据见 `references/flow-principles.md`「步骤级 `[加速可选]` 标注」。
>
> **前置数据编排段约定(可选,跨系统前置时使用):** 若用例的前置状态**在被测应用内无法构造**(如"订单中心删商品 → 商户后台看统计"),在用例**测试步骤之前**加一个「**前置数据编排**」段,声明必须跨系统完成的前置动作。段格式:
>
> ```markdown
> **前置数据编排**(跨系统前置,执行本用例前完成):
> | 序号 | 动作类型 | 目标系统 | 具体动作 | 完成判据 |
> | :-: | :- | :- | :- | :- |
> | 1 | 他系统UI操作 | 订单中心(见 01_研发自测方案.md §3.1 跨系统依赖环境) | 在"商品管理"删除商品"测试商品A" | 订单中心列表不再显示"测试商品A" |
> | 2 | SQL造删数 | 统计库(见 §五 DB 连接) | (UI 不可达时)软删除该商品 `UPDATE t_product SET del_flag=1 WHERE name='测试商品A'` | 影响行数 = 1 |
> ```
>
> 动作类型取 `他系统UI操作` / `SQL造删数` / `调对方接口`,目标系统的入口 URL / 账号 / DB 连接登记在 `01_研发自测方案.md` §3 测试环境与准入(§3.1 跨系统依赖环境·数据库 / §3.2 测试账号 / §3.3 前置数据准备);若项目另有外部 `测试环境与账号.md`(aiauto-test 端配置、不由本 SKILL 产出)则以之为准。该段属跨系统造数编排、非被测应用步骤,其 SQL / 接口不受"步骤列禁 SQL / 接口"约束(`check_testcase_format.py` 只扫「测试步骤」区域);被测应用自身步骤表仍严禁 SQL / 接口。详见 `references/flow-principles.md` >「用例级『前置数据编排』段」。

  第 5 次的直接原因就是「项目自己加的排除集漏了一项」。
  ⚠️⚠️ **只有走行级前置退路时**才需要「守护面涵盖 `.md` 就分两次跑、文档面去掉 `\*` 分支」:
  行级默认集里的 `\*` 会把 Markdown 的**列表项 `* 文本`** 与**整行加粗 `**文本**`** 一起静默吞掉,
  方向是**假绿**,而守护面写 `**` 或 `docs/**` 的断言天然涵盖 `.md`、必然中招。
  **块级剥离没有这个问题**(它对 Markdown 只剥 `<!-- -->`),这也是把它定为默认的原因之一。
  ⚠️ **写完整管道时 `|` 必须转义为 `\|`**——GFM 里 `|` 是列分隔符,**反引号代码段保护不了它**,
  不转义会把该行切成 8 格、整张表当场散架(硬门 Z7 专抓这一条)。
- **两个方向都必须有实跑记录**:方向一跑现状、期望 **0 命中**;方向二对着**必然命中的已知样本**跑
  同一条式子、期望 **≥1 命中**。⛔ **方向二留空或写 0 = 这条断言未经验证**——只跑方向一的断言
  可能是「式子写错、永远不会命中」的**恒 0 假绿**,而它在报告里与真正的零残留长得一模一样。
  方向二的样本就是维度 18 要求的「反向复现片段」,**一次实跑同时兑现两条规则,不是两项义务**。
- **退役**只有「守护对象已消失」「判据已移交常设机制(lint / CI grep 门 / 硬门脚本)」两条合法路径,
  且**必须留在表里标 `已退役(轮次 + 依据)`**,⛔ 不许静默删行。
  ⛔ **「跑了很多轮都没红过」不是退役理由**——常绿正是这类断言的正常状态,按它退役等于专挑还在生效的删。
  已退役行的两个方向列填 `— (已退役…)` 即可,硬门对已退役行不再要求实跑记录。
- **本轮确实没有零残留断言时**(既无裁剪/延期项、也无语义口径变更),整节只写一句
  「**本轮无零残留断言**」+ 原因,**不留空表头**。⚠️ 这句话是**写给 QR 子 Agent 看的**——
  `check_residual_assertions.py` **并不识别它**(与还原度覆盖表的「本轮无 UI 页面用例」不同,
  那句有正则专门认);该脚本的跳过条件是「扫描范围里既无零残留断言、也无登记表」,
  写不写这句都照样跳过。写它是为了让人分得清「确认过没有」与「忘了写」。
