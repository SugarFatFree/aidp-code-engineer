## 3. 测试环境与准入

### 3.1 测试环境信息

| 项目 | 值 |
| :- | :- |
| 系统入口 URL | `<https://test.example.com>` 或 `{待用户填写}` |
| 客户端类型 | Chrome 浏览器(120+) / Edge 浏览器 / H5 移动端 / iOS APP / Android APP / 微信小程序 / 桌面客户端(选其一,**若选 chrome-devtools-mcp 必须为 Web 浏览器类型**) |
| 后端环境 | 测试环境 / UAT 环境 |
| 数据库 | 默认「测试库,本方案不涉及数据库直查」;**若本轮含 `[双源对账]` 对账用例或「前置数据编排」的 `SQL造删数` 动作,此行改填库连接**(**`environment` 环境标识 / 类型 / host / port / 库名 / 只读或读写账号**),供执行方跑等价 SQL —— 下游 `auto-test-runner` 的 run-context `datasource` 取自此行。★**`environment` ∈ `dev` / `test` / `uat` / `staging` / `demo` / `prod`,改填库连接时必填、禁留空或写「未知」**,并**必须与「系统入口 URL / 后端环境」所属环境一致**:一致标 `✅ 环境匹配`;不一致就地标 `❌ 环境不匹配(DB=staging / 被测=test)`,判**不适用于本环境对账**并阻断依赖它的 `[双源对账]` 用例进入自动执行 |
| 跨系统依赖环境 | SSO 测试环境 `<URL>`、支付沙箱、短信测试通道(如适用);**「前置数据编排」段里 `他系统UI操作` / `调对方接口` 的目标系统入口 URL 一并登记于此**(账号见 §3.2) |

> ⚠️ **为什么 `environment` 必填:** 本行登记的 DB 连接会被下游 `auto-test-runner` 直接拿去做 `[双源对账]` 的数据真值判断,必须确认**这个库就是被测环境实际写入的库**。实际项目中曾登记成另一套非被测环境的库,用它查订单得出看似合理的对账结论,但被测环境成功下单后该库始终 0 行——它根本不是这套环境的库。**用错库的对账比不做对账更危险**:SQL 值与页面值本就不该相等,结论要么假性全红(误报一批缺陷)、要么凑巧全绿(漏掉真缺陷),而且看上去很笃定。下游会在执行期按 run-context `datasource.environment` 再做一次归属校验,**但校验的前提是这里先把它填对**。
>
> **字段说明:** "客户端类型"统一填写客户端种类(浏览器/APP/小程序/桌面),而非填写版本号。若启用 chrome-devtools-mcp,必须为 Web 浏览器类型(Chrome/Edge/Safari/Firefox)。**实际产出时此行只保留一种客户端类型(删除其余选项),否则 `check_test_plan_alignment.py` 会误判"同时含 Web 与非 Web 客户端"。**

- [ ] 测试账号已开通且能正常登录

> **账号新鲜度硬门怎么执行:** 任一参与本轮的账号「最近验证时间」为 `未验证` 或距今 > N 天 → **必须先跑一次登录冒烟预检**(只做登录 + 校验落地页/角色归属,**不跑任何业务用例**)。通过 → 把该账号的验证时间刷成当天日期;失败 → 在 §3.2 就地标 `❌ 失效(现象)`,并**阻断依赖该账号的套件进入 AI 自动执行**(改人工处置或换号后重跑预检)。
>
> **DB 环境一致性硬门怎么执行:** `environment` 与被测环境不一致 → 该 DB **判不适用于本环境对账**,`[双源对账]` 用例与 `SQL造删数` 前置**不得进入自动执行**(降级为纯 UI 断言或标阻断),并在 §3.1 就地标 `❌ 环境不匹配(DB=… / 被测=…)`。
>
> **两条硬门是同一个动机:** 把「账号有效性」「数据源环境归属」这两个**默认被无条件信任、一旦错就确定性污染结论**的前提,从口头/隐含假设升级为**模板必填字段 + 可核对约束 + 准入硬门**,让错误在最便宜的方案生成期就暴露,而不是拖到执行期作废一整轮。

### 5.1 用例级准则(默认值)

| 优先级 | 通过率门槛 | 不通过处理 |
| :-: | :- | :- |
| **P0 主流程** | **100%** | 阻塞上线;Critical Bug 立即修复 |

### 5.2 阻塞上线判定

任一以下情况触发阻塞:
- P0 用例任一不通过
- 数据安全/权限越权类 Bug(无论优先级)
- 跨系统集成断链(支付/短信/SSO 等)
- 已知合规底线问题
