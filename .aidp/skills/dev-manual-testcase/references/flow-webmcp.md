# WebMCP 用例族（条件启用 · 维度 20 **Web 专项**）

> ★ **本文件仅 Web 客户端适用**；跨端的应用工具用例先读 [`flow-client-mcp.md`](./flow-client-mcp.md)。
> ⛔ Appium / 小程序驱动即使也用 MCP 连接，**也不能套用本页的「页面注册」与 Chrome 前提** ——
> 那是测试驱动，不是应用能力。
>
> **本文件只在 `webmcp_enabled: true`（或归一后 `client_mcp.enabled: true` 且客户端 = Web、形态 = WebMCP）时适用。**
> ⚠️ Web 叶子未启用**只省略本文件的双窗口两类套件**——非 Web 已声明 `client_mcp.enabled: true` 时，
> 通用用例与维度 20 **仍须执行**。⛔ 两类应用能力**都**未启用才不产专项用例、不占覆盖矩阵与统计摘要、不在 QR 报告里留行。

---

## 一、先对齐概念（否则用例会测错东西）

**WebMCP = 网页把自身能力以「带 JSON Schema 的函数」形式登记给浏览器**，能在该页面执行 JS 的
AI Agent 可直接调用业务函数，不必靠无障碍树快照猜 DOM。

**⚠️ 它不是网络协议、没有传输层。** 消费方必须先有办法进入该页面的 JS 上下文。它提升的是
「**已经能操作该页面**的 Agent」的调用效率，不为远端 Agent 新增接入通道。

由此派生用例设计的核心假设：**调用方不可信**。能力入口是页面 JS 上下文里的普通对象，任何能在
本页执行 JS 的主体都能调它。所以安全三条（确认门 / 脱敏 / 不扩权）**必须按「对任意调用方生效」
来验**，不是验「助手很守规矩」。

## 二、启用判定由调用方负责，本 SKILL 不自行探测（硬前提）

| 入参 | 形态 | 说明 |
| :- | :- | :- |
| `webmcp_enabled` | `true` / `false` | Web 旧版兼容开关；新 `client_mcp.enabled: true` 且客户端 = Web / 形态 = WebMCP 同样启用本叶子。⛔ 非 Web 的通用用例**不依赖它** |
| `webmcp_entry_symbols` | 数组 | 该项目**实测**的能力入口标识符。⚠️ 挂载位置已迁移过一次、规范仍在演进，**写死任何名字都会过期** |
| `webmcp_launch_command` | 字符串 | 带参浏览器的完整启动命令。**用例里一律引用它、不要自拟** |

**⛔ 严禁在本 SKILL 内自行探测是否启用**（不 grep PRD、不扫代码标识符）。**Why：判定散落多处
必然漂移，一处判错就给未启用项目凭空长出用例和告警位。**

## 三、两类套件，缺一不可

### ① 未启用态套件（★常态路径，优先级不得低于已启用态）

用**不带任何参数的常规浏览器**跑。断言：

1. **无任何相关 DOM 元素** —— 与该能力上线前**逐像素一致**；
2. **控制台零报错**；
3. **既有功能零回归**。

> ⚠️ **这是绝大多数使用者的真实体验，不是边缘场景。**
>
> 该能力最容易做反的一点，就是把「浏览器不支持」当成**异常分支**处理（弹「您的浏览器不支持
> XX，请升级」）——**那是违规**。不支持是**主流路径**，正确表现是**什么都不发生**。
>
> 因此本套件的优先级与已启用态**同级**（P0 对 P0），不得因为「这是没开启的情况」就降到 P2。

**推荐用例形态**（复用既有 `[反向-残留]` 的反向断言 DSL）：

| 用例 | 断言 |
| :- | :- |
| 未启用态·无入口元素 | `断言(反向): 不存在文本"<能力相关按钮/标签文案>"` |
| 未启用态·控制台洁净 | 控制台无 error 级消息 |
| 未启用态·既有功能零回归 | 抽取本页既有核心操作各一条，结果与上线前一致 |

### ② 已启用态套件

用**带参浏览器**跑（启动命令由调用方通过 `webmcp_launch_command` 传入，**不要自拟**）。

覆盖以下九项，逐项至少一条用例：

| # | 覆盖项 | 要点 |
| :-: | :- | :- |
| 1 | 工具清单齐备性 | 以**设计文档的工具清单表**为基准逐条核对（见下方事实 2） |
| 2 | 只读工具正确性 | 返回值与页面手工操作所见一致 |
| 3 | 敏感值脱敏 | 凭据/密钥/令牌类**一律不出现**，含脱敏片段 |
| 4 | 写操作确认门 | **确认 / 取消 / 超时 / 并发**四态各一条 |
| 5 | 不扩权 | 低权角色调工具拿不到越权数据；越权与不存在**同一文案** |
| 6 | 服务端配置关闭时的表现 | 工具仍在清单里但**调用被拒**（见事实 1） |
| 7 | 总开关停用与恢复 | 停用后调用被拒；恢复后可用 |
| 8 | 刷新与重复登记 | 页面刷新后不产生重复登记、不报错 |
| 9 | 工具执行 ⟷ 手工操作链路一致性 | 同一业务动作两条路径**结果与副作用一致** |

## 四、三条会导致用例写错的实测事实（写进用例生成规则）

### 事实 1：停用后工具**不会**从助手清单里消失

实测该能力入口原型上**没有** unregister 类方法（只有登记 / 列出 / 执行 / 变更通知四类）。
**停用的正确表现是：仍在清单里、但调用被拒。**

> ⛔ 断言「清单里没了」**必然误判为缺陷**。这是本族最高频的写错点。

### 事实 2：列出工具的方法返回的是**浏览器侧全量工具**，且是**异步**的

它返回浏览器侧全部工具、**不只本页登记的**，返回值是 Promise。

**所以：校验「本页登记了哪些」须以设计文档的工具清单表为准，不能拿它的返回值当本页账本。**
用它做「本页工具齐备性」断言会把别的页面/扩展登记的工具也算进来。

### 事实 3：安全三条按「对任意调用方生效」来验

确认门 / 脱敏 / 不扩权**不是验「助手很守规矩」**。能力入口是页面 JS 上下文里的普通对象，任何
能在本页执行 JS 的主体都可调用（含外部 Agent 经调试协议、浏览器扩展）。

**用例应模拟外部调用方直接调工具，验证边界仍拦得住。** 只测「让助手做坏事，助手拒绝了」是
无效验证——那测的是助手，不是本系统的边界。

> **★写法固定：动作动词用「执行」，调用语义写进「操作对象」列。**
>
> | 操作动作 | 操作对象 | 操作数据 | 预期现象 |
> | :- | :- | :- | :- |
> | 执行 | 以外部调用方身份调用工具「删除接口」 | `{"id":1}` | 弹出二次确认框，未确认前不执行 |
>
> ⚠️ **别写成「调用」或「发起」** —— 实测都会被 `check_testcase_format.py` 报 Important
> `invalid_action_verb`（动作动词白名单没有它们），而 QR 派发流程明确要求子 Agent 读
> `by_level.Important` 并入维度判定 → **合规用例反被判不通过**。「执行」本就在白名单里
> （与 mock 清理验证等既有例外同款），实测放行。

> ⚠️ **这一条与核心原则 1「零代码级动作」相抵触，故按该 SKILL 既有范式做成窄口径例外**（与
> `[双源对账]` 的等价 SQL、「前置数据编排」段的跨系统造删数同一处理方式）：
>
> - **破例范围仅这三条安全用例**（确认门 / 脱敏 / 不扩权），标记 `[外部调用方]`；
> - **其余 WebMCP 用例仍走真人可操作的页内助手交互**（工具清单齐备性、只读工具正确性、
>   链路一致性等，都能由真人在助手对话框里完成）；
> - ⛔ **未启用时本例外不存在**——它随维度 20 一起整体不适用。
>
> **Why 值得破例：** 这三条的判据本身就是「对任意调用方都成立」。用真人路径去验它，验的是
> 助手的行为，**结论与本系统的边界是否严密无关**——那样的用例通过与否都说明不了问题。

## 五、用例模板的两项强制标注

### ① 双窗口前置必须在用例头部显式标注

- 未启用态套件 → **常规浏览器**；
- 已启用态套件 → **带参浏览器**。

⚠️ **不标注的后果是确定的**：执行者会用同一个浏览器跑完两套，其中一套**必然结论失真**
（用带参浏览器跑「未启用态」→ 元素存在 → 假红；用常规浏览器跑「已启用态」→ 能力入口不存在
→ 整套 block 或假绿）。

### ② 引用「测试环境与账号」文档取启动命令时，必须同时校验目标段是否存在

⚠️ **下游真实踩过**：用例三处指向该文档取启动命令，而文档里**从未回写这一段**——文件在、内容
锚点空，链接检查查不出来，执行者第一步就卡住。

**规则：** 用例引用该文档时同时校验目标段是否存在；**缺失即判 `block` 并写明缺哪一段**，不写
「见 XX 文档」了事。同时在自测方案里要求「测试环境与账号」段**登记完整启动命令**。

## 六、维度 20 的通过判据（QR 子 Agent 逐条核）

| # | 判据 | severity |
| :-: | :- | :-: |
| 1 | **两类套件都在**（缺任一即不通过；只写已启用态是最常见形态） | Critical |
| 2 | 未启用态套件的优先级**不低于**已启用态 | Critical |
| 3 | 未启用态三条断言齐全（无元素 / 控制台洁净 / 既有功能零回归） | Critical |

| 5 | **无「清单里没了」型断言**（违反事实 1） | Critical |
| 6 | 工具齐备性断言以**设计工具清单表**为基准，未拿列出方法返回值当本页账本（事实 2） | Critical |
| 7 | 安全三条按「外部调用方也拦得住」验（事实 3） | Critical |
