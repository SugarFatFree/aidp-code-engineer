# Java / Spring 项目：枚举 / 错误码 / 校验提示来源

> 生成用例前「从代码读取真实文案」这一步用（**后端侧**）。跨技术栈通用规则见 `../SKILL.md`。

| 要读什么 | Java/Spring 项目的位置 |
| :- | :- |
| **枚举 label（状态、类型、分类）** | `src/main/java/**/enums/*Enum.java` —— 取 `label` 字段值，**不是 `code`**；用例断言写用户看到的 label（如「已支付」而非 `2`） |
| **业务错误码与提示语** | 全局异常处理 `@RestControllerAdvice`、错误码枚举 `*ErrorCode.java`、`ErrorEnum.java` —— 反向用例的预期提示文案取自这里 |
| **参数校验提示** | DTO 上的 `@NotBlank(message = "…")` / `@Size(message = "…")` —— **反向用例（必填校验、超长校验）的预期提示直接取这些 `message`** |
| **接口路径**（仅供理解页面数据来源，**不写进用例步骤**） | `@RequestMapping` / `@GetMapping` |

## 注意

- ⚠️ **用例步骤严禁写接口调用**（真人可操作原则）；读 Controller 只为理解「这个页面的数据从哪来」，帮助判断反向用例该怎么造场景。
- 校验提示是反向用例的高价值来源：`@NotBlank(message="用户名不能为空")` 直接对应一条「不填用户名 → 提示『用户名不能为空』」的反向用例。
- 前后端枚举 label 不一致时，**以前端实际渲染的为准**写用例，并在待澄清问题清单登记该不一致。
