# 客户端 MCP 能力暴露详规（★ 按需安装的可选规则 · 端无关契约）

> # ⛔ 本文件默认【不在】`{{AIDP_HOME}}/rules/` 下 —— 与 `webmcp.md` 同一设计
>
> `rules/*.md` 是**路径触发**加载的：命中 `paths:` 就整份进上下文。绝大多数项目
> **不提供**客户端 MCP 能力，不该为此在每次编辑客户端代码时白读一遍本文件。
> 启用判定唯一实现 = `python3 {{AIDP_HOME}}/scripts/check_client_mcp.py --detect --json`；
> 判为 `declared` 后才由 `--install-rule` 装到 `{{AIDP_HOME}}/rules/client-mcp.md`。

## 〇、先分清两条轴（混了，后面每一条都会判错）

| 轴 | 问的问题 | 本规则管不管 |
| :- | :- | :-: |
| **应用能力** | 本应用**自己**是否向 AI 暴露业务工具 | ✅ 就是它 |
| **测试驱动** | AI 用 chrome-devtools / Appium / 小程序驱动**操控**本应用 | ⛔ 不是 |

**测试驱动走的也是 MCP 协议，但那是「AI 会操作这个客户端」，与「这个客户端提供了业务工具」
是两件事。** 下游已实证：报告里 `driver=cli` + 声明 `enabled=true` 被当成「用了 MCP 能力」，
而当时页面实际注册工具数是 **0**。⛔ 任何时候都不得用驱动可用性论证应用具备本能力。

## 一、端形态：能力跨端，实现不跨端

| client_type | 典型实现形态（`implementation`） | 端专有前提归谁 |
| :- | :- | :- |
| `web` | `webmcp` | **`webmcp.md` + `check_webmcp.py`**（secure context / 浏览器版本 / 启动开关） |
| `miniprogram` / `mobile` / `desktop` | `app-native`（应用自带 MCP 服务端）/ `bridge`（宿主或伴生进程桥接） | **本项目按真实实现登记**，写进详细设计与「测试环境与账号」 |

⛔ **非 Web 端绝不继承浏览器前提**：secure context、`--enable-features=…`、浏览器版本下限
全是 Web 专有；套到小程序 / 原生 App 上，既查不出真问题，又让根本不跑浏览器的端永久挂着
一组不可能满足的判据。**没有经证实的实现形态时，如实标「未提供」**——不要为了让流程跑通
而杜撰一个统一入口。

## 二、能力声明（PRD 头部 `autopilot_decisions`，默认关闭）

```yaml
client_mcp:
  enabled: true
  client_type: miniprogram        # web | miniprogram | mobile | desktop
  implementation: app-native      # webmcp | app-native | bridge | none
```

- **存量 Web 项目**的 `webmcp:` 段继续有效，等价于 `client_type: web` + `implementation: webmcp`。
- 两处都声明且不一致 → 判定脚本 `exit 2` **响亮失败**，⛔ 不静默取其一。
- `enabled: true` 但缺 `implementation` → 判 `declared-unimplemented`，**按未提供处理**。

## 三、工具契约（逐条硬要求，缺任一即本能力不合格）

1. **单一适配层**：全部工具在**唯一一处**登记/注销，业务代码不散落登记调用。散落的后果是
   「某个页面/某个 Activity 退出后工具还在」——调用方拿到一个指向已销毁上下文的工具。
2. **参数 Schema 必填**：每个工具声明入参/出参结构与必填性。没有 Schema 的工具，调用方只能靠
   猜，错误参数在业务层才炸。
3. **业务语义命名**：工具名是**业务动作**（`createWorkOrder`），不是内部函数名或路由名。
4. **能力边界显式**：工具清单即对外承诺面。⛔ 不暴露「万能执行」「任意查询」这类无边界工具。
5. **生命周期对齐**：进入某上下文才注册、离开即注销；清单随可用性变化，不留悬挂项。

## 四、身份、权限与写操作（★ 最容易被跳过的一段）

6. **调用方不可信假设**：AI 调用方**不是**你的 UI，不会替你做前置校验。所有权限判定、
   参数合法性、越权拦截**必须在应用侧重做一遍**，⛔ 不得依赖「UI 上点不到就调不到」。
7. **身份沿用当前登录态**：工具以**当前用户**身份执行，不得提权、不得走隐藏的管理员通道。
8. **写操作必须确认**：不可逆 / 对外可见 / 涉及资金与通知的操作，须有**明确确认环节**
   （UI 二次确认或工具契约里的显式确认参数），并在审计中记录确认来源。

## 五、错误契约与可观测

9. **错误结构化**：失败返回可判别的错误码 + 面向用户的中文说明，⛔ 不返回死文案、
   不把失败伪装成成功（空结果 / `success: true`）。
10. **审计与调用证据**：每次工具调用落审计日志（谁、何工具、入参摘要、结果、时间），
    敏感字段脱敏（同约定 40）。**测试期的「实际调用」必须有可核对的证据产物**；
    没有证据的「调用过」在报告里一律不成立（判定见 `aiauto_readiness.py`）。

## 六、四态如实记录（报告纪律）

| 态 | 含义 | 取不到时 |
| :- | :- | :- |
| 声明启用 | PRD/架构文档声明 | 按未声明处理 |
| 入口可用 | 能力入口在运行期实际可连接 | 写「未取到」 |
| 工具已注册 | **当前实例/页面**实际注册的工具清单 | 写「未取到」；空清单明确记 `0` |
| 实际调用 | 该用例确实调用了工具 **且有证据产物** | ⛔ 不得由上一态推断 |

- 四态**逐级独立**，⛔ 不得互相推导（「声明了」推不出「注册了」，「注册了」推不出「调用了」）。
- 适配当前动作的工具不存在时：普通业务用例走常规 UI/驱动路径并**写明回退原因**；
  **专门验证本能力的用例必须 block**，其余用例继续执行。

## 七、与其他约定的边界

- 权限落地 → 约定 40 / 上游设计侧检查项；日志与脱敏 → 约定 40。
- Web 端运行前提、启动参数、入口标识符 → `webmcp.md`（本文件**不复制**）。
- ⛔ 不要把本能力做成默认开启或强制约定：它是**可选**能力，未声明即整份不适用。
