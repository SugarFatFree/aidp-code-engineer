## 2. 分层架构约束

> 系统架构的分层规则、跨层调用限制、服务粒度等。

（待 `/sprint-design` 填充或人工补充。示例：）
- **分层架构**：严格遵循接入层 → 应用层 → 服务层 → 数据层，禁止跨层直接调用
- **服务粒度**：微服务拆分与业务领域边界对齐
- **接口规范**：服务间通信采用 RESTful API 或 gRPC
- **异步解耦**：非实时场景通过消息中间件异步
- **数据隔离**：每个微服务独立管理数据存储

## 4. 安全约束

（待填充。示例：）
- **权限控制**：RBAC 模型，敏感操作支持细粒度权限校验
- **数据加密**：敏感数据（身份证、手机号等）存储加密，传输 HTTPS/TLS
- **接口安全**：网关统一鉴权，防重放、防篡改
- **日志审计**：关键操作记录审计日志，保留 ≥ 6 个月
- **安全扫描**：提交前 SAST，上线前 DAST

---

## 5. 性能约束

（待填充。示例：）
- **响应时间**：P99 ≤ 500ms
- **缓存策略**：热点数据走 Redis，TTL ≥ 5 分钟
- **数据库**：慢查询阈值 500ms，必须加索引
- **并发**：接口默认限流 100 QPS

---

## 6. 数据约束

（待填充。示例：）
- **数据质量**：所有持久化字段必须有非空/长度/格式校验
- **数据一致性**：跨服务操作使用 Saga 或最终一致性方案
- **合规性**：个人隐私数据遵循《个人信息保护法》脱敏存储

---

## 7. 禁止事项（反模式）

> 明确的"不允许做"清单，开发时必须遵守。

（待填充。示例：）
- ❌ 禁止在 Controller 层直接访问数据库
- ❌ 禁止使用原生 SQL 字符串拼接（必须用 ORM 参数化查询）
- ❌ 禁止在前端存储敏感信息（Token、密钥）到 localStorage
- ❌ 禁止跨微服务直接访问数据库
- ❌ 禁止硬编码配置（密钥、URL、数据库连接）
