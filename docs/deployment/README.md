# 部署操作入口

本目录按版本保存实际部署资产和运维操作指引。进入目标版本目录，先读其 `README.md`；已有独立操作说明时沿用该入口，不重复维护同一套步骤。

操作指引在版本规划和正式发布时集中校准。日常执行结果以原部署工具、数据库工具和流水线的真实记录为准，不再复制成部署报告或 SQL 状态大表。

## 按实际产物导航

下列为可选布局示意，只建立确有内容的目录与文件。版本根已有完整操作说明时，不另建 SOP 或部署检查清单。

```text
docs/deployment/
├── {version}/
│   ├── README.md                       # 唯一操作入口：环境、步骤、成功判据与必要回退
│   ├── sql/
│   │   ├── 增量/                        # 已有环境升级
│   │   │   ├── {NN}_<用途>.sql          # 按实际执行顺序编号
│   │   │   └── 99_回滚脚本.sql           # 有对应回退操作时保留
│   │   └── 全量/                        # 全新部署基线
│   │       ├── 建表说明.md               # 必要时列目标库和执行顺序
│   │       └── {NN}_<用途>.sql
│   ├── 配置文件/
│   │   ├── 增量/配置项清单.md             # 仅本版改动及权威文件路径
│   │   └── 全量/                        # 全新部署需要的实际配置基线
│   │       ├── 配置说明.md               # 文件去向、换环境必改项、生效步骤
│   │       └── <实际配置文件>
│   └── 部署流程/SQL执行台账.md            # 仅确需独立 SQL 清单时使用
└── tools/                              # 已有跨版本运维工具按需归档
```

SQL 和配置的增量、全量产物分别进入对应子目录，不混放在 `sql/` 或 `配置文件/` 根目录。工具目录按实际归属应用分类；没有工具时不创建空目录，平铺目录不额外生成索引。

## 选择部署场景

| 场景 | 使用资产 | 操作边界 |
|---|---|---|
| 全新部署 | `sql/全量/`、`配置文件/全量/` | 按目标库建表、初始化必要数据并配置服务；不叠加执行升级脚本 |
| 已有环境升级 | `sql/增量/`、`配置文件/增量/配置项清单.md` | 只应用本次升级变化，保留环境已有配置与业务数据 |
| 回退 | 本次明确提供且适用的回退步骤与脚本 | 先核实版本、数据时点及目标环境；不能假定旧备份覆盖当前数据 |
| 服务自动迁移 | 项目既有迁移入口 | 说明启动时自动执行，避免再手工重复运行同一 SQL |

**全量与增量两轨绝不叠加执行。** 全量 SQL 用于从零建库，不夹带升级用 ALTER 或历史数据迁移。升级时不要用全量配置覆盖现网的证书路径、限流、地址白名单等环境设置。

版本操作说明只需写明：目标环境、服务与数据库；真实命令和配置步骤；依赖及执行顺序；成功判据；必要回退。有实际差异才分别说明新装和升级，不预填不存在的服务或部署方式。

## SQL 执行顺序

SQL 清单默认只有 `目标数据库` 和 `SQL脚本路径（按执行顺序）` 两列。

按实际需要分别列手工新装、升级和回退。自动启动迁移或没有手工 SQL 时，在既有操作说明简注即可，不创建空台账。执行结果、时间和数据库核验记录使用原工具的权威记录，不回填为各环境状态列。

## 配置变更

运行时原文件是权威；操作指引只引用路径，增量清单只列新增、修改、删除项及必要片段，不抄整份配置或 SQL。删除时明确单个 key 与整段的区别，运行时配置给出修改位置及生效命令。

全新部署配置说明列出文件去向和换环境必改项。引导层环境文件保持与源码同形，保留有效的变量默认值和配置引用；密码类使用虚构示例值并注明“示例值，非真实口令”，实际部署时替换。没有实际变化的项目在既有说明简注，不另造空清单。

## 备份与回退

遵守项目既有备份频率。数据库备份、完整冷备和迁移前快照合并计数，不按名称或调用方拆开额度。同日复用必须确认目标覆盖、产物可用和真实备份时间，并使用现有部署工具已经支持的跳过备份参数。

没有适用备份、记录矛盾或工具无法跳过内置备份时，先说明缺少的前提。迁移不是追加备份的例外；不得把备份改称“即时前像”“保护副本”“快照”来绕过限制。**不得用旧备份自动覆盖部署后新增的业务数据。**

## 跨版本工具

`tools/` 只存已有或明确需要归档的运维工具。按实际归属分类，保留可运行脚本及其内部引用的稳定文件名；排除缓存和构建产物。需要目录导航时维护一份索引，已有操作入口则沿用，不复制部署助手或新建测试工程。

目录及产物维护规则见 [版本与用户目录约定](../init/06_版本与用户目录约定.md)；部署操作边界见 [部署操作约定](../../{{AIDP_HOME}}/reference/部署操作约定.md)，双轨基线规则见 [约定细则 37](../../{{AIDP_HOME}}/reference/约定细则-5.md)。
