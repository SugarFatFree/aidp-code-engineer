## 目录结构

```
docs/design/
└── detail/
    ├── {version}/               # 版本级增量详细设计（整版本一份，不按 Sprint 拆分）
    │   ├── 00_索引.md           # ★ 恒有：专职索引（文件清单 + 每文件生成时间 + 主/补充标识，约定 14/15）
    │   ├── 01_详细设计.md       # 推荐：模块结构、公共组件、业务流程
    │   ├── 02_数据库设计.md     # 推荐：有数据库时
    │   ├── 03_接口设计.md       # 推荐：有 API 时
    │   ├── 04_对外开放接口.md / 05_集成对接.md / 06_测试方案.md / 07_安全设计.md / ...  # 按需专题（序号权威 = /sprint-design）
    │   └── 98_事实清单.md       # 代码事实基线（如有）；99_待澄清问题清单.md（如有）
    └── 全量/                     # ★ 跨版本全量详细设计（非版本目录）：/version 正式发布 Step 3.3.11 生成
        ├── 00_索引.md           # 仅目录内导航；整合"最新代码+全量需求+各版本详设"、自包含不引用外部文件
        └── 01_详细设计.md / 02_数据库设计.md / ... / 98_事实清单.md  # 覆盖式只留最新、无历史；规划期不动
```

> **架构三件套的位置**：全局架构约束（`架构约束.md` / `技术选型.md` / `UI规范约束.md`）属**项目级单一真源**，位于 **`docs/architecture/`**（不在 `docs/design/` 下）。权威定义见 [`../init/06_版本与用户目录约定.md`](../init/06_版本与用户目录约定.md) §2.1。

## `detail/{version}/`（版本级）职责

**该版本的具体设计**，由 `/sprint-design` 命令调用 `dev-logic-architect` skill 生成。

- 整个版本的详细设计集中在该目录，**按需自由分文件**（不套用"必出 3 份固定文件"模型）
- **恒有专职 `00_索引.md` + 内容 `01_` 起**：`00_` 槽位只给索引；专题按主题中文自描述命名——单专题即 `00_索引.md` + `01_详细设计.md`，多专题即 `00_索引.md` + `01_详细设计.md`/`02_数据库设计.md`/`03_接口设计.md`/… + `98_事实清单.md`（如有）。历史存量（裸 `00_<专题>.md` 单份态 / 裸名并列态）仍识别放行、新生成不采用
- 不按 Sprint 拆分（Sprint 执行顺序由 `plans/{version}/01_研发执行计划.md` 规划）
- 后续的 `/sprint-dev` 和 `/sprint-bugfix` 如引入新功能/接口/表，会自动追加增量

## `detail/全量/`（跨版本全量详细设计，非版本目录）

**当前最新的全量版本详细设计**，由 `/version` **正式发布（打 tag）** 时 Step 3.3.11 生成——**版本规划期不动**、`--no-tag` 准发布不生。

- **内容**：整合「最新代码事实（代码为准）+ 全量历史需求 + 各版本详细设计」形成的**独立可交付**全量设计
- **形态**：目录内拆分态自包含（`00_索引.md` 仅目录内导航 + `01_详细设计.md`/… + `98_事实清单.md`）
- **铁律**：① **只留最新、无历史**（每次正式发布覆盖式重生）② **自包含、不引用外部文件**（拿走整个仓库只留 `全量/` 也能完整读懂）
- **非版本目录**：不参与前版基线识别 / 版本级收敛审计 / 目录层级检查（与 `README` 同级豁免）

## 生成/更新时机

| 触发命令 | 更新目标 |
|---------|---------|
| `/sprint-design` | 生成 `detail/{version}/` 按需若干文件 + 动态更新项目级 `docs/architecture/` |
| `/sprint-dev` | 如引入新接口/表，自动回写 `detail/{version}/` 和 `docs/architecture/` |
| `/sprint-bugfix` | 如修复涉及设计变更，自动回写同上 |

## 相关命令

- `/sprint-design` — 生成版本详细设计（调用 `dev-logic-architect` skill）
- `/sprint-dev` — 开发完成后自动回写设计
- `/sprint-bugfix` — 修复涉及设计变更时自动回写
