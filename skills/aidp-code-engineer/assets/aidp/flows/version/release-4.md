#### Step 3.3.7.7：★ B 部分——部署目录其余产物完善 + 跨文档一致性（发布前）

**目标**：正式发布读取既有机器待同步引用，集中校准本版必要运维指引。先 Read `{{AIDP_HOME}}/reference/部署操作约定.md`；`--no-tag` 日常准发布只保留待办，不能借本段新增部署 Markdown。

```bash
python3 {{AIDP_HOME}}/scripts/deployment_ops.py pending --version {version}
```

无实际部署产物且无操作变化则跳过，不造空目录或子索引。存在实际产物时按下表校准，成功后仅结清已覆盖的待同步引用。

| 产物 | 发布前完善动作 |
|------|--------------|
| 既有唯一操作说明（版本根 `README.md` 或 `部署流程/部署流程.md`） | 环境/服务/库、实际命令顺序、成功判据、必要回退；校准 SQL/配置/初始化接口引用。已由 README 承载则不再补一份 SOP；无操作入口且确有部署内容才取模板。备份按真实策略与记录，不默认新增或自动恢复。 |
| `部署流程/SQL执行台账.md` | 仅 `目标数据库` 与 `SQL脚本路径（按执行顺序）` 两列，必要时分手工新装/升级/回退；自动迁移只注明无需重复手工执行，无手工 SQL 简注。执行状态/实查证据保留机器记录。 |
| `配置文件/增量/配置项清单.md` | 仅本版增删改动项、权威路径、必要生效动作；不抄全量内容、不放分析。按 release_scope.py 的真实升级区间校准。 |
| 版本根 `README.md` | 有部署产物时保留唯一入口及全新/升级两条互斥路径，说明两套绝不叠加；不存在的目录不造链接。不重复 SOP、子索引或 checklist。 |
| 既有 checklist | 只校必要操作引用；已有说明承担职责就不新增。用户未要求不另产报告。 |

正文不得包含 AI 过程、授权对话、门禁预算、测试/审查报告或可从 Git/流水线取的历史。审查发现/机器证据留原记录，必要补救命令才进运维指引。完成后运行 `python3 {{AIDP_HOME}}/scripts/release_baseline_check.py --version {version} --only links` 核现有链接。

**执行**：由 PM Agent（命令承载角色）Read 上述产物 → 按表完善 + Edit 回写。**无人值守（`--no-tag` / `--unattended`）照常执行**（纯文档整理、不需交互）。

**失败处置（不阻塞发布，★ 逐产物粒度）**：某产物读取/解析异常 → **只跳过该产物**（其余 B 部分产物照常完善）、发布报告加 WARN，不阻塞、不臆造内容补齐；**并登记 `docs/audit/{version}/发布欠账.md`**（步骤=Step 3.3.7 B，跳过项=具体产物名 + 精确定位，补跑命令 `/version {version} --finalize-docs`）。**★ B 部分本身不因 A 跳过而跳过**（解耦铁律，见 3.3.7.1）。

**输出摘要**：
```
📦 部署产物完善（{version}）：
   • 部署流程.md：占位符已实值化 / 关键项表 {填齐N项、置"无"M项} / SQL 引用已对齐整理后文件名
   • 配置项清单.md：3 段（新增·删除·运行时文件变更）已终检（必改项归 `配置文件/全量/配置说明.md`，约定 25/37）
   • deployment-checklist.md：{已核对 / 已生成骨架 / 无}
   • 跨文档一致性：✓（SQL 文件名 / 配置项 / 初始化接口 四文档互引一致）
```

#### Step 3.3.7.8：★ C 部分——跨版本工具目录 `docs/deployment/tools/` 整理（发布前，独立于 {version}/）

> **独立跳过条件**：`docs/deployment/tools/` 不存在或仅有 README / `.gitkeep` / 构建缓存、没有实际工具时跳过 C 部分，不创建目录或占位索引。正式发布有实际工具才整理，即使本版本 `docs/deployment/{version}/` 不存在；日常准发布不借此补 Markdown。A/B 的版本目录判据不得覆盖跨版本工具整理。

`docs/deployment/tools/` 是跨版本运维 / 一次性工具归档（非版本隔离，定义见 `06_版本与用户目录约定.md` §2.5.4.1）。范式层**只做轻量整理，不校验工具 SQL 内容**（脚本多为一次性、带环境上下文）：

| 整理动作 | 说明 |
|---------|------|
| **必要入口对齐** | 只核实际工具与已有 README/部署操作说明的引用；无入口时按 `readme_policy.py::is_readme_required_directory` 判断，平铺叶子不新建，多级枢纽才补必要导航。按真实路径和必要操作用途填写，不造占位示例、不复写执行历史。 |
| **构建产物清理** | 删除 `tools/` 下 `__pycache__/`、`*.pyc` 等构建产物（`find docs/deployment/tools -type d -name __pycache__ -exec rm -rf {} +`），不入库 |
| **分类归位提示（不自动搬）** | `tools/` 根下未归类的工具文件 → **WARN 提示**按归属归入 `本应用/` `<上游系统>/` `其他/`；**命令不自动搬迁**（归属需运维侧人工判断，避免误判）|
| **命名提示** | 工具文件名非中文 / 缺日期前缀 → INFO 提示（建议中文化 + 日期前缀）；**不强制改名**（可运行工具改名会断 README 交叉引用）|

**执行**：正式发布读取 `tools/` 实际目录树与已有入口，按表处理需要变更的引用与构建产物；缺少非必要 README 不视为失败、不补欠账。无人值守正式发布同样适用。实际整理失败只在既有发布记录注明具体失败与补跑方式，不臆造工具用途、不为该步骤另写部署报告。

**输出摘要**：
```
📦 跨版本工具目录整理（docs/deployment/tools/）：
   • README 索引：{已对齐N项 / 新登记M项 / 清理K项}
   • 构建产物清理：{删除 __pycache__ X 处 / 无}
   • 分类归位提示：{根目录未归类文件 Y 个（已 WARN、不自动搬）/ 无}
```

#### Step 3.3.7.9：★ D 部分——双轨部署基线产出（全量轨，约定 37；独立于 A/B/C）

> **单一信源 = 约定 37**（`{{AIDP_HOME}}/reference/约定细则-5.md`）。本步只做**编排 + 跳过判定 + 失败处置**；判据链（表清单三态核对 / 导出源反查 / 去环境绑定物 / A·B 分区 / 两层收录矩阵 / 三重检索剔死配置 / 值可见无占位 + 密码示例值 / 多形态两条路径后果）**一律以细则片 5 为准，本处不复述**（约定 21）。**进入本步的第一动作 = `Read {{AIDP_HOME}}/reference/约定细则-5.md`。**

**产出**：`docs/deployment/{version}/sql/全量/` + `docs/deployment/{version}/配置文件/全量/`（SQL 增量脚本随实际开发产出，配置 Markdown 在规划/正式发布集中校准）。

**★ 独立跳过判定（与 A/B/C 解耦）**：
- **`--no-tag` 准发布 → 跳过并登记**（全量基线属正式发布交付物）：`release_debt.py add --version {version} --step 3.3.7.9 --title "准发布未产全量基线" --redo "/version {version}"`；
- **真实库 / 配置中心不可达 → 跳过本步**（不阻塞），`release_debt.py add --step 3.3.7.9 --title "双轨部署基线未产出" --note <原因> --redo "/version {version} --rebuild-baseline"`。**⛔ 不得拿其它环境顶替、不得凭历史脚本拼**（37.3-2 / 37.6）；
- **⛔ 「本版零变更」不是跳过理由**——全量描述"当前代码要跑起来需要什么"，与本版改没改无关（37.1）。

**执行（5 步，按序）**：

1. **基线环境确认门**：交互式 → `AskUserQuestion` 让用户选"以哪个环境为全量基线"（候选 = 配置中心里真实存在的 namespace + 应用数据源可达的库）。**目标环境不存在时如实告知让用户选，绝不默认拿研发环境冒充生产**（37.6）。无人值守（`--unattended`）→ 取 PRD `autopilot_decisions.deployment` 声明的目标环境；无声明则**跳过本步 + 记欠账**，不猜。
2. **区间计算**：`python3 {{AIDP_HOME}}/scripts/release_scope.py --version {version}` 取 `prev_released_tag` / `covered_versions`（含中间过渡版本），供 37.5 增量校准定基线区间。
3. **只读采集（约定 35 只读边界）**：DDL 经**元数据视图**导出、配置经**只读 API** 拉取——**不执行任何 DDL/DML、不改任何环境配置、不启动任何服务**。连接串从**应用的数据源 / 引导层配置**反查，**禁用数据库客户端默认连接**（37.3-2 的两起真实取错事故）。
4. **按 37.3 / 37.4 生成产物**（⛔ 含 nginx / compose / k8s 与前端运行时配置；引导层按 37.4-2 跨 profile 补齐，补项同步写进源码），核查发现留既有机器核对记录；`建表说明.md` / `配置说明.md` 仅保留真实目标、操作和必要补救步骤；**其中触及需求或接口口径的，按约定 22 级联回上游文档**（37.6）。
5. **机器门（强制，不靠自觉）**：
   ```bash
   python3 {{AIDP_HOME}}/scripts/release_baseline_check.py --version {version} --json
   ```
   13 项确定性校验。**有 ERROR → 逐条修复后重跑，修不掉则本步判失败**（走上面的欠账登记 + 跳过），**绝不带 ERROR 发布全量基线**——占位符残留 / 密码明文 / 环境绑定物残留这类缺陷在新环境跑起来之前发现不了。WARN（裸配置项 / 建表缺幂等）不阻塞，但须在发布报告列出。

**输出摘要**：
```
📦 双轨部署基线（约定 37）：
   • 基线环境：{env}（{来源：用户确认 / PRD 声明}）  升级区间：{prev_tag} → {version}
   • 全量 SQL：{N} 张表（A 自有 {a} / B 共享 {b}）· 剔除代码有库无 {x} 张 · 跨环境差异 {d} 处
   • 全量配置：{M} 个 dataId + 引导层 {k} 份 · 剔死配置 {y} 项 · 补缺口 {z} 项 · 密码示例值 {p} 处
   • 机器门：{0 ERROR / N WARN}
   • 核查发现：{条目数}（已留机器记录{；已按约定 22 级联 N 处}）
```

**失败处置**：任一步失败 → **不阻塞发布**，跳过 D 部分 + WARN + `release_debt.py add --step 3.3.7.9`，发布报告注明"双轨部署基线欠账，`--rebuild-baseline` 补跑"。

### Step 3.3.9：★ 整理 docs/references（发布前对外需求归档 + 已满足标注）

**目标**：发布前整理 `docs/references/` 目录（结构与生命周期权威见 `docs/init/06_版本与用户目录约定.md` §2.6）：确保版本子目录存在、维护索引、对本版本已满足的对外需求补充说明。

**执行步骤**：

1. **确保版本子目录**：`mkdir -p docs/references/{version}/`（若本版本无第三方依赖、目录为空则保留空目录即可，不强制造文件）。

2. **★ 复核本版本「提给第三方的需求」并标注已满足**：遍历 `docs/references/{version}/` 下的对外需求文档，对每条需求判定是否已满足——
   - **判定依据**：结合约定 26 第三方 Mock 生命周期状态（前端 `VITE_USE_MOCK` / 后端 `@Profile("mock")` 等开关是否已关、`.env.*` baseURL 是否已切真实、`集成对接.md`「需第三方提供的接口清单」对应项是否已交付联调通过）；
   - **已满足**（第三方已交付 / 已切真实对接）→ 在该需求条目内**追加说明**：`> ✅ 已满足：{满足方式，如"对方已交付接口、{日期}切真实对接、Mock 已清理"}（{YYYY-MM-DD}）`；
   - **不确定**（无法从代码/Mock 状态机械判定）→ **提示用户确认**该条是否已满足，由用户裁决后再标注，不擅自标记。

3. **维护索引 `docs/references/README.md`**：生成/更新两区索引——
   - **「跨版本通用」区**：列 `docs/references/` 根目录下的通用全接口文档（路径 + 一句话用途）；
   - **「各版本对外需求」区**：按版本倒序列各 `docs/references/{version}/` 子目录及其下文件（标注「✅ 已满足 / ⏳ 待交付」状态汇总）。

4. **根目录散落版本专属文件仅提示**：若 `docs/references/` 根目录下存在疑似"某版本专属"的散落文件（如文件名含版本号、内容明显是单版本对外需求），**仅列出提示**用户手动归位到对应 `{version}/`，**不自动移动**（范式无法可靠判定版本归属，避免误移）。

> ⚠️ 本步只整理 `docs/references/`，不触碰 `docs/design/detail/{version}/集成对接.md`（我方内部对接设计，与对外需求分属两处）。

> ➡️ **本步只做「已满足标注 + 索引维护」**；`docs/references/{version}/` 的**补充合并回主文档 + 废弃/延期对外需求清除**由紧接的 **Step 3.3.10**（`release-5.md`）作为第 5 个收敛目标统一处理（本步先标 ✅已满足/⏳待交付 → 3.3.10 据此判定保留/清除）。
