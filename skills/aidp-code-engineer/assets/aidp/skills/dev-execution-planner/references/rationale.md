# 设计根因(Why)

> 本文件收录 `SKILL.md` 各规则背后的根因与实测数据。`SKILL.md` 正文只写现行行为;
> 想知道「为什么这样规定」时再读本文件,执行时不必加载。

## 需求规模档位(scale=S/M/L)

**根因:** 不分档时,无论需求大小都走满全套产出——实测「代码:文档 ≈ 9.4:1」,
一个只改两个页面的小需求也产出与大版本同规格的文档族,收益随需求变小而递减,成本却随产出量线性增长。

**由此得出的规则:** 编排层据 REQ 数 / 页面数 / 是否建表判档并随调用传入,S/M 档按档位裁剪产出;
缺省 = L(全套),保证未传档位的调用方行为不变。档位只裁「产出范围」,⛔ 不裁 Critical 判据与硬门。

## 脚本退出码约定

本 SKILL 全部 `check_*.py` / `scan_*.py` 一律:`0` = 通过或 N/A 跳过 / `1` = 检出违规 / `2` = 入参或环境错
(路径不存在、不可读、依赖缺失,并向 stderr 打印原因)。三条不可回退:

1. **严重度不占退出码**——分档一律读 `--json`;用 `2` 表示业务判错会与「入参错、修正参数后重跑、不计维度失败」撞码,
   最严重的违规反被静默放行。选 `2` 而非 `3`:Python `argparse` 自身对用法错就返回 2。
2. **`exists()` 与 `is_dir()` 必须分开判**——合并写会把「路径不存在」与「传入单个文件 = 合法 N/A」混为一谈,
   手滑写错路径即整档静默放行。
3. **有 N/A 跳过分支的脚本,`--json` 必须给出 `skipped: true` 等可区分标记**——否则「真通过」与「整档没跑」分不开。

## 已登记的已知缺口

`analyze_third_party_progress.py` 在样例上抛裸 traceback 且 `exit 1`(崩溃伪装成「检出违规」)。
同类缺口的修复方向:读失败记为 `read_error` 并返回 `2`,⛔ 绝不可静默计为通过。它是分析工具、不是检查门,故不纳入 QR 派发。

## `mvn compile` 不是只编译

`stack-java-spring.md` 曾把 `mvn compile` 注释成「✅ 只编译,不打包」,那句话是错的:它会跑完
`generate-sources → … → process-resources → compile` 整条 lifecycle,绑在这些相上的插件(典型 `frontend-maven-plugin`
默认绑 `generate-resources`)全部执行,等于触发本 SKILL 明文严禁的完整前端构建。故现行写法是直调 goal 的
`mvn -q compiler:compile`,⛔ 别改回去。

## QR 维度索引表的「等级」「脚本可判」两列

这两列是后来为编排层 `qr_level` 分级派发补上的(此前只有「由谁判 / 脚本 / 接没接 / 裁剪档」)。
补列时立的约束:`qr_level=critical|scripts` 档只认这一列,⛔ 不在正文另写一份 Critical 清单——同一判据两份清单必然漂移。

## `scan_aidp.py` 的运行根识别顺序

只按「存在」取第一个候选时,一个只放了 `settings.json` 的 `.claude` 会抢在真正装了命令的 `.agents` 前面,
扫到的是空壳、输出却看着正常。故在「第一个存在者」之前加了「第一个含 AIDP 特征(`commands/` / `skills/` / `AIDP*.md`)者」,
再之前是显式入参、环境变量 `AIDP_HOME` 与脚本自身安装位置(装在哪个运行根下就扫哪个)。旧兼容名(不带斜杠写作 `".aidp"`)
仍排候选第一,保证旧项目缺省行为不变。命令清单只列 `commands/*.md`,不把 `settings*.json` / `CLAUDE.md` 这类配置文件当命令。
