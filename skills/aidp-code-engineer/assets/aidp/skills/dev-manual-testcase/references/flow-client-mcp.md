# 客户端应用 MCP 业务能力用例（维度 20 通用半场）

`client_mcp.enabled` 默认关闭;旧 Web `webmcp_enabled: true` 只代表 Web 显式启用。两者冲突先登记为输入错误并要求澄清(⚠️ 落点是**待澄清问题清单**〔维度 13〕,⛔ 不中断生成——本 SKILL 立着「不中断原则」,不点名落点会被读成停下等人),不能静默覆盖。未启用时不生成本用例族、覆盖矩阵或 QR 行。这里测试的是**应用向 AI 暴露业务工具**,不是 Chrome DevTools/Appium/小程序**测试驱动**本身的 MCP 连接。

## 取材和用例

以 architect 的工具清单与入/出 Schema、身份与权限、写操作确认、生命周期、错误契约、审计日志和调用证据声明为单一上游基准。每工具逐项生成可观察断言:入口实连、本应用实例工具清单、入参/出参正确、越权与不存在合并文案、写入确认/取消/超时/并发、停用/恢复、失败不伪装空数据、审计日志脱敏、工具路径与人工 UI 路径一致。每条带来源锚点和 `[应用MCP]` 标记;确认门/脱敏/不扩权继续复用 `[外部调用方]`,动作动词用既有「执行」,操作对象写具体工具,不放宽代码级动作禁令。没有可核对工具契约时登记设计缺口,不得伪造“通过”用例。

`[应用MCP]` 用例可在四要素步骤表之后单列「**应用工具断言**」专段,只记录本应用工具的结构化返回/错误契约/审计结果与设计 Schema 的值级比对,并引用真实调用 artifact;它不是允许任意调用接口或执行 SQL 的步骤。普通 UI 用例仍断言页面可见现象;视觉还原度即使用工具准备了状态,布局/样式也必须由 UI 驱动和截图验,不能用工具出参替代。

**仅 Web + WebMCP** 再读 `flow-webmcp.md` 的未启用态/已启用态双窗口及九项 Web 专属覆盖;本节与那九项是同一族的通用视图,已由 Web 九项覆盖的工具正确性/确认/脱敏不再重复造 TC-ID。Web 浏览器启动命令只取 `webmcp_launch_command`,secure context/Chrome 参数不移植到非 Web。

**非 Web** 仅在详细设计证实有**应用自有 MCP 服务或桥接**时生成专项用例;从该端的真实连接入口/账号/实例来源取前置,用普通 UI 驱动配合但不把 Appium/小程序驱动当业务工具。入口取不到或本应用实例零注册时,专项用例 `block(precondition-unmet)` + 证据,其他不依赖工具的 UI 用例继续。声明启用但实现未取到时保留待测与 block,不写 pass;声明不支持/未提供时不造工具套件。

## 四类正反例（合成用例,非项目实测）

| 场景 | 正向判定 | 反向边界 |
| :- | :- | :- |
| Web 已实现 | Web 声明 + 本页注册 + 实际调用日志,视觉另由 DOM/截图断言 | 只有 `driver=cli`、本页零注册时 `[应用MCP]` 专项 block |
| 非 Web 已实现 | 移动 App 的已证实应用服务/桥接列出并调用业务工具,Appium 仅点 UI | 桥接不可连接时专项 block、普通 UI 继续,不要求 Chrome 参数 |
| 非 Web 未实现 | 小程序声明不支持/未提供,仅生成普通 UI 回归 | 小程序驱动通过 MCP 连接不能因此造应用工具用例 |
| 测试驱动可用但应用未提供 | Chrome DevTools MCP 能点页面,应用未声明,结果只记 UI 驱动 | `mcp-remote` 驱动不等于应用工具调用通过 |
