# 第零步:研发自测方案对齐(Critical 强制前置)

> 本文件是 `SKILL.md`「执行流程 第零步」的细则全文,按需 Read。
> **这是生成用例之前的强制前置**:主动询问 8 项、方案物理落盘、chrome-devtools 的 5 组连接信息询问铁律、0.6 出口硬自检——**任何一项都不是可选的**,骨架里保留了结论,做法全文在这里。

### 第零步:研发自测方案对齐(**Critical 强制前置**)

**生成用例之前,Agent 必须主动询问用户当前的研发自测方案,严禁直接进入用例生成。**

#### 0.1 主动询问

用户调用本 SKILL 时,无论是否提供了 PRD/详细设计/执行计划,Agent **第一轮回复必须**包含以下询问(可整合成一个简洁的多项问题块):

```
开始前先和你对齐一下"研发自测方案",我会按照自测方案组织用例并把方案与用例双向引用起来:

1. 是否已有现成的研发自测方案文档?(若有,请提供路径,我读取后追加用例引用并核对一致性)
2. 测试范围:本轮覆盖哪些模块/功规点?(全量回归 / 本次迭代增量 / 指定模块,默认按 PRD 全量)
3. 执行环境:测试环境 URL、客户端类型、所需测试账号(覆盖各角色)+ **每个账号最近一次验证成功的日期**、前置数据(默认手动浏览器执行,如需 AI 浏览器自动化请明示;**推荐 chrome-devtools-mcp**,具体安装与启动命令见下文 0.5)
   - **★若本轮含 `[双源对账]` 用例或 SQL 造删数**,追问该 DB 连接的 **`environment` 环境标识**(dev/test/uat/staging/demo/prod),并确认它**与被测环境一致**
4. 执行人与时间:谁来执行(研发本人/QA/AI 浏览器)、计划时间窗口
5. 通过/不通过准则:用例通过率门槛(默认 P0=100%、P1≥95%、P2≥80%)、阻塞性 Bug 处理策略
6. 缺陷跟踪:Bug 记录在哪儿(JIRA/禅道/Issue/飞书表格),用例中"实际结果"列是否写 Bug 链接
7. 风险与豁免:已知阻塞、第三方未交付、需用户豁免的维度
8. **AI 浏览器自动化(可选)**:是否启用 AI 浏览器执行?**前置门槛**:仅当客户端类型为 **Web 浏览器项目**(Chrome/Edge/Safari/Firefox/Chromium 内核)时,推荐使用 **chrome-devtools-mcp**(Chrome DevTools 官方提供、可经 npm 全局安装(`npm i chrome-devtools-mcp@latest -g`),基于 Chrome DevTools Protocol,支持本地/远程两种模式)。**chrome-devtools-mcp 仅适用于 Web 浏览器项目,不适用于桌面客户端 / 小程序 / iOS/Android 原生 APP**(详见 [`references/chrome-devtools-mcp-setup.md`](./chrome-devtools-mcp-setup.md) §0 适用范围),非 Web 项目应改用 Appium / 微信开发者工具 / WinAppDriver 等专用方案。**若项目同时包含 Web 与非 Web 客户端(如 iOS APP + Web 后台),需确认 chrome-devtools-mcp 仅覆盖 Web 部分,非 Web 部分另行声明工具**。

   **⚠️ 连接信息 Critical 强制前置询问(与"研发自测方案对齐"同级):** 一旦方案**选用 chrome-devtools-mcp**(用户显式启用 **或** SKILL 推荐启用),Agent **必须逐项主动询问 / 确认**以下 5 组运行与连接信息,**严禁跳过询问直接 bake 占位 / 默认默默带过**:
   - **① 渲染模式(必问,默认无头)**:**优先无头模式**(`--headless=new`,**无需 GUI 桌面环境**,服务器 / WSL / SSH 也能跑);**仅当**——① 需被网站当成真人(反无头 / 反爬验证)② 需测试不同分辨率 / 真实视觉渲染效果 ③ 无头模式下页面无法正常加载 / 操作——三者之一成立时才切**有头模式**。**走本地模式时,生成方案、写 §2.2 前 Agent 必须自动检测本机是否安装 Chrome(检测命令见 references §2.0),未安装则引导用户安装,严禁静默跳过。**
   - **② 连接模式(必问)**:本地模式(Claude Code 与 Chrome **同机**,走 **`chrome-devtools-cli`** CLI 直调,**不读 MCP 配置、切渲染模式免重启**;无头本地只需本机装 Chrome,**有头本地**还须 **GUI 桌面环境**)/ 远程模式(Claude Code 与 Chrome **异机**,走 **`chrome-devtools-mcp`** MCP 服务,需端口转发 + 端点写入 MCP 配置)。**有头但本地无 GUI 桌面 → 必须走有头 + 远程模式,连接到具备 GUI 的远程 chrome 服务。**
     **⚠️ 连接模式判定护栏(Critical,勿误连共享 / 远程实例):**
     - **同机 + 项目根无 `.mcp.json`(即未注册自己的 `chrome-<git_user>` 远程服务)→ 必判本地模式、必走 `chrome-devtools-cli`(CLI 直调)**;这是绝大多数自测的场景。
     - **仅当**确为异机、**且已按 references §1 注册 `chrome-<git_user>` 服务(`--scope project` 写入项目根 `.mcp.json`)**,才判远程、走 `chrome-devtools-mcp`。
     - ★ **MCP 远程变体绝不得当作"本地 CLI 的替代"**:无用户后缀的**通用名 `chrome-devtools` / 工具 `mcp__chrome-devtools__*`** 属 MCP 远程变体(驱动共享 / 远程 Chrome),本机场景误用它 = 连错实例,`list_pages` 会混入他人标签页、串测污染。本地模式**默认只认 `chrome-devtools-cli`(命令 `chrome-devtools`)**,不得回退到**通用名** MCP 变体;仅当命令确不可用且短期修不了时,才可按下条以插件自起的隔离实例作**显式声明**降级。
     - **缺 CLI 入口的处理(先诊断、再显式降级、绝不静默):** 本地模式但**疑似缺 `chrome-devtools` 命令**时:① **先诊断命令名 / PATH**——技能名 `chrome-devtools-cli` ≠ 命令名 `chrome-devtools`,应改查 `command -v chrome-devtools` / 跑 `chrome-devtools status`,或把 npm 全局 bin 加进 PATH(多数一修即回落本地 CLI);② **短期修不了**才用**显式声明的**降级——同插件 `mcp__plugin_chrome-devtools-mcp_chrome-devtools__*`(**自起本机独立隔离 Chrome**,非共享 / 远程实例),并把实际驱动如实写入报告 **driver 字段**(取值 `cli | mcp-remote | mcp-plugin-fallback | manual`),**不得静默切换**;③ **被禁止的只是无用户后缀通用名 `mcp__chrome-devtools__*`(连共享 / 远程实例),不是**插件自起的隔离实例。
   - **③ 远程模式追加(选远程时必问)**:远程 chrome 服务**所在主机 IP + 端口**(默认 9222)、**是否已执行端口转发**
   - **④ 测试环境访问地址(必问)**:前端应用 URL(如 `https://test.example.com`)
   - **⑥ (条件启用·仅 旧 Web `webmcp_enabled: true`（或 `webmcp.enabled: true`）、或 `client_mcp.enabled: true` 且客户端=Web、实现形态=WebMCP 时问)浏览器启动命令**:把 `webmcp_launch_command` 原样登记进方案 **§3.4「浏览器启动命令」**(未启用态套件用常规浏览器、已启用态套件用带参浏览器,两条都写)。⚠️ **不要自拟命令**——自拟即使跑通也无法复现;⚠️ 落点是**本 SKILL 产出的 `01_研发自测方案.md`**,不是 aiauto-test 端的外部文件。**未启用时本问项整条不存在**(不问、不建 §3.4、方案里不留位置)。
   - **⑥ (条件启用·仅调用方传 `webmcp_enabled: true` 时问)浏览器启动命令**:把 `webmcp_launch_command` 原样登记进方案 **§3.4「浏览器启动命令」**(未启用态套件用常规浏览器、已启用态套件用带参浏览器,两条都写)。⚠️ **不要自拟命令**——自拟即使跑通也无法复现;⚠️ 落点是**本 SKILL 产出的 `01_研发自测方案.md`**,不是 aiauto-test 端的外部文件。**未启用时本问项整条不存在**(不问、不建 §3.4、方案里不留位置)。
   - **⑤ 各角色测试账号(必问)**:覆盖各角色的**用户名 / 密码**,并逐个问**「最近一次验证成功是什么时候」**(填进方案 §3.2 的「账号最近验证时间」列;没验过填 `未验证`)
   - 附:**客户端类型确认**(必须为 Web 浏览器,非 Web 类型直接拒绝启用 chrome-devtools-mcp);**chrome 调试端点** = 本地 `http://localhost:9222` / 远程 `http://<远程 IP>:9222`;详细安装/启动/端口转发/无头与本地检测命令见 [`references/chrome-devtools-mcp-setup.md`](./chrome-devtools-mcp-setup.md)(SKILL 0.5 章节为速查摘要)

   **询问与回填铁律:** 上述 5 组必须**显式问过 / 确认过**再回填方案 §2.2;用户未答的项可标 `{待用户填写}` 占位 + 在"待澄清问题清单"登记 T-NNN,但**严禁"没问就 bake 占位 / 默认"**。**连接信息不完整时,chrome-devtools-mcp 在 §2.2 不得标"已就绪",只能标"待连接信息补全(见 T-NNN)"**,且不得据此让用例进入 AI 自动执行。

   **⚠️ 切换规则:本地 CLI 免重启,远程 MCP 改端点才重启(Critical):** 本地路径走 **`chrome-devtools-cli`**(CLI 直调,**不读 MCP 配置**),**无头 ↔ 有头切换只是改本机 chrome 启动命令的 `--headless=new` 开关并重启 chrome 进程,Claude Code 无需重启**;远程路径走 **`chrome-devtools-mcp`**(MCP 服务),端点写入 MCP 配置,MCP 配置项**只在 Claude Code 启动时读取一次**,**仅"首次配置远程端点 / 更换远程机器·端口"时才需改 MCP 配置 + 重启 Claude Code**(详见 references §6)。方案 §2.2 与用例文档"AI 浏览器执行入口"须按所选路径写明对应的切换流程,避免"以为切了、实际没切"的不一致。

   **⚠️ 单步操作等待上限(超时阈值)主动设定 + 用户确认(Critical):** 一旦选用 chrome-devtools-mcp,Agent **必须主动**在方案 §2.2 写入浏览器单步操作的等待上限,默认 **每步操作等待 ≤ 3 秒、首次打开页面放宽到 ≤ 30 秒**(防止页面卡死 / 元素不出现时无限等待,把整轮自测拖垮)。**该阈值必须经用户确认后才正式启用**:用户确认前在 §2.2 标注 `单步操作等待上限: 每步 ≤ 3 秒 / 首次打开页面 ≤ 30 秒(默认值,待用户确认)`,用户可调整为其它数值;**用户确认或调整前,不得据此默认值进入 AI 自动执行**(与上述 5 组运行/连接信息同级,均为 chrome-devtools-mcp 正式启用 AI 执行的前置条件)。AI 执行入口指令(用例文档"附录:AI 浏览器执行入口")须同步写明该等待上限,并要求 AI 工具单步操作超过该阈值即判为卡死,记录当前 URL / 截图后继续下一步,不无限等待。

   **⚠️ 关键步骤截图(有头 / 无头都要求,Critical):** 一旦选用 chrome-devtools-mcp,方案 §2.2 必须写明:**每个关键步骤(登录、提交、状态变化、断言通过/失败、报错)都必须截图留痕并归档,无论有头还是无头模式**。**无头模式下无可见窗口,截图是唯一的执行证据与验证依据;有头模式同样须截图存档以便复核。** 用例文档"附录:AI 浏览器执行入口"须同步要求 AI 工具在关键步骤截图并保存,缺失截图的步骤视为执行无证据、不予判定通过。
```

**询问规则:**
- 用户已在 prompt 中显式回答的项,跳过
- 用户回答"按默认即可" → 走默认值(默认值见下文 0.3),无须再追问
- 仍缺失的项目走"占位符 + T-NNN 待澄清"策略,**严禁中断生成**
- **chrome-devtools-mcp 连接信息例外(item 8 的 5 组)**:占位符策略仅在**已显式询问之后**适用;**严禁未问就 bake 占位 / 默认**——选用 chrome-devtools-mcp 却跳过运行/连接信息询问(含渲染模式与本地 Chrome 检测),属违规(详见 item 8「连接信息 Critical 强制前置询问」)

#### 0.2 自测方案文档生成/更新(**落盘先行,严禁延后**)

无论用户是否提供现成方案,本 SKILL **必须先用 Write 工具把"研发自测方案"文档物理写盘**,把它作为用例的上层入口——**落盘是第零步的硬动作,严禁"等用户确认后再写"或"等用例生成完再补"**:

- **用户提供现成方案** → SKILL 读取并解析,在末尾追加/更新"用例索引"章节(链接本次产出的全部用例文件 + 套件 + TC-ID),并写回该文件(或按默认路径落盘一份)
- **用户无现成方案** → SKILL **立即**按 0.3 默认值起草最小方案(模板见 `assets/test-plan-template.md`),**先用 Write 工具写盘 `01_研发自测方案.md`,再照常进入后续步骤生成用例**。用户确认改为**非阻塞**:落盘后用例生成正常推进,用户可事后修订方案文件,**严禁把落盘卡在"用户确认"之后**
- **非交互 / 编排场景(如 `/version`、`/sprint-selftest` 调用,无用户实时应答)** → 直接用 0.3 默认值落盘 `01_研发自测方案.md`,并在方案文档头部记录一行 `> ⚠️ 本方案由默认值起草,待用户复核`;**严禁因"没人确认"而跳过方案文件**——缺方案是 Critical 阻断项,不是可延后 / 可省略项
  > ⚠️ **调用方指针已迁移,别照旧指针找**:研发自测**已从 `/sprint-plan` 抽出为独立的 `/sprint-selftest`**,`/sprint-plan` 单独跑**不再顺带触发自测**。本 SKILL 只认「有没有用户实时应答」这一条判据,与具体由哪个命令调起无关;此处列命令仅为举例,**新增调用方无须回来改这一行**。

自测方案默认文件:`{测试文档目录}/{项目名}/01_研发自测方案.md`(与用例同目录平级,字典序在用例文件之前)

> **落盘判据:** 进入第一步之前,`01_研发自测方案.md` 必须是磁盘上真实存在的文件(可被 `test -f` / `ls` 命中),而不是"上下文里讨论过 / 起草过"。

#### 0.3 默认值(用户不指定时)

| 项目 | 默认值 |
| :- | :- |
| 执行方式 | 用户手动打开前端应用,使用 Chrome/Edge 浏览器逐套件执行 |
| 执行人 | 研发本人(自测阶段);后续由 QA 接手(系统测试阶段) |

| 项目 | 摘要 | 详见 references |

#### 0.6 第零步出口硬自检(**早期拦截,先于用例生成**)

进入第一步生成用例**之前**,必须执行以下硬自检——把维度 16-A 的物理存在性校验**前移一份**到此处,确保"缺方案"在最前面被拦下,而不是押到末尾 21 维度后检(长编排链路下末尾后检经常被整段跳过):

- [ ] **方案文件已物理落盘**:`{测试文档目录}/{项目名}/01_研发自测方案.md` 在磁盘上真实存在(用 `test -f` / `ls` 核验;**不接受"上下文里讨论过 / 起草过"算通过**)
- [ ] **★账号新鲜度**(§3.2):账号表带「账号最近验证时间」列,且参与本轮的每个账号既非 `未验证`、距今也不超过 **N=7 天**;超期/未验证的**先跑登录冒烟预检**(只登录 + 校验落地页与角色归属,不跑业务用例),通过刷成当天日期、失败就地标 `❌ 失效(现象)` 并阻断依赖它的套件进入 AI 自动执行
- [ ] **★DB 环境一致性**(§3.1,仅当数据库行改填了库连接):`environment` 已填(非空、非「未知」)且与被测环境一致;不一致判**不适用于本环境对账**,阻断 `[双源对账]` 用例与 SQL 造删数进入自动执行

> **这两条为什么放在出口硬自检:** 「账号有效性」与「数据源环境归属」是两个**默认被无条件信任、一旦错就确定性作废整轮**的前提。实际项目中曾出现:主测+备用两个管理员账号都已失效,方案仍声明「已就绪」,直到执行期登录被拦才发现,前置准备与套件编排全部作废;另一轮把非被测环境的库当被测环境的库做双源对账,得出确定性错误结论并污染整份报告。**在方案生成期暴露是最便宜的**。

**自动化辅助:** `python3 <SKILL_DIR>/scripts/check_test_plan_alignment.py <测试目录> --plan-only`(该脚本另有 **E 项「环境前提就绪度」report-only 提示**——账号表缺列/账号未验证或超期、DB 行改填了连接却没 `environment`,**只提示、不影响退出码**;它们是「该跑登录冒烟预检 / 该核对 DB 归属」的提醒,方案作者可能有正当理由,硬拦会制造常驻噪声)(`--plan-only` 只验 A 方案文件存在性 + B 方案核心章节完整性,**跳过** C 双向引用 / D 默认手动执行等依赖用例文件的检查;用例尚未生成时不会因"找不到用例文件"误报。方案缺失或关键章节不全 → 退出码 1 拦截;方案落盘且 §1/§2/§3/§5/§8 齐全 → 退出码 0。用例生成后再去掉 `--plan-only` 跑完整维度 16)。

**未通过处理:** 文件未落盘 → **不得进入用例生成**,必须立即回到 0.2 用 Write 工具补落盘后再继续第一步。本自检不可豁免、不可延后,与末尾维度 16-A 是同一判据的"前置副本"(双保险)。
