# 维护者说明:关键约定的根因

> 本文件只给**维护本 SKILL 的人**看,生成用例时不必读。`SKILL.md` 正文只写现行行为,
> 「为什么这样定、改回去会怎样」集中记在这里,避免正文堆积历史对比。

## 1. 需求规模档位(`scale=S/M/L`)

- **根因**:不分档时无论需求大小都走满全套,实测「代码:文档 ≈ 9.4:1」——一个只改两个页面的小需求也产出与大版本同规格的文档族,收益递减而成本线性。
- **现行口径**:编排层判档后随调用传入;缺省 = L(全套)。档位写进产出文档头部元信息,否则「文档为什么这么薄」会被误判成漏做。

## 2. `[回归]` 标记 + `关联缺陷` 独立字段

- **根因**:缺陷只写在备注列时是单向关联——从缺陷找不到回归用例,`auto-test-runner` 也无法按稳定文本 glob 跨版本继承复跑。
- **现行口径**:标题旁 `[回归]` + 元信息 `> **关联缺陷**: {缺陷ID}`,两者须稳定可识别、不改写。

## 3. 编排层调用入参缺省 = 全套口径

- **根因**:入参若改变缺省行为,独立调用与编排调用的产物会悄悄分叉,而复核者无从判断差异来自入参还是漏做。
- **现行口径**:7 个入参不传时产物与 QR 报告按全套口径产出;非缺省值只由编排层传入,独立调用不自行切换(含「模块太大先限 30 条」这类自我裁剪)。

## 4. 第零步「主动询问 8 项」

- **根因**:自述项数散落在 `SKILL.md`、`flow-step0-test-plan.md`、`quality-review-checklist.md` 多处,询问块增删一条时任一处漏改都不会有任何信号(实际出现过自述 6 项、实列 8 项)。
- **守护**:`tests/test_step0_ask_count.py` 以 0.1 询问块为单一信源逐处比对,含变异对照。

## 5. `{{AIDP_HOME}}` 路径占位

- **根因**:本 SKILL 会被逐字节下发到不同 Agent 工具链的项目里,运行根随工具链不同(对照表见 `SKILL.md`「运行路径约定」)。写死某一个目录名会让其它工具链下「找不到被测项目侧脚本 → 标不适用」,失效方向是假绿;让 SKILL 自行探测运行根则会出现「两个目录都在时取哪个」的歧义。
- **现行口径**:运行根由**安装方渲染** `{{AIDP_HOME}}`、SKILL 不探测;正文一律写 `{{AIDP_HOME}}/...`(相对被测项目根),⛔ 不与「被测项目根 + 斜杠 + 占位符」的前缀写法混写。安装器拒收写死「另一个」运行根 + 受管目录的行,对照表行须带 `runtime-path-ignore:` 标注;守护 `tests/test_open_source_distribution.py`。
