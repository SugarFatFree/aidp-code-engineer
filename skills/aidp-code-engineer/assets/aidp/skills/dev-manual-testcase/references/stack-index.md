# 技术栈细则 · 按需加载索引

> **为什么拆**：本 SKILL 的**跨技术栈通用**规则（真人可操作口径、测试套件组织、四要素步骤、覆盖矩阵与测试设计方法论、用例数量基线、用例族标记）写在 `SKILL.md`；**语言/框架专有的部分**——主要是「**从代码里捞真实文案/路由/枚举**」这一步该读哪些文件——拆在本目录 `stack-*.md`，按被测项目技术栈按需加载。

## ⚠️ 先说清楚：本 SKILL 的技术栈耦合本来就很浅

用例是**真人视角的 UI 操作**（点击、输入、看到什么），**天然与技术栈无关**——同一份用例在 Vue 版和 React 版实现上应当完全一样。技术栈只影响一件事：**生成用例时，去哪个文件读真实的按钮文案、路由路径、枚举 label**（禁止臆造文案，见 `../SKILL.md`「从代码读取」原则）。

因此本目录文件都很短，只回答「**这个栈的文案/路由/枚举藏在哪**」。

## 探测 → 加载

| 探测信号 | 加载 |
| :- | :- |
| `*.vue`，或 `package.json` 依赖含 `vue` | `stack-vue.md` |
| `*.jsx`/`*.tsx`，或 `package.json` 依赖含 `react` | `stack-react.md` |
| `*.java` + `pom.xml`（后端枚举/错误码来源） | `stack-java-spring.md` |

前后端分离项目通常同时命中 1 个前端栈 + 后端栈。**探测不到时**：按 `../SKILL.md` 的通用「从代码读取」原则，自行定位路由配置、页面组件、国际化文件、枚举定义四类来源。

## 与 SQL 的关系（重要边界）

`[双源对账]` 用例的等价 SQL 与「前置数据编排」段的造删数 SQL，属 **SQL 方言**而非编程语言——其写法差异（达梦/MySQL/Oracle 的分页、日期函数、软删除过滤）由**执行方**按实际库适配，本 SKILL 只要求 SQL 语义正确、口径与页面一致，**不按方言拆文件**。
