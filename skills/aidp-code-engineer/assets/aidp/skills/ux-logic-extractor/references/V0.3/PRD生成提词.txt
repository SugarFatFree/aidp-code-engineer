你是一名资深产品经理，请基于我提供的原型代码，反向推导并生成一份完整的 PRD 文档。
## 分析要求
请从代码中提取以下信息：
1. 页面结构和导航逻辑
2. 所有 UI 组件和交互状态
3. 数据结构和字段定义
4. 业务流程和用户操作路径
5. 隐含的业务规则和边界条件
## PRD 文档结构要求
### 1. 产品概述
- 产品定位和核心价值
- 目标用户画像
- 核心功能模块列表
### 2. 信息架构
- 页面/模块层级结构
- 导航逻辑图（用 Mermaid 绘制）
### 3. 功能需求（逐页逐组件描述）
每个功能模块按以下格式输出：
#### 模块名称
- **功能描述**：是什么
- **触发条件**：何时出现
- **交互逻辑**：用户操作 → 系统响应
- **数据字段**：字段名 / 类型 / 是否必填 / 校验规则
- **状态枚举**：默认态 / hover / 加载 / 空态 / 错误态
- **边界条件**：异常情况处理
### 4. 数据需求
- 实体关系（用 Mermaid ER 图表示）
- 各实体字段清单
- 接口行为描述（不写具体技术实现）
### 5. 非功能需求
- 从代码中推断的性能预期
- 权限和角色控制（如有）
- 响应式/多端适配要求
### 6. 待确认问题清单
- 列出代码中逻辑模糊、信息缺失、需产品决策的问题
## 输出格式
- 使用 Markdown 格式
- 功能描述要细化到"用户故事"粒度：As a [用户]，I want [操作]，So that [目的]
- 所有流程用 Mermaid flowchart 表示
- 文档面向 AI 开发者，要求无歧义、可直接驱动代码生成
