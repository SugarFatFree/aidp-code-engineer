# docs/deployment/tools/ — 跨版本运维 / 一次性工具归档

> **隔离级别**：**跨版本**（非版本隔离，不随某个版本走）
> **用途**：收纳一次性运维 / 历史数据修复 / 字典导入 / 测试数据清理类的**工具 SQL 与脚本**。
> **与 `docs/deployment/{version}/` 的边界（务必分清）**：
> - `docs/deployment/{version}/`：随版本发布的**正式部署产物**（DDL / 配置 / 部署流程），**按版本隔离**、随版本走。
> - `docs/deployment/tools/`：**跨版本、非版本隔离**的运维侧临时 / 历史工具，**按归属应用分类**，不随某个版本走。

## 目录结构（按归属应用分子目录）

```
docs/deployment/tools/
├── README.md      # 本索引：分类 + 用途说明
# ⚠️ 下方三个子目录是三分基线【示例】，本仓当前无工具、目录尚未创建
├── 本应用/         # 操作业务应用【自有库】的工具：DDL / 历史数据修复 / 第三方同步补推 / 测试数据清理
├── <上游系统>/     # 操作【第三方 / 上游系统】的脚本（如订单中心 order-center 的字典导出导入）
└── 其他/           # 【跨系统】（多方联动）的迁移方案整目录
```

**分类原则**（按脚本主要操作 / 归属的应用归位）：

- 操作本应用自有库 → `本应用/`
- 操作第三方 / 上游系统（如订单中心）→ `<上游系统>/`（按系统名命名，如 `order-center/`）
- 跨多系统联动 → `其他/`

> 子目录名**可按项目实际应用命名**；`本应用 / <上游系统> / 其他` 为通用三分基线。

## 文件命名规范

- SQL / 文档文件名**尽量用中文**（描述用途），**保留日期前缀**便于按时间排序（如 `20260715_字典表历史数据修复.sql`）。
- **可运行工具**（含被本 README 交叉引用的 `.py` / `.sql`）**内部文件名保持稳定**、仅外层目录中文化——避免引用断链。
- **不纳入构建产物**（`__pycache__` 等不入库）。
