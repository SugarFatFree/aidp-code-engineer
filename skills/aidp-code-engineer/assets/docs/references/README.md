# docs/references/ — 第三方接口资料 + 提给第三方的需求

> **隔离级别（两层分流）**：
> - **通用区** `docs/references/` 根 —— 项目级（跨版本跨用户共享）：第三方平台**跨版本通用**的全接口文档 / 能力清单 / 长期参考资料。
> - **各版本区** `docs/references/{version}/` —— **版本级（按版本隔离）**：本版本「**提给第三方的需求**」（对外协作业务诉求）+ 本版本相关的对方资料。
>
> 权威定义见 [`../init/06_版本与用户目录约定.md`](../init/06_版本与用户目录约定.md) §2.6。

## 用途

| 子路径 | 内容 | 层级 |
|--------|------|------|
| `docs/references/`（根） | 第三方平台跨版本通用的全接口文档 / 能力清单 / 长期参考（对方**已有**能力的资料）| 项目级（不隔离）|
| `docs/references/{version}/` | 本版本「提给第三方的需求」（我方要求对方**新做/改造**的业务诉求）+ 本版本相关的对方资料 | 版本级（按版本隔离）|

> **边界**：`docs/references/{version}/` = **对外业务诉求**（给第三方看）；`docs/design/detail/{version}/05_集成对接.md` = **我方内部对接设计**（给自己人看）。两者分离，不互相复抄。

## 生命周期（三阶段）

1. **版本规划期**（`/version` 规划流程）
   - ① 确保 `docs/references/{version}/` 存在；
   - ②「提给第三方的需求」由 [`/sprint-design`](../../.aidp/commands/sprint-design.md) 落盘到此；
   - ③ ★ **引用链强制**：本目录规划期生成的文件**必须**被研发需求（`00_索引.md` + `01_研发需求.md`）+ 详细设计（`00_索引.md` + `01_详细设计.md`）在「关联文档」中引用——**缺失即 `version-auditor` E 引用链审计告警**（与「研发需求 ↔ 详设引用密度」铁律同级）。
2. **开发期**（`/sprint-dev` / `/sprint-design` 读取）
   - 消费端读「对方接口资料」时**同时覆盖两处**：`docs/references/{version}/`（版本专属）+ `docs/references/` 根（通用）。
3. **版本发布期**（`/version` 发布流程）
   - ① 确保 `{version}/` 存在；
   - ② **维护本 README 的「通用区」+「各版本区」两段索引**；
   - ③ ★ **复核 `{version}/` 提给第三方的需求**：对已满足（第三方已交付 / 已切真实对接，结合 [约定 26](../../AGENTS.md) Mock 清理状态判定）的需求，在文档内**追加「✅ 已满足」说明**（含满足方式 + 日期）；不确定的提示用户确认；
   - ④ 根目录散落的**版本专属**文件**仅提示**用户归位，**不自动移动**（范式无法可靠判定版本归属）。

## 典型内容

- 第三方大模型 API（如 OCR、TTS、IAT、Chat）—— 通用区
- 外部业务系统接口（如 SSO 统一认证、数据中台、资源中心）—— 通用区
- 项目自产的开放 API 清单（供外部调用方）—— 通用区
- 本版要求第三方新增/改造的接口、字段、时序、SLA 诉求 —— 各版本区

## 使用场景

- Architect Agent 在 `/sprint-design` 时读取（通用区 + 当前版本区），了解第三方能力并落盘对外需求
- Backend Agent 开发时参考接口签名（通用区 + 当前版本区）

## 维护

- 新增/变更第三方**通用**接口资料 → 放根目录 + 更新「通用区」索引
- 本版**提给第三方的需求** / 本版对方资料 → 放 `{version}/` + 更新「各版本区」索引
- 在 `memory/techContext.md` 的「外部服务依赖」章节同步记录
